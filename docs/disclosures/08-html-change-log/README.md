### **1. Summary**

#### **기능 요약**

- 07단계에서 만든 정정공시 family를 읽어 문서 순서에 따른 값 변화를 비교하는 기능이다.
- `/html-change-log`에서 `사채발행파싱` 또는 `유무상증자파싱` 결과를 조회한다.

#### **세부 설명**

- 입력 경로는 `<data_root>/07-converted/<mode>/parsed-<mode>.json`이다.
- 08단계는 조회 화면이며 별도의 `08-*` 폴더나 결과 JSON을 만들지 않는다.

```text
<data_root>/
└── 07-converted/
    └── <mode>/
        └── parsed-<mode>.json
```

### **2. Core**

#### **Feature**

**[Core Processing] 정정 family 선택 기능**

- **목적:** 비교 가능한 정정 family의 범위를 확정한다.
- family ID가 있고 문서 순서가 정수이며 문서가 2개 이상인 결과만 선택한다.
- family ID가 큰 순서로 정렬한다.
<br>

**[Core Processing] 문서별 변동 비교 기능**

- **목적:** 최초 공시부터 최신 정정공시까지 이웃한 문서의 값 변화를 계산한다.
- family 안의 문서는 공시 순서와 접수번호로 정렬한다.
- 이웃한 두 문서에 저장된 비교 항목을 그대로 비교한다.
- 변경 전후 값과 변경 항목을 비교 결과에 유지한다.
<br>

**[Core Processing] 변동 임계값 기능**

- **목적:** 날짜나 수치의 작은 차이를 주요 변동 집계에서 제외한다.
- 날짜 차이는 설정한 일수 이하, 수치 차이는 설정한 비율 이하이면 작은 변동으로 본다.
- 목록은 구조와 순서가 같고 모든 수치 차이가 기준 이하일 때만 작은 변동으로 본다.
- `회차`의 변경은 주요 변동으로 집계하지 않는다.
<br>

**[Core Processing] 정정내역 값 판정 기능**

- **목적:** 날짜와 수치를 확실히 읽을 수 있을 때만 작은 변동인지 판정한다.
- 날짜는 한글 날짜, 점이나 하이픈 한 가지로 나눈 날짜 또는 `YYYYMMDD` 형식만 읽는다. 실제로 없는 날짜는 읽지 않는다.
- 수치는 부호, 숫자, 올바른 쉼표와 소수점만 있을 때 읽는다. 목록과 묶음 안의 수치도 같은 기준으로 읽고 순서는 바꾸지 않는다.
- 날짜나 수치를 읽지 못하면 정상 판정 규칙에 따라 작은 변동에서 제외하지 않는다. 다른 parser나 값을 사용하지 않으므로 Fallback이 아니다.
<br>

**[Core Processing] 조회 필터와 내보내기 기능**

- **목적:** 조건에 맞는 family와 Excel 행을 선택한다.
- 제목, 접수번호와 항목 이름으로 검색할 수 있다.
- `변경사항만 보기`는 주요 변경이 있는 family만 결과에 포함한다.
- `최신버전만`을 선택하면 family마다 최신 문서만 Excel에 넣는다.
<br>

#### **Fallback**

- 없음.

#### **Shutdown**

**[Input Handling] 변환 결과 입력 오류시 중단하기**

- **목적:** 비교할 변환 유형과 결과 파일이 분명하지 않으면 Core를 실행하지 않는다.
- 변환 결과 파일이 없거나 읽을 수 없으면 실패 처리한다.
<br>

### **3. Serving**

#### **Feature**

**[Input Handling] 정정내역 조회 요청 기능**

- **목적:** 화면에서 비교 범위와 표시 조건을 Core 요청으로 전달한다.
- 사용자는 `변동 임계값`에서 날짜와 수치 기준을 저장할 수 있다.
- 결과 폴더, 변환 유형과 조회 개수를 요청값으로 사용한다.
- 변동 임계값을 지정하지 않으면 날짜는 3일, 수치는 1%를 Core 입력으로 사용한다. 정상 요청의 기본값이므로 Fallback이 아니다.
<br>

**[Core Processing] 정정 family 목록 표시 기능**

- **목적:** 정정 이력이 있는 공시를 빠르게 찾는다.
- Core가 선택한 family 중 화면에서 정한 개수만 보여 준다.
- 처음에는 문서 수, 제목과 바뀐 항목만 보여 주고 family를 선택하면 상세 내용을 불러온다.
- 바뀐 항목 이름은 5개까지 보여 주고 나머지는 개수로 표시한다. Core의 상세 결과는 줄이지 않는다.
<br>

**[Core Processing] 정정내역 표 표시 기능**

- **목적:** Core가 만든 변경 결과만 화면에 표시한다.
- 상세 화면은 문서 정보와 변경 전후 값을 함께 보여 주며, 바뀐 항목은 행, 공시 순서는 열로 표시한다.
- 요청한 항목과 관계없는 내용은 제외한다.
- 발행금액과 발행가액은 숫자일 때 억 원 단위로 보여 준다.
- 목록은 쉼표로 잇고 빈 값은 `-`로 표시한다.
<br>

#### **Fallback**

**[Core Processing] 정정내역 표시 복구 기능**

- **목적:** 일부 표시값을 만들지 못해도 확인된 변경 결과는 계속 보여 준다.
- 변경 기록이 없거나 문서 위치를 찾지 못한 칸은 비워 둔다.
- 발행금액이나 발행가액이 숫자가 아니면 원래 값을 보여 준다.
- 발행대상자나 투자자 금액을 읽지 못하면 각 항목을 공백으로 이어 표시한다.
<br>

#### **Shutdown**

**[Input Handling] 조회 요청 오류시 중단하기**

- **목적:** 비교 범위를 임의로 바꿔 Core를 실행하지 않는다.
- 결과 폴더나 변환 유형이 없으면 실패 처리한다.
- 지원하지 않는 변환 유형, 잘못된 폴더와 1보다 작은 조회 개수는 실패 처리한다.
