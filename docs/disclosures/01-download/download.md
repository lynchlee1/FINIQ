# 01 다운로드 실행

## KIND 검색 결과 다운로드

`연도별` 처리는 요청 기간을 달력 연도 경계에서 나누는 방식이다.

01단계는 당일 KIND 공시가 모두 반영된 뒤 실행한다.

- 요청 시작일과 종료일이 같은 연도에 있으면 해당 요청 기간을 하나의 `<START_DATE>_<END_DATE>` 기간 폴더에 저장한다.
- 같은 연도에 다음 기간을 이어받아도 기존 폴더를 확장하지 않고 다음 요청 기간의 별도 폴더를 만든다.
- 요청 기간이 연도를 넘으면 각 연도의 마지막 날과 다음 연도의 첫날을 경계로 기간을 나눈다.
- 같은 연도에 여러 기간 폴더가 생겨도 다음 SQLite 변환 단계는 공통 상위 입력 경로에서 모든 결과를 읽고 공시일 연도별로 다시 묶는다.

### 제약과 분기

- 각 폴더 이름과 metadata에는 실제 요청 시작일과 종료일을 유지한다.

### 중단 조건

- 검색 조건을 검증할 수 없거나 저장된 조건을 현재 형식으로 정확히 바꿀 수 없으면 검색 범위를 바꾸지 않고 실패 처리한다.

## 다운로드 metadata 기록과 재개

다운로드 조건, 페이지별 진행 내역과 검증 상태를 metadata로 남긴다.

### 제약과 분기

- 다운로드가 정상 완료되지 않으면 `kind_workflow.input.json`을 만들지 않는다.
- 중단된 다운로드를 재개하면 `kind_workflow.checkpoint.json`에 저장된 마지막 페이지와 pagination 정보를 재개 기준으로 사용한다.
- 저장된 pagination을 읽을 수 없으면 앞선 페이지 값이나 `null` 요약으로 대신하지 않는다.

## 다운로드 목록 일관성 검증

한 기간의 모든 페이지를 받은 직후 같은 검색 조건으로 첫 페이지를 다시 요청한다.
운영에서는 당일 공시 반영이 끝난 뒤에만 다운로드를 시작하므로 실행 중 전체 목록을 반복 조회하지 않는다.

### 제약과 분기

- 다시 받은 페이지 정보와 공시 행이 첫 다운로드와 같을 때만 새 임시 결과를 게시한다.
- 새 결과 게시가 끝난 뒤 이전 결과 백업 삭제만 실패하면 게시를 실패로 되돌리지 않는다. 새 결과를 유지하고 남은 백업 경로를 정리 경고로 반환한다.

### 중단 조건

- 두 목록이 다르면 실패 처리하고 새 임시 결과를 게시하지 않으며 이전 기간 결과를 유지한다.

## 결과와 진행 내역 표시

누락 페이지와 다운로드 진행 내역을 화면에 전달한다.

- 저장 파일 구성 검사는 대상 폴더 수집, 로컬 구성 검사, KIND 조회 잠금 대기·시작, 범위별 완료와 최종 결과를 `실행 현황`에 기록한다.
- KIND 건수 비교는 같은 작업에서 완료한 저장 파일 구성 결과를 재사용한다. 파일명·크기·수정 시간이 달라진 폴더만 현재 파일을 다시 검사하며, 저장 페이지 수와 전체 페이지 수의 일치 조건은 그대로 확인한다.

### 제약과 분기

- 전체 누락 결과를 바꾸지 않고 화면에 전달할 범위만 제한한다.
- 직접 실행의 진행 내역은 실행 중에만 전달한다.
- 백그라운드 작업은 정해진 줄 수만큼 최근 진행 내역을 보관한다.

## 다시 받기

기존 결과 검증이 실패하면 같은 요청 기간을 다시 받을지 사용자가 결정하게 한다.

1. 공시 자동화 화면 오른쪽 `알림`에서 어느 기간의 결과가 어떤 검사에서 어긋났는지 확인한다.
2. 해당 기간의 기존 결과를 새 결과로 교체해도 되는지 판단한다.
3. 다시 받으려면 `다시 받기`를 누른다. 기존 결과를 유지하려면 누르지 않는다.
4. 작업이 끝나면 01단계 상태가 `완료`로 바뀌었는지 확인한다.

### 제약과 분기

- 서버는 `workflow_status=needs_download_confirmation`과 함께 충돌 내역과 `download_confirmation`을 반환한다.
- `download_confirmation`은 현재 01단계 설정과 충돌별 기간·종류·저장 건수·현재 KIND 건수로 만든 hash다.
- 다시 실행할 때 서버가 반환한 `download_confirmation`을 보내야 해당 요청 기간을 01단계의 일반 실행 경로로 다시 받는다.
- 그사이 01단계 설정이나 충돌 내역이 바뀌면 새 확인값을 반환하고 다시 판단을 기다린다.
- 사용자가 허가하지 않으면 기존 결과를 지우거나 다시 받지 않는다.
