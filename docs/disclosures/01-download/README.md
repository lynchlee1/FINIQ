### **1. Summary**

#### **기능 요약**
- KIND에서 공시 조건검색을 진행하고 결과를 HTML 형식으로 저장하는 기능이다.

#### **세부 설명**
- 저장 경로는 `<data_root>/01-list`이며, 저장 형식은 아래와 같다.
- 하위 폴더 이름에는 연도별 시작일과 종료일을 YYYYMMDD 형식으로 기록한다.
```text
<data_root>/
└── 01-list/
    └── <YYYYMMDD>_<YYYYMMDD>/
        ├── *_post_page_*.body
        ├── kind_workflow.input.json
        └── kind_workflow.checkpoint.json
```

### **2. Core**

#### **Feature**

**[Input Handling] 기존 데이터 무결성 검사 기능**
- **목적:** 데이터 최신화를 위해 각 연도별 폴더에서 데이터 무결성 검사를 수행한다.
- 다운로드 실행 전에는 항상 무결성 검사를 실행하며, 무결성이 확인된 경우에만 데이터를 다운로드한다.
- 다음 조건으로 기존 결과가 유효한지 판정한다.
  1. `kind_workflow.input.json`의 조건으로 연도별 재검색한 전체 공시 수가 저장값과 같음
  2. 페이지 번호가 중복 없이 1부터 연속함
  3. 본문 간 전체 페이지 수와 건수가 일치함
<br>

**[Result Validation] 메타데이터 생성 기능**
- **목적:** 데이터 무결성 검사 및 복원을 위해 메타데이터를 생성한다.
- 정상 다운로드는 연도별 폴더에 각각 `kind_workflow.input.json`과 `kind_workflow.checkpoint.json`을 생성한다.
  - `kind_workflow.input.json`은 정상 다운로드가 완료됐을 때만 생성한다.
  - `kind_workflow.input.json`에는 버전 기록인 `format=finiq_kind_workflow_input_v1`를 필수로 표기한다.
<br>

**[Result Validation] 다운로드 목록 일관성 확인 기능**

- **목적:** 한 검색기간의 결과가 같은 시점의 KIND 목록으로 구성됐는지 게시 전에 확인한다.
- 한 기간의 모든 페이지를 받은 직후 같은 검색 조건으로 첫 페이지를 다시 요청한다.
- 다시 받은 페이지 정보와 공시 행이 첫 다운로드와 같을 때만 새 임시 결과를 게시한다.
<br>

#### **Fallback**

**[Input Handling] 기존 결과 검증 실패 후 전체 기간 재다운로드 기능**

- **목적:** 일부 정상처럼 보이는 페이지와 새 페이지를 섞지 않는다.
- 기존 결과 검증이 실패하면 우측 알림 창에서 사용자 확인을 받은 뒤 해당 기간의 본문과 workflow 보조 파일 전체를 삭제 대상으로 삼는다.
- 연간 다운로드는 부분 이어받기를 사용하지 않고 기간 단위로 새 결과를 만든다.
- 사용자가 허가하지 않으면 삭제하거나 재다운로드하지 않는다.
<br>

#### **Shutdown**

**[Input Handling] 검색 조건 오류시 실행 중단하기**
- **목적:** 인식하지 못한 조건을 삭제해 검색 범위가 조용히 넓어지는 일을 막는다.
- `search_filters`의 공시유형 입력은 `disclosure_type_groups`만 사용한다.
- `disclosureTypeArrXX`, `disclosureTypeXX`, `pDisclosureTypeXX`는 `disclosure_type_groups`를 바탕으로 생성한다.
  - 해당 값들은 직접 입력하면 실패 처리한다.
<br>

**[Input Handling] 메타데이터 강제하기**
- **목적:** 메타데이터가 없는 경우 작동하지 않도록 강제한다.
- 본문 파일이 있는 폴더에는 무조건 `kind_workflow.input.json`이 있어야 한다.
  - 읽을 수 없거나, 필수 필드가 누락된 상태거나, `format`이 현재 값이 아니라면 실패 처리한다.
<br>

**[Input Handling] KIND 조회 실패시 즉시 종료하기**
- **목적:** 로컬 파일과 서버 파일을 비교하지 못할 경우 실패 처리한다.
- 메타데이터 내 조건으로 KIND에 요청을 보냈을 때 전체 페이지 수나 건수를 조회하지 못한 경우 실패 처리한다.
<br>

**[Input Handling] 저장 pagination 읽기 실패시 즉시 종료하기**

- **목적:** 기존 다운로드 범위를 앞선 값이나 빈 요약으로 추측하지 않는다.
- 저장된 마지막 페이지나 결과 폴더 목록에서 pagination 정보를 읽지 못하면 앞선 페이지 값이나 `null` 요약으로 대신하지 않고 실패 처리한다.
<br>

**[Result Validation] 다운로드 중 KIND 목록 변경시 즉시 종료하기**
- **목적:** 한 검색기간에 서로 다른 시점의 공시 목록이 섞인 결과를 게시하지 않는다.
- 다시 받은 첫 페이지의 페이지 정보나 공시 행이 첫 다운로드와 다르면 실패 처리한다.
- 새 임시 결과를 게시하지 않으므로 이전 기간 결과가 있으면 그대로 유지한다.
<br>

### **3. Serving**

#### **Feature**

**[Input Handling] 다운로드 실행 기본값 기능**

- **목적:** 생략 가능한 요청값을 정상 계약에 정의된 값으로 채운다.
- 회사명은 `""`, 제출인은 `""`, 시장은 `전체`, 증권 종류는 `전체`로 채운다.
- 시작 페이지는 1, 페이지 크기는 100, 요청 간 대기는 1초, 제한 시간은 20초다.
- 병렬 처리 방법을 고르지 않으면 연도 단위로 나누어 실행한다.
- 진행 내역 보관 수를 정하지 않으면 20줄을 사용하며 최대 500줄까지 보관한다.
<br>

**[Core Processing] 다운로드 표시 수**

- 누락 페이지는 앞의 20개만 보여 준다.
- 직접 실행할 때는 진행 내역을 실행 중에만 전달한다. 백그라운드 작업은 정해진 줄 수만큼 최근 내역을 보관한다.
<br>

#### **Fallback**

- 없음.

#### **Shutdown**

**[Input Handling] 검색 요청 오류시 중단**
- **목적:** 잘못된 입력을 임의로 바꿔 검색하지 않는다.
- 시장, 증권 종류와 공시 유형이 허용된 값이 아니면 실패 처리한다.
- 저장된 검색 조건을 현재 형식으로 정확히 바꿀 수 없으면 실패 처리한다.
<br>

**[Result Validation] 기존 결과 조회 오류시 중단**

- **목적:** 읽을 수 없는 기존 결과를 빈 결과로 표시하지 않는다.
- 기존 결과 폴더를 읽을 수 없으면 결과가 없는 것으로 표시하지 않고 실패 처리한다.
