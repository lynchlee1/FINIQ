# KIND 조건검색 결과 저장 예외 사양

복구 동작, 중단 조건과 정상 범위를 벗어난 계약만 설명한다.

## 처리 계약

### 복구 동작

#### 기존 결과 무효화 후 전체 기간 입력 확정

일부 정상처럼 보이는 페이지를 현재 실행의 입력으로 받아들이지 않는다.
- 기존 결과 검증이 실패하면 해당 기간의 본문과 workflow 보조 파일을 현재 입력에서 제외한다.
- 화면에서 재다운로드 확인을 받으면 빈 시작 상태와 전체 검색기간을 다운로드 입력으로 확정한다.
- 실제 페이지는 정상 다운로드 규칙에 따라 다시 만든다.

### 중단 조건

#### 검색 조건 오류가 나면 실행 중단

인식하지 못한 조건을 삭제해 검색 범위가 조용히 넓어지는 일을 막는다.
- `search_filters`의 공시유형 입력은 `disclosure_type_groups`만 사용한다.
- `disclosureTypeArrXX`, `disclosureTypeXX`, `pDisclosureTypeXX`는 `disclosure_type_groups`를 바탕으로 만든다.
  - 해당 값들은 직접 입력하면 실패 처리한다.

#### 필수 metadata

메타데이터가 없는 경우 작동하지 않도록 강제한다.
- 본문 파일이 있는 폴더에는 무조건 `kind_workflow.input.json`이 있어야 한다.
  - 읽을 수 없거나, 필수 필드가 누락된 상태거나, `format`이 현재 값이 아니라면 실패 처리한다.

#### KIND 조회가 실패하면 즉시 종료

로컬 파일과 서버 파일을 비교하지 못할 경우 실패 처리한다.
- 메타데이터 내 조건으로 KIND에 요청을 보냈을 때 전체 페이지 수나 건수를 조회하지 못한 경우 실패 처리한다.

#### 저장한 pagination을 읽지 못하면 즉시 종료

기존 다운로드 범위를 앞선 값이나 빈 요약으로 추측하지 않는다.
- 저장된 마지막 페이지나 결과 폴더 목록에서 pagination 정보를 읽지 못하면 앞선 페이지 값이나 `null` 요약으로 대신하지 않고 실패 처리한다.

#### 다운로드 중 KIND 목록이 바뀌면 즉시 종료

한 검색기간에 서로 다른 시점의 공시 목록이 섞인 결과를 게시하지 않는다.
- 다시 받은 첫 페이지의 페이지 정보나 공시 행이 첫 다운로드와 다르면 실패 처리한다.
- 새 임시 결과를 게시하지 않으므로 이전 기간 결과가 있으면 그대로 유지한다.

## 화면과 서비스 계약

### 복구 동작

#### 전체 기간 재다운로드 확인

기존 결과 삭제와 전체 기간 재다운로드 여부를 사용자가 결정하게 한다.
- 기존 결과 검증이 실패하면 삭제·재다운로드 전에 우측 알림 창에서 사용자 결정을 받는다.
- 서버는 `workflow_status=needs_download_confirmation`과 함께 충돌 내역, `download_confirmation`을 반환한다.
- `download_confirmation`은 현재 01단계 설정과 충돌별 기간·종류·저장 페이지 수·현재 KIND 페이지 수로 만든 hash다.
- 다시 실행할 때 서버가 반환한 `download_confirmation`을 보내야 기존 결과를 지우고 다시 받는다. 그사이 01단계 설정이나 충돌 내역이 바뀌면 새 확인값을 반환하고 다시 판단을 기다린다.
- 사용자가 허가하지 않으면 기존 결과를 지우거나 다시 받지 않는다.
- 실제 작업 순서는 [01단계 결과 다시 받기](guides.md)에서 확인한다.

### 중단 조건

#### 검색 요청 오류가 나면 중단

잘못된 입력을 임의로 바꿔 검색하지 않는다.
- 시장, 증권 종류와 공시 유형이 허용된 값이 아니면 실패 처리한다.
- 저장된 검색 조건을 현재 형식으로 정확히 바꿀 수 없으면 실패 처리한다.

#### 기존 결과 조회 오류가 나면 중단

읽을 수 없는 기존 결과를 빈 결과로 표시하지 않는다.
- 기존 결과 폴더를 읽을 수 없으면 결과가 없는 것으로 표시하지 않고 실패 처리한다.
- 기존 다운로드 결과를 읽어 화면 결과를 만든다.
