# KIND Search Result Download Features

## Purpose

KIND 공시 조건검색 결과를 페이지별로 내려받아 이후 단계에서 사용할 수 있게 저장한다.

## Features

### Download KIND Search Results

#### Behavior

공시 자동화 01단계에서 정한 검색 조건으로 KIND 공시 목록을 페이지별로 내려받는다.

`연도별` 처리는 요청 기간을 달력 연도 경계에서 나누는 방식이다. 연도마다 하나의 고정 폴더를 유지하거나 앞선 폴더의 종료일을 늘리는 방식은 아니다.

- 요청 시작일과 종료일이 같은 연도에 있으면 해당 요청 기간을 하나의 `<START_DATE>_<END_DATE>` 기간 폴더에 저장한다.
- 같은 연도에 다음 기간을 이어받아도 기존 폴더를 확장하지 않고 다음 요청 기간의 별도 폴더를 만든다.
- 요청 기간이 연도를 넘으면 각 연도의 마지막 날과 다음 연도의 첫날을 경계로 기간을 나눈다.
- 같은 연도에 여러 기간 폴더가 생겨도 다음 SQLite 변환 단계는 공통 상위 입력 경로에서 모든 결과를 읽고 공시일 연도별로 다시 묶는다.

#### Defaults and Exceptions

- 검색 조건을 검증할 수 없거나 저장된 조건을 현재 형식으로 정확히 바꿀 수 없으면 검색 범위를 바꾸지 않고 실패 처리한다.
- 같은 연도의 기간별 폴더를 다운로드 단계에서 합치거나 이름을 바꾸지 않는다. 각 폴더 이름과 metadata에는 실제 요청 시작일과 종료일을 유지한다.

### Validate Existing Data Integrity

#### Behavior

연도별 저장 결과가 현재 KIND 검색 결과와 맞아 재사용할 수 있는지 확인한다.

- 검사를 시작할 때 선택한 데이터 경로와 검색 조건을 하나의 실행 입력으로 고정하고, 파일 구성 검사와 KIND 재조회 및 이어지는 다운로드에 같은 입력을 사용한다.
- `메타데이터 읽기`는 저장된 `kind_workflow.input.json`만 확인하고 본문 파일 구성 검사와 KIND 조회를 시작하지 않는다.
- 메타데이터 응답과 오류는 검사를 시작한 데이터 경로에만 반영하며, 경로가 바뀐 뒤 도착한 결과는 현재 상태를 덮어쓰지 않는다.
- `저장 파일 구성 검사`는 메타데이터 읽기와 현재 설정 비교가 끝난 뒤에만 시작한다.
- 저장 파일 구성과 KIND 건수는 같은 검사 작업에서 순서대로 확인한다. `저장 파일 구성 검사`만 순번과 `검사하기`를 표시하고, 종속된 `KIND 건수 비교`는 순번 없이 검사 중에도 `대기`로 표시한다.
- `저장된 설정 적용`은 완료된 메타데이터 읽기 결과를 유지하고 현재 설정 비교만 즉시 다시 계산한다. 적용 뒤에는 메타데이터를 다시 읽지 않고 `저장 파일 구성 검사`부터 이어서 검사한다.
- 저장 범위들의 검색 설정이 서로 다르면 하나의 설정으로 맞출 수 없으므로 `저장된 설정 적용`을 제공하지 않는다.
- 연도별 폴더마다 저장된 검색 조건을 현재 조건과 비교하며, 한 폴더라도 다르면 기존 결과 재사용과 다운로드 시작을 막는다.
- 연도 분할 폴더 이름의 시작일·종료일은 해당 폴더의 `kind_workflow.input.json` 기간과 정확히 같아야 한다.
- 본문 파일이 있는 폴더에는 읽을 수 있고 필수 필드와 현재 `format`을 갖춘 `kind_workflow.input.json`이 있어야 한다.
- `kind_workflow.input.json`의 조건으로 연도별 재검색한 전체 공시 수는 저장값과 같아야 한다.
- 페이지 번호는 중복 없이 1부터 연속해야 한다.
- 본문 간 전체 페이지 수와 건수는 일치해야 한다.
- 공시 링크가 유효하면 회사 링크가 없는 행도 공시 건수에 포함한다. 회사 링크 유무를 페이지 손상 판정에 사용하지 않는다.
- 공시 유형 코드는 선택 순서와 관계없이 같은 집합이면 같은 검색 조건으로 판단한다.
- 로컬 본문 검사는 실행 설정의 worker 수로 페이지를 병렬 확인하고 입력 페이지 순서대로 결과를 합친다.
- 여러 기간 폴더를 검사할 때는 로컬 폴더 범위를 병렬 처리하고 각 폴더 내부 worker는 1개로 제한한다. 기간 폴더가 하나이면 그 폴더의 페이지를 병렬 처리한다. KIND 현재 건수 조회는 기간별로 직렬 실행한다.
- 문제가 있는 파일을 사용자의 확인을 받아 삭제하면 삭제 목록은 처리 내역으로 남기고, 남은 폴더의 파일 구성과 KIND 건수를 다시 검증한다.
- 삭제 허가는 삭제 예정 파일을 확인한 실행 입력에만 적용하며, 화면의 데이터 경로나 검색 조건이 달라지면 새 조건의 파일을 대신 삭제하지 않는다.

#### Defaults and Exceptions

- 기존 결과 폴더를 읽을 수 없으면 실패 처리하고 빈 결과로 취급하지 않는다.
- 본문 파일이 없는 폴더는 기존 다운로드 범위로 취급하지 않는다.
- 메타데이터 내 조건으로 KIND에 요청을 보냈을 때 전체 페이지 수나 건수를 조회하지 못하면 실패 처리한다.
- 무결성 검증이 실패한 기간의 본문과 workflow 보조 파일은 현재 실행 입력에서 제외한다.
- 저장된 본문에서 전체 페이지 수와 공시 건수를 확인할 수 없으면 해당 기간을 손상된 결과로 판정하고, 관련 본문과 workflow 파일을 실패 원인과 함께 정리 후보로 표시한다.
- 새 검사를 시작하거나 검사 입력이 바뀌면 앞선 삭제 확인과 확인 문구를 지운다.
- 삭제 요청은 파일 삭제 묶음을 시작하기 전까지만 취소할 수 있다. 삭제를 시작한 뒤에는 본문만 지우고 workflow 보조 파일을 남기지 않도록 확인된 후보 묶음을 끝까지 처리한다.
- 검사 중 화면의 경로나 검색 조건을 바꿔도 진행 중인 검사와 다운로드 입력은 바뀌지 않으며, 바뀐 값은 다음 요청부터 사용한다.
- 검사 시작이 거부되거나 작업이 실패·취소되면 실행 중 상태를 끝내고 같은 조건으로 다시 검사할 수 있게 한다.
- 검사 작업 중 화면을 새로 열어도 작업 ID와 고정한 실행 입력을 함께 복구해 완료 후 검증과 다운로드 연결을 이어 간다.
- 작업 상태를 일시적으로 조회하지 못하면 실행 중 잠금과 작업 ID를 유지하고 같은 작업의 상태 조회를 계속한다.
- 새 작업이 시작된 뒤 도착한 이전 작업의 응답과 오류는 현재 상태와 후속 동작에 반영하지 않는다.
- 화면은 비교표, 영향받은 파일·기간과 복구 동작을 실패한 검사 단계 아래에만 표시한다.

### Record Download Metadata and Resume

#### Behavior

다운로드 조건, 페이지별 진행 내역과 검증 상태를 metadata로 남긴다.

#### Defaults and Exceptions

- 다운로드가 정상 완료되지 않으면 `kind_workflow.input.json`을 만들지 않는다.
- 중단된 다운로드를 재개하면 `kind_workflow.checkpoint.json`에 저장된 마지막 페이지와 pagination 정보를 재개 기준으로 사용한다.
- 저장된 pagination을 읽을 수 없으면 앞선 페이지 값이나 `null` 요약으로 대신하지 않는다.

### Verify Download List Consistency

#### Behavior

한 기간의 모든 페이지를 받은 직후 같은 검색 조건으로 첫 페이지를 다시 요청한다.

#### Defaults and Exceptions

- 다시 받은 페이지 정보와 공시 행이 첫 다운로드와 같을 때만 새 임시 결과를 게시한다.
- 두 목록이 다르면 실패 처리하고 새 임시 결과를 게시하지 않으며 이전 기간 결과를 유지한다.

### Display Results and Progress

#### Behavior

누락 페이지와 다운로드 진행 내역을 화면에 전달한다.

- 저장 파일 구성 검사는 대상 폴더 수집, 로컬 구성 검사, KIND 조회 잠금 대기·시작, 범위별 완료와 최종 결과를 `실행 현황`에 기록한다.

#### Defaults and Exceptions

- 전체 누락 결과를 바꾸지 않고 화면에 전달할 범위만 제한한다.
- 직접 실행의 진행 내역은 실행 중에만 전달한다.
- 백그라운드 작업은 정해진 줄 수만큼 최근 진행 내역을 보관한다.

### Redownload Entire Date Range

#### Behavior

기존 결과 검증이 실패하면 기존 결과 삭제와 전체 기간 재다운로드 여부를 사용자가 결정하게 한다.

1. 공시 자동화 화면 오른쪽 `알림`에서 어느 기간의 결과가 어떤 검사에서 어긋났는지 확인한다.
2. 기존 결과를 지우고 해당 기간을 처음부터 다시 받아도 되는지 판단한다.
3. 다시 받으려면 `전체 다시 받기`를 누른다. 기존 결과를 유지하려면 누르지 않는다.
4. 작업이 끝나면 01단계 상태가 `완료`로 바뀌었는지 확인한다.

#### Defaults and Exceptions

- 서버는 `workflow_status=needs_download_confirmation`과 함께 충돌 내역과 `download_confirmation`을 반환한다.
- `download_confirmation`은 현재 01단계 설정과 충돌별 기간·종류·저장 페이지 수·현재 KIND 페이지 수로 만든 hash다.
- 다시 실행할 때 서버가 반환한 `download_confirmation`을 보내야 기존 결과를 지우고 빈 시작 상태에서 전체 검색기간의 페이지를 다시 만든다.
- 그사이 01단계 설정이나 충돌 내역이 바뀌면 새 확인값을 반환하고 다시 판단을 기다린다.
- 사용자가 허가하지 않으면 기존 결과를 지우거나 다시 받지 않는다.
