# 06 목차 분리 실행

## 목차 기준으로 HTML 분리

- `disclosures/html_sections.py`는 원본 `toc_N` heading, ID가 없는 구형 heading, 구형 paragraph, XForms 단일 서식 본문 중 하나를 상호 배타적으로 확정한다. `CORRECTION` paragraph는 같은 문서의 정정 목차로 포함한다.
- 원본 `toc_N`은 그대로 보존한다. 첫 경계 이전 영역은 `preamble`, 목차 없는 XForms 본문은 `document` ID를 사용한다.
- 각 결과에는 `kind`, `level`, `parent_toc_id`, `is_toc`을 기록한다. `cover`는 위계 stack을 초기화하고, `part`와 `section`은 앞선 더 낮은 level 중 가장 가까운 항목을 부모로 갖는다.
- 첫 정정 목차를 제외한 모든 section을 하나의 유효한 HTML 문서로 자동 저장하며 Manual selection을 요구하지 않는다.

### 입력 범위

- 이전 클라이언트가 `section_save_rules`를 보내도 저장 범위 결정에는 사용하지 않는다.
- `limit`은 처리할 입력만 줄인다. 제한 밖에 있지만 전체 입력으로 설명되는 기존 HTML을 예상 밖 파일로 판정하지 않는다.

### 출력과 게시

- 새 HTML은 임시 폴더에서 모두 만든 뒤 출력으로 옮긴다. 게시 중 교체 실패·취소·최종 무결성 오류가 나면 이번에 게시한 파일을 제거하고 교체 전 파일을 모두 복원한다.
- 표준 작업공간의 출력 경로는 현재 소유 모드의 `06-sections/<mode>`만 허용한다. `06-sections` 또는 다른 mode를 지정해도 경로를 보정하지 않는다.
- 파생 필터는 상위 기본 필터의 `06-sections/<parent_mode>`를 사용하고 자식 전용 06단계 폴더는 만들지 않는다.

### 병렬 처리와 결과 표시

- 목차 조합 요약, 분리 저장과 결과 검사는 설정한 worker 수 범위에서 HTML 파일별로 병렬 처리하고 입력 파일 순서로 결과를 합친다.
- 목차 분리 실행이 끝나면 실행한 전체 입력에서 확인한 고유 목차 구조를 빠짐없이 화면에 표시한다. 구조 안의 각 구간은 내부 ID를 이어 붙이지 않고 `머리말`, `표지`, `부`, `N단계 목차`, `본문`과 제목을 줄 단위·위계별 들여쓰기로 보여주며, 실행에서 제외되는 정정 구간에는 `제거 예정`을 표시한다. 실제 목차만 센 `목차 수`, 비목차 구간까지 포함한 `전체 구간 수`, 같은 구조를 가진 `공시 수`를 구분한다.

### 입력 구조 오류

- 입력 파일을 읽거나 parsing하지 못하면 목록·요약·검사·저장 작업 전체를 실패 처리한다.
- 전체 문서와 과거 KIND 본문 조각은 같은 HTML parser가 `body`를 갖춘 문서로 정규화한다. 정규화한 `body`에서 검증된 구조 중 하나로 유일하게 확정할 수 없으면 실패 처리하며, 다른 selector나 문자열 규칙으로 우회하지 않는다.
- `toc_N`이 중복·역순이거나 일부 구조 heading에만 붙어 있으면 목차를 추정하지 않고 실패 처리한다.
- 구조 경계와 parser가 바로 뒤로 옮긴 제목 `p`에서 제목을 찾지 못하면 실패 처리한다.

### 경로와 기존 출력 오류

- `06-sections/<YYYY>/`는 만들지 않는다. 그 경로로 쓰려 하면 실패 처리하며 `06-sections/<YYYY>/`를 읽어 보정하지도 않는다.
- 입력 폴더와 출력 폴더가 같거나 서로 안쪽에 있으면 자기 결과를 다시 입력으로 읽을 수 있으므로 저장 전에 실패 처리한다.
- 기존 출력에 현재 입력으로 설명할 수 없는 HTML이 있으면 자동 삭제하거나 정상 완료로 표시하지 않고, 실제 쓰기 전에 실패 처리한다.
- 출력 폴더 아래 symbolic link는 외부 경로로 쓰거나 읽을 수 있으므로 저장과 결과 검사 전에 실패 처리한다.

## 검사와 진행 내역 표시

분리 결과를 바꾸지 않고 화면에 전달할 진행 내역만 제한한다.

### 검사 입력

- 화면은 `기존 데이터 검토` 바로 아래에서 `조건검색 필터`를 선택하게 하고, 목록에는 기본 필터만 보여 준다. 검사·개별 공시·저장은 선택한 기본 필터의 내부 HTML을 읽고 `06-sections/<mode>`에 저장한다.
- 파생 필터를 이 단계에 전달하면 상위 기본 필터가 소유한 05·06 폴더를 사용한다. 화면에 보이지 않는 이전 페이지의 모드를 대신 사용하지 않는다.

### 검사 범위

- `기존 데이터 검토`는 첫 화면에 표시할 목록만이 아니라 입력 HTML 전체를 읽어 목차 구성과 문제 파일을 검사한다.
- 저장 결과 검사는 입력 순서대로 만든 예상 HTML을 실제 파일과 즉시 비교하고, 이후 비교에는 상대 경로와 건수만 보관한다.
- KIND가 과거에 `<html>`, `<head>`, `<body>` 없이 본문 조각만 제공한 원문도 같은 HTML parser의 정상 입력으로 문서화한 뒤 목차를 판정한다. 별도 parser나 다른 데이터 소스로 우회하지 않는다.
- 규격화된 `KIND 원본 없음` 빈 원문은 실제 공시 본문처럼 목차를 해석하지 않는다. 파일명의 접수번호와 파일 안의 접수번호가 같을 때만 원문을 같은 상대 경로에 그대로 저장하고, 검사 결과에는 별도 건수로 남긴다.

### 검사 결과 표시

- `KIND 원본 없음` 항목은 원문 placeholder만 열 수 있으며 행과 상단 검토 패널의 목차별 보기 동작은 실행하지 않는다.
- 전체 검사는 한 파일의 오류에서 중단하지 않는다. 정상·`KIND 원본 없음`·목차 없음·읽기 실패 건수를 각각 집계하고, 설정한 표시 수까지 문제 파일의 상대 경로와 구체적인 원인을 반환한다. 화면은 전체 문제 건수와 첫 문제의 경로·원인을 함께 표시한다.

### 진행 기록

- 목차 HTML 저장 결과의 진행 내역은 생성 중부터 최근 200줄만 보관한다.
- 우측 `설정`의 `진행 확인 간격 (건)`을 전체 검사와 분리 저장 요청에 함께 전달하며, 각 작업은 첫 건·설정한 간격·마지막 건에 진행 로그를 남긴다.
