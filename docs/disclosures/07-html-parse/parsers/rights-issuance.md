# 유상·무상증자 공시 변환

## 목적

`rights_issuance` mode가 유상·무상·유무상증자 공시에 공통으로 적용하는 표 선택, 주식 종류, 상태와 검증 규칙을 정의한다.

## 단계 계약

### 증자 mode 선택

- `parse_rights_issuance()`가 `rights_issuance` mode의 업무값을 공통 record에 추가한다.

### 회사 metadata 연결

- metadata에 회사명이 있으면 `corp_name`에 저장한다.

### 발행 유형 결정

- 외부 제목의 공백을 정리한 뒤 `유무상증자` → `무상증자` → `유상증자` 순서로 확인한다.
- 확정한 유형을 `증자유형`에 저장하고 유형별 결과 규칙을 선택한다.

#### 중단 조건

- 외부 제목이 없거나 세 유형 중 하나를 확정하지 못하면 실패 처리한다.

### 증자 표 선택

- 번호를 정규화한 한 칸 제목이 `유상증자`·`무상증자`인 표를 선택한다.
- 첫 줄에 `제3자배정 대상자`와 `배정주식수`가 있거나, 두 칸 이상인 줄의 `N=1`이 번호와 공백을 제외하고 `신주의 종류와 수`·`신주 발행가액`과 정확히 일치하는 표도 선택한다.
- 선택한 표의 `logical_rows`를 HTML 순서대로 합치며 선택하지 않은 표에서 값을 찾지 않는다.

### 고정 N 행 찾기

- 행 검사용 셀은 앞 번호와 공백을 제거한다.
- field마다 정한 `N`번째 셀 이름이 정확히 일치하는 첫 행만 사용하고 값은 그 행의 맨 오른쪽에서 읽는다.
- 주식 종류나 목적처럼 추가 구분이 필요한 field는 정해진 다음 셀도 정확히 확인한다.

#### 제약과 분기

- 값이 비거나 숫자로 바꿀 수 없어도 다른 행으로 바꾸지 않는다.
- 증자유형은 외부 제목, 발행대상자는 열 header로 정하므로 이 규칙을 적용하지 않는다.

### 공통 일정 필드 추출

- `N=2`에 주식 종류가 있으면 종류별 값을 저장하고 두 칸 양식은 보통주식 값으로 저장한다.
- `신주배정기준일`, `1주당 신주배정주식수 (주)` 또는 단위 없는 같은 이름, `신주권교부예정일`은 `N=1`이 같은 첫 행의 맨 오른쪽 값을 읽는다.
- `상장예정일`은 공백을 뺀 `N=1`이 `신주의 상장 예정일`과 같은 첫 행의 맨 오른쪽 값을 읽는다.

### 주식 수량 추출

- `신주의 종류와 수`는 `N=1`이 해당 이름이고 `N=2`가 정해진 주식 종류인 첫 행의 맨 오른쪽 값을 읽는다.
- 보통주식은 `보통주식 (주)`·`보통주 (주)`, 기타주식은 `기타주식 (주)`·`기타주 (주)`·`우선주식 (주)`·`우선주 (주)`·`종류주식 (주)`·`종류주 (주)`를 허용한다.

#### 제약과 분기

- 첫 일치 행이 0이나 `-`여도 뒤 행의 양수로 바꾸지 않는다.

### 발행 전 주식 총수 추출

- `N=1`이 `증자전 발행주식총수 (주)` 또는 `증자전 발행주식총수`, `N=2`가 정해진 주식 종류인 첫 행의 맨 오른쪽 값을 읽는다.
- 보통주식은 `보통주식`·`보통주`, 기타주식은 `기타주식`·`기타주`·`우선주식`·`우선주`·`종류주식`·`종류주`를 허용한다.

### 배정 대상자 추출

- 첫 줄의 서로 다른 열에 `제3자배정 대상자`와 `배정주식수`가 있는 첫 표를 사용한다.
- 대상자나 수량이 없는 줄은 제외하고 한 수량 칸에 정수가 여러 개면 모두 더한다.
- 특정 단위나 기호가 붙은 숫자를 따로 제거하지 않는다.

#### 제약과 분기

- 모든 대상자명이 `-`이고 모든 수량을 읽을 수 없으면 `[["-", 0]]`과 `explicit_zero`를 반환한다.
- 대상자가 둘 이상이고 전체 수량이 신주 합계의 두 배이며 마지막 합계 이름·수량이 신주 합계와 맞으면 마지막 줄을 제거한다.
- 합계 이름은 `계`, `합계`, `소계`, `총계`가 독립된 단어일 때만 인정한다.
- 저장할 대상자가 없으면 `null`, `source_not_found`와 strong warning을 기록한다.
- `증자방식`에 `제3자배정`이 있고 제목에 `종속회사`가 없는데 대상자 표가 없어도 같은 처리한다.
- 대상자 추출이 적용되지 않는 공시는 빈 목록을 반환한다.
- 대상자 합계가 신주 합계와 달라도 값을 저장하고 다음 후보 표로 바꾸지 않는다.

### 필드 상태 기록

- `신주의 종류와 수`, `증자 전 발행주식총수`, `발행가액`에 전체 상태와 종류별 상태를 만든다.
- 하나라도 양수이면 `parsed`, 양수 없이 0이나 `-`가 있으면 `explicit_zero`, 원본이 모두 없으면 `source_not_found`다.

#### 제약과 분기

- 종류별 원본 누락과 증자 전 보통주식이 0인 경우는 strong, 복수 종류가 양수면 medium, 전체 수량이 명시적 0이면 weak warning을 만든다.

### 발행 관계 검증

- 발행대상자 합계와 신주 합계가 다르면 차이 크기와 관계없이 weak warning을 만든다.
- 발행목적 합계와 `신주 수량 × 같은 종류의 양수 발행가액` 합계가 다르면 weak warning을 만든다.

#### 제약과 분기

- 관계가 달라도 값을 고치지 않으며 유형별 상세값에는 별도 상태나 warning을 만들지 않는다.

### 최상위 결과 생성

- 공통 추출값은 최상위에 두고 유형별 상세 결과는 `유상증자`와 `무상증자`에 저장한다. 적용하지 않는 상세 결과는 `null`이다.
- 유상증자와 유무상증자는 최상위 수량·목적·가액·방식·납입일·일정·발행대상자를 `유상증자`에 저장한다.
- `유상증자`의 `신주배정기준일`과 `1주당 신주배정주식수`는 유상 부분에서 따로 읽는다.

### 증자 parser 문제 조사

- 06단계 HTML과 `resources/KIND/rights_issuance`의 실제 KIND 파일을 대조한다.

## 파일과 저장 형식

- `<data_root>/06-sections/rights_issuance/<YYYY>/<acpt_no>.html`을 입력으로 받아 `<data_root>/07-converted/rights_issuance/parsed-rights_issuance.json`에 구조화 결과를 저장한다.
- 증자 유형 판정에 title이 필요하므로 `compressed_metadata_path`에서 선택한 모든 HTML의 title을 연결해야 한다.

### `<data_root>/07-converted/rights_issuance/parsed-rights_issuance.json`

- 유상·무상·유무상증자 공통 record를 담은 출력 파일이다.
- `신주의 종류와 수`와 `증자 전 발행주식총수`는 보통주식·기타주식 항목을 항상 유지한다.
- 전용 최상위 field는 `corp_name`, `증자유형`, `신주의 종류와 수`, `증자 전 발행주식총수`, `발행목적`, `발행가액`, `증자방식`, `납입일`, `신주권교부예정일`, `상장예정일`, `발행대상자`, `유상증자`, `무상증자`다.
- `증자유형`은 `유상증자`, `무상증자`, `유무상증자` 중 하나다.
- 종류별 수량과 가격은 `[["보통주식", 값], ["기타주식", 값]]` 순서를 유지한다. 원본을 찾지 못한 종류의 값은 `null`이다.
- `발행목적`과 `발행대상자`는 `[[이름, 정수], ...]`, 빈 배열, `null` 또는 적용하지 않음을 나타내는 `"-"`다. `발행가액`은 종류별 목록 또는 `"-"`다.
- `유상증자`는 최상위 유상 field에 `신주배정기준일`과 `1주당 신주배정주식수`를 더한 객체다. `무상증자`는 수량·증자 전 수량·배정기준일·1주당 배정수·교부예정일·상장예정일을 담은 객체다.
- 유상증자는 `무상증자=null`, 무상증자는 `유상증자=null`, 유무상증자는 두 객체를 모두 저장한다.
- `field_parse_status`는 최상위 업무 field 상태, `field_parse_status_detail`은 종류별 수량·증자 전 수량·발행가액 상태를 기록한다. 유형별 상세 객체에는 별도 상태를 만들지 않는다.

## 무상증자 전용 계약

### 유상 항목 미적용 처리

- `발행목적`, `발행가액`, `증자방식`, `납입일`, `발행대상자`는 검색하지 않는다.
- 각 값에는 `-`, 상태에는 `not_applicable`을 기록하며 warning과 합계 검증에서 제외한다.

### 무상 상세 결과 생성

- `신주의 종류와 수`, `증자 전 발행주식총수`와 공통 일정값을 무상증자 부분에서 읽어 최상위와 `무상증자`에 저장한다.
- `유상증자`는 `null`로 저장한다.

#### 제약과 분기

- 무상 상세값이 누락돼도 최상위 값으로 채우지 않는다.

## 유상증자 전용 계약

### 자금 사용 목적 추출

- `N=1`이 `자금조달의 목적`과 정확히 일치하는 모든 행에서 `N=2`의 사용처명과 맨 오른쪽 금액을 HTML 순서대로 읽는다.

#### 제약과 분기

- 0이나 `-`인 항목은 제외한다.
- 숫자를 하나도 읽지 못하면 `null`과 `source_not_found`, 숫자는 있지만 양수 항목이 없으면 빈 목록과 `explicit_zero`를 기록한다.
- 사용처명에서는 원 단위 표기만 제거하며 허용 이름이나 탐색 순서를 하드코딩하지 않는다.

### 발행가액 추출

- 일반 양식은 `N=1`이 `신주 발행가액`, `N=2`가 주식 종류인 첫 행의 맨 오른쪽 값을 읽는다.
- 예정·확정 양식은 `N=1`이 `신주 발행가액`, `N=2`가 `확정발행가`, `N=3`이 주식 종류인 첫 행의 맨 오른쪽 값을 읽는다.

#### 제약과 분기

- 보통주식·기타주식 두 항목을 항상 유지한다.
- 첫 일치 행의 0이나 `-`를 뒤 행의 양수로 바꾸지 않으며 숫자를 읽지 못한 종류는 `null`이다.
- `N=2`가 `예정발행가`인 행은 맨 오른쪽이 확정예정일이므로 사용하지 않는다.

### 방식과 납입일 추출

- `N=1`이 `증자방식` 또는 `납입일`과 정확히 일치하는 첫 행의 맨 오른쪽 값을 각 field에 저장한다.

### 유상 상세 결과 생성

- `무상증자`는 `null`로 저장한다.

## 유상·무상증자 전용 계약

### 유상·무상 구간 분리

- 합친 줄에서 앞 번호와 공백을 제거한 `N=1`이 `무상증자`와 정확히 일치하는 첫 한 칸짜리 행을 구분점으로 사용한다.
- 앞 번호가 없는 `무상증자`도 같은 구분점으로 사용한다.
- 구분점 앞은 유상 부분, 뒤는 무상 부분으로 처리한다.

#### 중단 조건

- 외부 제목이 유무상증자인데 구분점을 찾지 못하면 실패 처리한다.

### 유상 상세 결과 생성

- 공통 유상 상세 규칙을 구분점 앞의 유상 부분에 적용한다.

#### 제약과 분기

- 유상 부분의 값이 누락돼도 선택하지 않은 표나 최상위 값으로 채우지 않는다.

### 무상 상세 결과 생성

- 수량, 증자 전 수량, 배정기준일, 1주당 배정수, 교부예정일과 상장예정일을 무상 부분에서 다시 읽어 `무상증자`에 저장한다.

#### 제약과 분기

- 무상 부분의 값이 누락돼도 최상위 값이나 유상 상세값으로 채우지 않는다.
