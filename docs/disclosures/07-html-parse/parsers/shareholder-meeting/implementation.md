# 주주총회 구현 원칙

## 안건과 두 개의 허용 대체 경로

기본 원본은 첫 번째로 확인된 구조화 안건 표 하나다. 표를 선택할 때 제목 열도 함께 고정한다. 행 값이 비어 있거나 형식이 맞지 않아도 다른 열, 후손 셀, 인접 셀, 뒤의 표로 바꾸거나 여러 표를 합치지 않는다.

실패 뒤 다른 원본을 찾는 대체 경로(fallback)는 두 개만 허용한다.

1. 문서에 구조화 안건 스키마가 아예 없을 때만, 정확한 라벨과 같은 행에 있는 두 개의 직접 자식 셀을 읽는다.
2. 이름으로 선임 상세와 안건을 연결한 결과가 0건이고, 같은 직책의 선임 상세와 이름 없는 호환 안건이 각각 한 건뿐일 때만 둘을 연결한다.

구조화 안건 표는 첫 머리글에 `번호`와 `회의목적사항`이 있는 표다. 표의 직접 행과 각 행의 직접 셀만 사용하므로 바깥 layout 표가 안쪽 안건 표의 머리글을 자기 값처럼 가져가지 않는다. 평면 표는 `회의목적사항`을 제목 열로 고정한다. 그룹 머리글은 둘째 줄에 `안건` 열이 명시된 경우에만 그 열을 사용한다. 구형 안건은 첫 직접 자식 셀의 번호와 공백을 정규화한 값이 `결의사항`, `기타 결의사항`, `의안 주요내용` 중 하나와 정확히 일치할 때 둘째 직접 자식 셀을 읽고, `<br>`과 안건 번호·표식으로 레코드를 나눈다. 정정 전후 비교 표와 `-` 같은 자리표시자는 안건으로 사용하지 않는다.

주식 양도, 외부감사인, 사업목적 합병처럼 표현이 여러 개인 항목은 첫 문법이 실패한 뒤 다른 문법을 시도하지 않는다. 같은 기준 원본에서 가능한 후보를 독립적으로 모은 뒤 중복을 제거한다.

## 인물 식별자 사전 결정

사람을 만들기 전에 선임 상세 행에서 같은 인물 키에 연결된 생년월을 모아 식별자를 정한다.

- 생년월이 없으면 생년월 없는 식별자를 사용한다.
- 생년월이 하나면 그 값을 가진 식별자를 사용한다.
- 서로 다른 생년월이 둘 이상이면 동명이인일 수 있으므로 생년월이 없는 안건이나 선임 표면을 어느 한 사람에게 연결하지 않는다.
- 선임 상세 행에 생년월이 적혀 있으면 원문 값을 그대로 유지한다.

선임 대상, 일반 안건 후보(`agenda_candidate`)와 생년월이 빈 선임 상세 행에 같은 규칙을 적용한다. 기존 주체를 나중에 변경하거나 합치지 않는다.

선임 상세는 표 셀 안이 아닌 독립 제목이 `이사선임 세부내역`, `사외이사선임 세부내역`, `감사선임 세부내역`, `감사위원선임 세부내역` 중 하나와 정확히 일치하고 뒤 표의 머리글이 유효할 때만 읽는다. 정정 비교 표 안의 목차 문자열은 제목으로 인정하지 않는다. 성명이 비었거나 `-`, `성명`, `미정`, `미확정`, `후보자 미정`, `선임예정`, `해당사항 없음`이면 사람을 만들지 않는다. 후보자 표면 앞의 명시적 직책과 `선임의 건` 같은 행위 문구는 이름에서 분리하고, 직책·위원회 문장만 남으면 사람을 만들지 않는다. `외 N인`의 N명이나 이름 없는 역할도 추정하지 않는다. 유효한 영문 성명은 길이와 관계없이 유지한다.

## 주요 경력과 다른 법인

`other_company`는 다른 법인명과 직위가 명시된 원본으로 우선 사용한다. `major_career`는 `<br>`로 구분한 한 줄 전체에 현재 표식, 기관 표지, 지원하는 직책이 모두 있을 때만 `serves_at` 관계로 만들고 근거 필드는 `주요경력(현직포함)`으로 기록한다. 과거 경력, 학교·학과, 일반 전문직 설명, 여러 기관이 섞여 대상을 하나로 정할 수 없는 줄은 제외한다.

같은 셀에서 기관명과 직책이 줄바꿈된 경우에는 `기관명 줄 + 바로 다음 완전한 직위 줄` 전체가 명시 문법에 맞아야 한다. `사내\n이사`, `부\n회장`처럼 직책 단어가 중간에서 갈린 표면은 기관명과 직책의 조합으로 보지 않는다. 원문 기관명이 전달받은 보고회사명과 정확히 같을 때만 `@reporting_company`로 연결하며, 회사명을 모를 때 부서명이나 다른 메타데이터로 보완하지 않는다.

## 외부감사인

첫 번째로 확인한 `기타 투자판단에 참고할 사항`의 값 행에 회계법인 이름과 선임·변경 행위가 함께 있을 때만 외부감사인을 추출한다. 이름 없는 선임보고에서는 기관을 추정하지 않고, 기관명의 오탈자나 약칭도 임의로 고치지 않는다. 현재 감사기관과 변경 전 감사기관은 각각 `current`, `former`로 구분한다. 선택한 값이 비거나 해석되지 않아도 뒤의 같은 제목으로 바꾸지 않는다.

## 해임·사임과 그래프 수명주기

직책과 이름이 직접 붙은 해임·사임 안건만 종료 대상으로 삼는다. 상위 안건의 직책을 역할이 없는 하위 안건에 물려주지 않는다. `ROLE + 한국어 3음절 이름 + 의 + 해임·사임` 또는 영문·띄어쓴 이름의 명시 문법 밖에서는 이름 끝의 `의`를 목록 조회나 길이로 보정하지 않는다.

그래프에서는 결과공고, 가결, 유효한 회의일이 모두 있는 종료 관계만 사용한다. 같은 회사, 같은 사람 식별자, 같은 직책에 해당하는 더 이른 선임 관계가 정확히 맞을 때만 재직을 끝낸다. 이름만 같거나 직책이 다르거나, 동일일·미래의 선임 또는 구형 임원 관계에는 다시 연결하지 않는다.

## 거래 주체

현재 참고사항의 값 행, 선택된 안건, 이미 파싱한 사업목적 변경 이유에서 이름과 거래 행위가 직접 연결된 경우에만 주주, 양도·양수인, 제3자배정 대상, 합병·인수·양도 대상을 만든다. RESULT의 인수·양도 대상 관계에는 안건 상태를 보존하고, `최대주주인 NAME`은 `maximum=true`인 현재 주주 관계로도 나타낸다. 이름 없는 역할, 관련공시 링크, 일반적인 인수합병 설명은 주체의 원본으로 사용하지 않는다.

합병은 방향을 확정할 수 있는 문장만 처리한다. 법인 표지가 붙은 단일 상대방, 명시적인 피합병·소멸 법인, 법인 표지가 붙은 흡수합병 대상, 보고회사가 정확히 한쪽인 두 당사자 문장이 여기에 해당한다. 취소·철회·중단·무산·백지화·폐기 문장은 관계로 만들지 않는다.

## 사업목적 변경

표 셀 안이 아닌 `사업목적 변경 세부내역` 제목 뒤의 유효한 표 하나를 사용한다. `구분`이 비었거나 `내용`이 `변경전` 또는 `내용`인 머리글 행은 제외한다. `구분=사업목적 변경`이면 `내용`과 `내용_1`을 `before`와 `after`로 저장하고, 나머지는 `content`로 저장한다. 근거는 선택한 표의 행과 `이유` 필드를 가리킨다.

합병 상대방은 같은 `이유` 필드에서 이름과 합병 방향이 함께 명시될 때만 `merger_target_of`로 만든다. 법인 표지가 붙은 흡수합병 대상, 조사 `와`·`과`·`와의`·`과의`로 연결된 소규모·간이합병 상대, `합병 예정` 법인, `종속회사(NAME) 흡수합병`, `합병 후 소멸법인 NAME`, `합병완료된 (구)NAME`, 피합병 법인처럼 방향을 확정할 수 있는 문법만 허용한다. 복수 피합병회사는 괄호 안 전체가 법인 표지를 가진 이름 목록일 때만 나눈다. 두 당사자가 함께 나오면 사업목적을 넘겨받은 당사자가 문장 뒤에 정확히 반복될 때만 반대편을 대상으로 정한다. 날짜와 `소규모`·`간이` 같은 수식어, 관계기업·사업부 같은 역할명, 이름 없는 `계열회사 흡수합병`은 기관명으로 사용하지 않는다.

## 그래프 입력 계약

그래프는 현재 `agenda_records`, `entities`, `relationships` 배열만 사용한다. 구형 `agendas`, `elections`, 파싱된 메타데이터나 원문을 다시 해석해 빈자리를 메우지 않는다.

주주총회 노드를 만들려면 필터링된 레코드의 `company_id`, `company_name`, `disclosed_date`, `title`, 같은 접수번호의 파싱 결과, 유효한 `meeting_date`가 모두 필요하다. 이를 `company_key`, `submitter`, `disclosed_at`, 파싱된 제목·원본, 공시일로 대체하지 않는다. 예약 참조값 충돌, 중복 참조값, 관계 끝점 유형 불일치, 비어 있는 원문 근거가 있는 그래프 관계는 제외한다.
