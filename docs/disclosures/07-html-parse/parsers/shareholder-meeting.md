# 주주총회 공시 변환

- 사례 HTML: [`examples-2026-08-14.html`](./examples-2026-08-14.html)

`shareholder-meeting` parser는 주주총회 공시의 안건, 사람·기관과 관계를 결정론적으로 추출하며 실행 중 LLM이나 외부 모델을 호출하지 않는다. 후보자를 현직 임원으로 보거나 이름 없는 주체를 추정하지 않고, 파싱 실패를 다른 필드·문서 구조·metadata로 보완하지 않는다. 모호한 문장의 추출률보다 잘못된 관계를 만들지 않는 데 우선순위를 둔다.

## 추출 범위

### 추출하는 정보

| 항목 | 처리 방식 |
| --- | --- |
| 안건 | 열 구조가 분명한 구조화 안건(structured agenda)과 라벨 옆 셀을 읽는 구형 안건(legacy agenda)을 처리한다. |
| 임원 후보와 선임 결과 | 이사·사외이사·감사·감사위원 후보를 찾는다. 결과공고(RESULT)에서 가결된 경우에만 실제 선임 관계를 만든다. |
| 해임·사임 | 대상자와 직책을 기록하고, 가결된 결과는 그래프의 임원 재직 기간에도 반영한다. |
| 다른 회사의 현직 | 후보자의 주요 경력에서 현재 다른 법인과 직책이 명확할 때 재직 관계를 만든다. |
| 외부감사인 | 현재 감사기관과 변경 전 감사기관을 구분한다. |
| 주식 거래 당사자 | 주주, 주식 양도인·양수인, 제3자배정 대상자를 역할별로 구분한다. |
| 기업 거래 대상 | 합병·인수·양도의 상대 회사가 원문에 명시된 경우에만 연결한다. |
| 근거와 참조 | 문서 안에서만 유효한 주체, 참조값, 원문 근거를 보존하고 그래프 연결 대상의 유형을 검사한다. |

### 추출하지 않는 정보

다음 주체와 관계는 생성하지 않는다.

- 안건 중 **주주제안자**: 안건은 남기되 주체나 관계를 남기지 않는다.
- 안건 중 **주식매수선택권 대상자**: 안건은 남기되 주체나 관계를 남기지 않는다.
- 투표 중 **전자투표 관리기관** 및 **시스템 제공기관**: 주체나 관계를 남기지 않는다.

### 입출력과 필드 계약

`parse_shareholder_meeting()`은 `<data_root>/06-sections/shareholder_meeting/<YYYY>/<acpt_no>.html`을 입력으로 받아 공통 레코드에 `shareholder_meeting` 업무값을 추가하고, `<data_root>/07-converted/shareholder_meeting/parsed-shareholder_meeting.json`에 결과를 저장한다. 외부·내부 HTML 쌍을 받는 공개 파서는 외부 공시 제목을 호출 경계에서 `NOTICE` 또는 `RESULT`로 정규화하고, 지원하지 않는 제목은 `ValueError`로 거부한다. 내부 HTML 상세 파서를 직접 호출하면서 모드를 생략하거나 잘못 지정하면 `disclosure_phase=unknown`으로 유지한다. 문서 구조나 다른 메타데이터로 단계를 보완하지 않는다.

필터 레코드의 `company_name`은 파싱 전에 `reporting_company_name`으로 전달한다. 이 값은 명시적 현직 기관을 `@reporting_company`로 연결하거나 두 합병 당사자의 방향을 판정할 때만 쓴다. HTML의 누락 필드를 대신 채우는 값은 아니다.

| 필드 | 계약 |
| --- | --- |
| `disclosure_phase` | `notice`, `result`, `unknown` 중 하나 |
| `meeting_date` | 단계별 정규 날짜 라벨이 붙은 첫 직접 행에서 읽은 `YYYY-MM-DD`; 선택한 값이 잘못돼도 다른 행이나 공시일로 바꾸지 않고 `null`로 둠 |
| `agendas`, `agenda_items` | 같은 안건 제목 문자열 배열 |
| `agenda_records` | `agenda_ref`, `number`, `title`, `resolution_type`, `candidate`, `result_raw`, `status`, `remarks`, `source`, `attributes`, `evidence`를 가진 안건 배열 |
| 역할별 선임 목록 | `director_elections`, `outside_director_elections`, `auditor_elections`, `audit_committee_elections` |
| `elections` | 위 역할별 선임 목록을 적힌 순서대로 합친 배열 |
| `entities` | `entity_ref`, `entity_type`, `name`, `attributes`, `mentions`를 가진 문서 단위 주체 배열 |
| `relationships` | `source_ref`, `target_ref`, `relationship_type`, `attributes`, `evidence`를 가진 관계 배열 |
| `business_purpose_changes` | `category`, `reason`, `evidence`와 `before`·`after` 또는 `content`를 가진 배열 |

목록 필드는 값이 없을 때도 빈 목록으로 만든다. 회의 시각·장소, 기준일, 주주명부 폐쇄기간은 별도 출력 필드가 아니다. `agenda_ref`는 행 순번을 기준으로 문서 안에서 유일하며 같은 의안 번호가 반복돼도 겹치지 않는다. 안건 상태는 원문 결과와 비고가 명시한 경우에만 `passed`, `rejected`, `unresolved`, `withdrawn`, `not_tabled` 중 하나로 정규화한다. 제목에 `승인의 건`이 있어도 가결로 추론하지 않는다. 결과 표의 가결 여부, 찬성·반대·기권률과 비고는 원문에 있을 때 함께 읽되, 표결 수치는 원문 머리글과 값을 `attributes`에 보존할 뿐 통합 수치 스키마로 바꾸지 않는다. 안건도 전역 분류 체계로 추정하지 않는다.

선임 항목은 원래 표 값과 `section_title`, `section_type`, `name`, `birth_month`, `term`, `is_new`, `is_full_time`, `major_career`, `other_company`, 출처 근거를 가진다. `section_type`은 `director`, `outside_director`, `auditor`, `audit_committee_member` 중 하나다. 감사위원 표의 `사외이사여부`는 감사위원 역할 속성으로 유지하며, 같은 사람이 사외이사와 감사위원 표에 함께 나오면 한 문서 단위 사람에 두 역할을 연결할 수 있다. `major_career_lines`와 `other_company_lines`에는 원문의 `<br>` 경계를 보존한다.

`entity_type`은 원문 문맥으로 정한 `person` 또는 `organization`이다. `@reporting_company`와 `@meeting`은 09단계에서 실제 노드로 해석할 예약 참조이며, 안건 관계는 `agenda_records[].agenda_ref`를 쓴다. 07단계의 `entity_ref`는 해당 공시 안에서만 유효하다. 다른 공시와의 동일인·동일 기관 확정은 09단계의 보수적인 주체 해소 범위다. `evidence`와 `mentions`에는 원문을 다시 찾을 수 있도록 `section_title`, `table_index`, `row_index`, `field`, `raw_text`를 기록한다.

## 관계 계약

`relationships`는 다음 15개 관계를 사용한다.

| 관계 | 의미 |
| --- | --- |
| `includes` | 주주총회가 안건을 포함함 |
| `candidate_for` | 사람이 임원 후보로 올라감 |
| `elected_as` | 가결 결과에 따라 임원으로 선임됨 |
| `removed_from` | 가결 결과에 따라 직책에서 해임됨 |
| `resigned_from` | 가결 결과에 따라 직책에서 사임함 |
| `subject_of` | 사람이나 기관이 특정 안건의 대상임 |
| `serves_at` | 사람이 다른 회사에서 현재 근무함 |
| `external_auditor_of` | 회계법인이 보고회사의 외부감사인임 |
| `shareholder_of` | 사람이나 기관이 보고회사의 주주임 |
| `transferor_of` | 사람이나 기관이 주식 양도인임 |
| `transferee_of` | 사람이나 기관이 주식 양수인임 |
| `proposed_allottee_of` | 사람이나 기관이 제3자배정 대상임 |
| `merger_target_of` | 기관이 합병 대상임 |
| `acquisition_target_of` | 기관이 인수 안건의 대상임 |
| `divestment_target_of` | 기관이 양도 안건의 대상임 |

모든 관계에는 허용된 출발점과 도착점 유형, 문서 안에서만 유효한 참조값, 비어 있지 않은 원문 근거가 있어야 한다. 후보와 현재 임원은 구분한다. `elected_as`, `removed_from`, `resigned_from`은 결과공고에 `passed`가 명시된 경우에만 만든다.

임원 역할은 관계의 `attributes.office_type`에 `director`, `outside_director`, `auditor`, `audit_committee_member` 중 하나로 저장한다. 종료 관계는 사람에서 `@reporting_company` 방향이며 `disclosure_phase=result`, `outcome=passed`를 함께 기록한다. `external_auditor_of`도 회계법인에서 `@reporting_company` 방향이고 `attributes.state`는 `current` 또는 `former`다. `shareholder_of`, `transferor_of`, `transferee_of`, `proposed_allottee_of`, `merger_target_of`는 명시된 사람이나 기관에서 `@reporting_company`로 향한다. `acquisition_target_of`와 `divestment_target_of`는 명시된 기관에서 해당 `agenda_ref`로 향한다.

## 구현 원칙

### 안건과 두 개의 허용 대체 경로

기본 원본은 첫 번째로 확인된 구조화 안건 표 하나다. 표를 선택할 때 제목 열도 함께 고정한다. 행 값이 비어 있거나 형식이 맞지 않아도 다른 열, 후손 셀, 인접 셀, 뒤의 표로 바꾸거나 여러 표를 합치지 않는다.

실패 뒤 다른 원본을 찾는 대체 경로(fallback)는 두 개만 허용한다.

1. 문서에 구조화 안건 스키마가 아예 없을 때만, 정확한 라벨과 같은 행에 있는 두 개의 직접 자식 셀을 읽는다.
2. 이름으로 선임 상세와 안건을 연결한 결과가 0건이고, 같은 직책의 선임 상세와 이름 없는 호환 안건이 각각 한 건뿐일 때만 둘을 연결한다.

구조화 안건 표는 첫 머리글에 `번호`와 `회의목적사항`이 있는 표다. 표의 직접 행과 각 행의 직접 셀만 사용하므로 바깥 layout 표가 안쪽 안건 표의 머리글을 자기 값처럼 가져가지 않는다. 평면 표는 `회의목적사항`을 제목 열로 고정한다. 그룹 머리글은 둘째 줄에 `안건` 열이 명시된 경우에만 그 열을 사용한다. 구형 안건은 첫 직접 자식 셀의 번호와 공백을 정규화한 값이 `결의사항`, `기타 결의사항`, `의안 주요내용` 중 하나와 정확히 일치할 때 둘째 직접 자식 셀을 읽고, `<br>`과 안건 번호·표식으로 레코드를 나눈다. 정정 전후 비교 표와 `-` 같은 자리표시자는 안건으로 사용하지 않는다.

주식 양도, 외부감사인, 사업목적 합병처럼 표현이 여러 개인 항목은 첫 문법이 실패한 뒤 다른 문법을 시도하지 않는다. 같은 기준 원본에서 가능한 후보를 독립적으로 모은 뒤 중복을 제거한다.

### 인물 식별자 사전 결정

사람을 만들기 전에 선임 상세 행에서 같은 인물 키에 연결된 생년월을 모아 식별자를 정한다.

- 생년월이 없으면 생년월 없는 식별자를 사용한다.
- 생년월이 하나면 그 값을 가진 식별자를 사용한다.
- 서로 다른 생년월이 둘 이상이면 동명이인일 수 있으므로 생년월이 없는 안건이나 선임 표면을 어느 한 사람에게 연결하지 않는다.
- 선임 상세 행에 생년월이 적혀 있으면 원문 값을 그대로 유지한다.

선임 대상, 일반 안건 후보(`agenda_candidate`)와 생년월이 빈 선임 상세 행에 같은 규칙을 적용한다. 기존 주체를 나중에 변경하거나 합치지 않는다.

선임 상세는 표 셀 안이 아닌 독립 제목이 `이사선임 세부내역`, `사외이사선임 세부내역`, `감사선임 세부내역`, `감사위원선임 세부내역` 중 하나와 정확히 일치하고 뒤 표의 머리글이 유효할 때만 읽는다. 정정 비교 표 안의 목차 문자열은 제목으로 인정하지 않는다. 성명이 비었거나 `-`, `성명`, `미정`, `미확정`, `후보자 미정`, `선임예정`, `해당사항 없음`이면 사람을 만들지 않는다. 후보자 표면 앞의 명시적 직책과 `선임의 건` 같은 행위 문구는 이름에서 분리하고, 직책·위원회 문장만 남으면 사람을 만들지 않는다. `외 N인`의 N명이나 이름 없는 역할도 추정하지 않는다. 유효한 영문 성명은 길이와 관계없이 유지한다.

### 주요 경력과 다른 법인

`other_company`는 다른 법인명과 직위가 명시된 원본으로 우선 사용한다. `major_career`는 `<br>`로 구분한 한 줄 전체에 현재 표식, 기관 표지, 지원하는 직책이 모두 있을 때만 `serves_at` 관계로 만들고 근거 필드는 `주요경력(현직포함)`으로 기록한다. 과거 경력, 학교·학과, 일반 전문직 설명, 여러 기관이 섞여 대상을 하나로 정할 수 없는 줄은 제외한다.

같은 셀에서 기관명과 직책이 줄바꿈된 경우에는 `기관명 줄 + 바로 다음 완전한 직위 줄` 전체가 명시 문법에 맞아야 한다. `사내\n이사`, `부\n회장`처럼 직책 단어가 중간에서 갈린 표면은 기관명과 직책의 조합으로 보지 않는다. 원문 기관명이 전달받은 보고회사명과 정확히 같을 때만 `@reporting_company`로 연결하며, 회사명을 모를 때 부서명이나 다른 메타데이터로 보완하지 않는다.

### 외부감사인

첫 번째로 확인한 `기타 투자판단에 참고할 사항`의 값 행에 회계법인 이름과 선임·변경 행위가 함께 있을 때만 외부감사인을 추출한다. 이름 없는 선임보고에서는 기관을 추정하지 않고, 기관명의 오탈자나 약칭도 임의로 고치지 않는다. 현재 감사기관과 변경 전 감사기관은 각각 `current`, `former`로 구분한다. 선택한 값이 비거나 해석되지 않아도 뒤의 같은 제목으로 바꾸지 않는다.

### 해임·사임과 그래프 수명주기

직책과 이름이 직접 붙은 해임·사임 안건만 종료 대상으로 삼는다. 상위 안건의 직책을 역할이 없는 하위 안건에 물려주지 않는다. `ROLE + 한국어 3음절 이름 + 의 + 해임·사임` 또는 영문·띄어쓴 이름의 명시 문법 밖에서는 이름 끝의 `의`를 목록 조회나 길이로 보정하지 않는다.

그래프에서는 결과공고, 가결, 유효한 회의일이 모두 있는 종료 관계만 사용한다. 같은 회사, 같은 사람 식별자, 같은 직책에 해당하는 더 이른 선임 관계가 정확히 맞을 때만 재직을 끝낸다. 이름만 같거나 직책이 다르거나, 동일일·미래의 선임 또는 구형 임원 관계에는 다시 연결하지 않는다.

### 거래 주체

현재 참고사항의 값 행, 선택된 안건, 이미 파싱한 사업목적 변경 이유에서 이름과 거래 행위가 직접 연결된 경우에만 주주, 양도·양수인, 제3자배정 대상, 합병·인수·양도 대상을 만든다. RESULT의 인수·양도 대상 관계에는 안건 상태를 보존하고, `최대주주인 NAME`은 `maximum=true`인 현재 주주 관계로도 나타낸다. 이름 없는 역할, 관련공시 링크, 일반적인 인수합병 설명은 주체의 원본으로 사용하지 않는다.

합병은 방향을 확정할 수 있는 문장만 처리한다. 법인 표지가 붙은 단일 상대방, 명시적인 피합병·소멸 법인, 법인 표지가 붙은 흡수합병 대상, 보고회사가 정확히 한쪽인 두 당사자 문장이 여기에 해당한다. 취소·철회·중단·무산·백지화·폐기 문장은 관계로 만들지 않는다.

### 사업목적 변경

표 셀 안이 아닌 `사업목적 변경 세부내역` 제목 뒤의 유효한 표 하나를 사용한다. `구분`이 비었거나 `내용`이 `변경전` 또는 `내용`인 머리글 행은 제외한다. `구분=사업목적 변경`이면 `내용`과 `내용_1`을 `before`와 `after`로 저장하고, 나머지는 `content`로 저장한다. 근거는 선택한 표의 행과 `이유` 필드를 가리킨다.

합병 상대방은 같은 `이유` 필드에서 이름과 합병 방향이 함께 명시될 때만 `merger_target_of`로 만든다. 법인 표지가 붙은 흡수합병 대상, 조사 `와`·`과`·`와의`·`과의`로 연결된 소규모·간이합병 상대, `합병 예정` 법인, `종속회사(NAME) 흡수합병`, `합병 후 소멸법인 NAME`, `합병완료된 (구)NAME`, 피합병 법인처럼 방향을 확정할 수 있는 문법만 허용한다. 복수 피합병회사는 괄호 안 전체가 법인 표지를 가진 이름 목록일 때만 나눈다. 두 당사자가 함께 나오면 사업목적을 넘겨받은 당사자가 문장 뒤에 정확히 반복될 때만 반대편을 대상으로 정한다. 날짜와 `소규모`·`간이` 같은 수식어, 관계기업·사업부 같은 역할명, 이름 없는 `계열회사 흡수합병`은 기관명으로 사용하지 않는다.

### 그래프 입력 계약

그래프는 현재 `agenda_records`, `entities`, `relationships` 배열만 사용한다. 구형 `agendas`, `elections`, 파싱된 메타데이터나 원문을 다시 해석해 빈자리를 메우지 않는다.

주주총회 노드를 만들려면 필터링된 레코드의 `company_id`, `company_name`, `disclosed_date`, `title`, 같은 접수번호의 파싱 결과, 유효한 `meeting_date`가 모두 필요하다. 이를 `company_key`, `submitter`, `disclosed_at`, 파싱된 제목·원본, 공시일로 대체하지 않는다. 예약 참조값 충돌, 중복 참조값, 관계 끝점 유형 불일치, 비어 있는 원문 근거가 있는 그래프 관계는 제외한다.

## 검증 기준

### 실제 원문 골든 자료

`tests/fixtures/shareholder_meeting/golden`에 실제 공시를 고정해 다음 자료를 관리한다.

- `manifest.json`: 원본 경로, 원문 SHA-256, 정규화 출력 SHA-256, 양성·음성 검증 조건
- `adjudication.json`: 문서별 판정 근거, 의견 차이, 최종 합의
- `adjudication_prompt.md`: 판정 기준
- `sources/`: 데이터베이스 원본과 바이트가 같은 전체 HTML

같은 입력을 두 번 파싱해 정규화한 JSON이 일치하는지 검사한다. 출력 SHA-256이 바뀌면 이전 결과와 원문 검증 조건을 비교한 뒤 목록을 갱신한다.

## 설계 근거

| 결정 | 이유 |
| --- | --- |
| 둘째 머리글은 `안건` 열이 명시된 경우에만 사용한다. | 표결 수치용 그룹 머리글을 제목 열로 오인하지 않기 위해서다. |
| `재선임` 같은 행위어는 독립된 단어일 때만 제거한다. | 접두어 정규식이 실제 이름 일부를 자를 수 있다. |
| 이름 끝 `의`는 엄격한 종료 문법 안에서만 조사로 처리한다. | 이름 길이나 후보 목록을 이용한 보정은 다른 원본에 의존하고 실제 이름을 훼손할 수 있다. |
| 사람을 만들기 전에 생년월을 확정한다. | 사후 병합은 입력 순서에 따라 결과가 달라지고 동명이인을 합칠 수 있다. |
| 그래프는 파서의 누락값을 다른 필드로 채우지 않는다. | 계약 밖의 출처 없는 날짜·신원·직책이 생길 수 있다. |
| 영역별 첫 기준 원본과 물리적 줄 경계를 고정한다. | 첫 원본 실패 뒤 다른 위치를 찾으면 문서 구조에 따른 숨은 대체 경로가 생긴다. |
| 양성 문법과 오탐 경계를 함께 검사한다. | 넓은 키워드는 취소된 거래, 과거 경력, 일반 역할어를 관계로 만들 수 있다. |
| 같은 원본의 합법 문법은 독립적으로 수집한 뒤 중복을 제거한다. | `A 실패 → B 시도` 방식은 불필요한 우선순위와 대체 경로를 만든다. |
| 전수 감사는 변경되지 않는 코드 스냅숏에서 실행한다. | 시작과 종료 해시가 다르면 결과가 현재 코드의 검증 근거가 될 수 없다. |
