# 공시원문 변환 동작

기본 자료 흐름과 정상 실행 계약을 설명한다.

## 공시원문 변환

### 자료 흐름

- `/html-parse`에서 변환 유형을 선택해 parsing하거나 preview할 때 적용한다.
- 입력 HTML은 `<data_root>/06-sections/<year>/<acpt_no>.html`에서 읽으며 `<year>`는 4자리 숫자 폴더다. metadata는 `<data_root>/03-filter/<mode>/filtered.json`과 `<data_root>/04-external-html-download/<mode>/compressed-external-html.json`에서 읽는다.
- 결과는 `<data_root>/07-converted/<mode>/parsed-<mode>.json`에 저장한다. 원본 HTML은 수정하지 않는다.

```text
<data_root>/
├── 03-filter/<mode>/filtered.json
├── 04-external-html-download/<mode>/compressed-external-html.json
├── 06-sections/<year>/<acpt_no>.html
└── 07-converted/<mode>/parsed-<mode>.json
```

### 변환 유형

**`bond_issuance` · 사채발행파싱** — 상세 필드를 지원한다. 세부 규칙은 사채발행 변환 절에서 설명한다.

**`rights_issuance` · 유무상증자파싱** — 상세 필드를 지원한다. 공통 규칙과 유상·무상·혼합 결과는 유무상증자 변환 절에서 설명한다.

**`shareholder_meeting` · 주주총회파싱** — 원본 표 구조와 안건·선임·사업목적 변경 결과를 만든다. 세부 규칙은 주주총회 변환 절에서 설명한다.

**`asset_transaction` · 유무형자산거래파싱** — 공통 record와 원본 표 구조만 만든다.

**`security_transaction` · 발행증권거래파싱** — 공통 record와 원본 표 구조만 만든다.

마지막 두 유형은 별도 schema가 없는 변환 절에서 공통 계약을 설명한다. 함수별 책임은 공시원문 변환 함수 절에서 확인한다.

### 처리 계약

#### 정상 동작

##### 연도별 parser 입력 수집

한 실행에서 읽을 HTML 범위를 강제된 저장 구조로 고정한다.
- `<data_root>/06-sections` 바로 아래에 있는 4자리 연도 폴더만 확인한다.
- `<data_root>/06-sections/<year>` 바로 아래의 `*.html`만 읽고 입력 루트, 이름이 다른 폴더, 더 깊은 하위 HTML은 제외한다.

##### 공통 HTML 입력 변환

모든 mode가 같은 문자와 표 구조를 입력으로 사용하게 한다.
- HTML을 UTF-8로 읽고 병합된 표를 펼친다.
- 병합 셀을 펼친 `positional_rows`는 열 위치를 보존한다. parser가 라벨을 찾는 `logical_rows`는 빈 칸과 같은 글이 연속된 칸을 제거하고 그 결과가 빈 행도 제외한다.

##### 공통 parser 실행

변환한 HTML 입력에서 선택한 mode에 맞는 업무값을 추출한다.
- 선택한 mode parser를 실행하고 공통 식별값, 값별 상태와 warning 규칙을 모든 mode에 동일하게 적용한다.
- 메인 함수와 보조 함수가 맡는 역할은 공시원문 변환 함수에서 설명한다.

##### 외부 metadata·family 연결

parser 결과에 붙일 외부값과 correction family를 어디서 읽는지 고정한다.
- metadata는 mode별 `filtered.json`과 `compressed-external-html.json`에서 읽는다.
- title·회사명·시장·공시시각·본문 문서번호를 정해진 출처에서 연결하고 완성된 family만 저장한다.

##### 최종 결과 구성·저장

record·family·warning·error와 실행 집계를 JSON 한 파일에 저장한다.
- parser 결과에서 `raw_tables`를 제거한 뒤 metadata·family와 warning을 연결하고 필터를 적용한다.
- 최종 JSON에는 실행 mode와 입력 경로, 필터 조건, 집계, family, record, warning과 error를 기록한다.
- `raw_tables`는 parser를 직접 분석할 때만 쓰며 저장 record에서는 제거한다. `raw_rows`는 만들지 않는다.
- `acpt_no`와 metadata 연결 key에는 `Path(file_path).stem` 전체를 사용한다. 밑줄을 기준으로 자르거나 숫자인지 검사해 다른 값으로 바꾸지 않는다.
- 저장 record에는 parser가 반환한 `title`, `acpt_no`, `상장구분`, 유형별 값이 남는다. metadata에 값이 있으면 `doc_no`, `disclosed_at`을 연결하고 완성한 family에는 `family_id`, `current_sequence`, `family_member_count`를 기록한다.
- 외부 title은 함수 선언에 `title` 인자가 있는 parser에만 전달한다. 저장 record가 참조하는 family 본문은 최상위 `families`에 한 번만 모은다.
- `bond_issuance`와 `rights_issuance`는 metadata에 회사명이 있을 때 `corp_name`도 저장한다.
- parser와 Web workflow는 `rcept_no`, `source_file`, 빈 `correction_families`를 만들지 않는다.
- 입력 루트는 최상위 `input_directory`에 한 번만 기록한다. record·warning·error·preview에는 파일 경로나 파일명을 넣지 않고 `acpt_no`로 원본을 식별한다. `source_preview`도 바깥 record에 있는 `acpt_no`를 반복하지 않는다.

##### warning 구조 일관성 확인

parser가 만든 warning 수준과 집계가 서로 일치하는지 최종 payload를 구성하기 전에 확인한다.
- 같은 warning 목록에 중복·빈 문장·수준 누락·복수 수준 지정이 없는지 확인한다.
- `parse_warnings`와 수준별 목록이 일치하는지 확인한다.

### 화면과 서비스 계약

#### 정상 동작

##### Preview

저장하기 전에 원문과 변환 결과를 확인한다.
- preview는 변환 결과와 원문 표 일부를 함께 보여 준다. 원본과 저장 결과는 바꾸지 않는다.
- 표가 길면 앞부분과 생략한 행 수만 보여 준다. 기본 건수는 [공통 동작 문서](../common/behavior.md)를 따른다.
- 표 제목은 원문 제목, 변환 결과 제목, 빈 값 순서로 선택한다.

##### 필터 후보

결과를 거를 때 사용할 값과 공시를 미리 확인한다.
- 선택한 항목은 모든 입력에서 값별 개수와 접수번호 예시를 계산한다.
- 접수번호 예시를 줄여 보여 주지만 전체 개수는 모두 계산한다. 예시 범위는 [공통 동작 문서](../common/behavior.md)를 따른다.
- 후보는 화면에서 이어서 쓸 필터 입력일 뿐, 저장한 변환 결과는 바꾸지 않는다.

##### 변환 오류 표시 범위 제한

변환 실패 결과를 바꾸지 않고 화면에 전달할 예시 범위만 제한한다.
- 공시 시각 오류 예시는 [공통 동작 문서](../common/behavior.md)를 따른다.

## 공시원문 변환 함수

### 자료 흐름

- Web workflow 진입점은 `features/disclosures/html_parse_common.py`이며 `PARSER_REGISTRY`에서 선택한 mode parser를 찾는다.
- 메인 함수는 변환 실행, preview, 필터 후보 생성과 저장 결과 조회를 담당한다.
- 보조 함수는 HTML·표 해석, metadata·family 연결, warning과 최종 payload 구성을 담당한다.
- 단계 입출력과 공통 중단 규칙은 공시원문 변환, mode별 업무값은 아래 mode 절을 따른다.

### 처리 계약

#### 정상 동작

##### 변환 실행 입력 준비

메인 함수가 처리할 HTML 범위와 mode parser를 확정한다.
- `parse_disclosure_html_payload()`는 입력값을 검증하고 mode parser를 선택한다.
- 입력은 `input_directory/<year>/<acpt_no>.html`만 사용하며 `<year>`는 4자리 숫자 폴더다.

##### HTML·표 입력 변환 보조 함수

모든 mode가 같은 문자와 표 구조를 사용하게 한다.
- byte 입력은 UTF-8로 읽고 복구 가능한 HTML DOM으로 만든다.
- 표에서 `rowspan`과 `colspan`을 펼쳐 원래 위치와 실제 검색 위치를 함께 보존한다.

##### metadata 입력 보조 함수

외부 정보와 correction family를 만들 때 어떤 입력을 쓰는지 고정한다.
- metadata는 지정된 `filtered.json`과 `compressed-external-html.json`에서만 읽는다.
- 파일명 stem을 연결 key로 사용해 metadata index를 만든다.

##### 변환 실행 메인 함수

확정한 HTML 전체를 같은 조건으로 변환해 결과 하나로 저장한다.
- `parse_disclosure_html_payload()`는 HTML을 순서대로 처리한다.
- parser 결과에 metadata와 family를 연결하고 warning·error·집계를 포함한 JSON을 저장한다.

##### mode parser 메인 함수

공시 유형별 업무값을 공통 record에 추가한다.
- `parse_bond_issuance()`, `parse_rights_issuance()`, `parse_shareholder_meeting()`, `parse_asset_transaction()`, `parse_security_transaction()` 중 선택한 mode에 맞는 함수만 실행한다.
- 각 함수는 공통 식별값과 표 구조에 mode별 값을 추가하며 상세 추출 규칙은 해당 mode 절을 따른다.
- parser가 직접 반환한 결과에서 `raw_tables`는 최종 JSON을 저장하기 전에 제거한다.

##### 값 추출 공통 보조 함수

입력 표에서 결과 field를 찾고 변환할 때 같은 규칙을 사용한다.
- 행 이름 검색, 공백 정리와 숫자 변환은 공통 규칙을 사용한다.

##### metadata·family 연결 보조 함수

정해진 외부값과 완성된 correction family만 parser 결과에 연결한다.
- title·회사명·시장·공시시각·본문 문서번호를 정해진 metadata 출처에서 연결한다.
- correction family를 완성한 경우에만 record에 family 참조를 추가하고 family 본문을 최상위에 저장한다.

##### warning 보조 함수

확인이 필요한 문제를 일관된 구조로 검증하고 집계한다.
- parser warning에서 수준과 code를 검증한 뒤 공시별·수준별 건수를 집계한다.

##### payload 보조 함수

검증된 변환 결과를 최종 저장 구조로 구성한다.
- 성공 record, family, warning, error, 필터 조건과 실행 집계를 최종 payload로 구성한다.
- 저장 결과에서 제외한 성공 record warning도 최상위 warning 집계에는 남긴다.

### 화면과 서비스 계약

#### 정상 동작

##### 변환 취소 메인 함수

실행 중인 변환을 취소한다.
- `cancel_disclosure_html_parse()`가 취소 요청을 전달한다.

##### 조회 메인 함수

저장 전후 결과를 화면이나 파일로 확인한다.
- `build_parse_preview_payload()`는 변환 결과와 원문 표 미리보기를 만든다.
- `build_parse_filter_candidates_payload()`는 값별 개수와 접수번호 예시를 만든다.
- 다른 조회 함수는 사채 요약, 정정 내역과 Excel 결과를 만든다.

## 사채발행 변환

### 자료 흐름

- HTML·metadata·상태·warning·최종 payload 공통 계약은 공시원문 변환을 따른다.
- 사채발행 parser가 추가하는 업무값과 mode별 검증만 설명한다.

### 처리 계약

#### 정상 동작

##### 고정 셀 위치 추출

원문 표에서 field를 같은 순서로 찾고 읽는다.
- 라벨은 해당 칸 앞 번호와 공백을 제거한 뒤 검사한다.
- 메인 표 field는 병합 셀에서 연속한 중복을 압축한 `logical_rows`를 기준으로 `N`을 정한다.
- field마다 왼쪽에서부터 셀 위치 `N`을 고정하고 그 위치에서만 라벨을 확인한다.
- 행을 찾은 뒤 값은 맨 오른쪽 셀에서 읽는다.
- 첫 일치 행을 찾으면 맨 오른쪽 셀이 비어 있거나 값을 변환할 수 없어도 다른 이름이나 뒤 행으로 바꾸지 않는다.
- 한 행에 여러 업무값이 있거나 값 열이 양식마다 달라 이 순서를 적용할 수 없는 field는 해당 기능에 예외를 명시한다.

##### 사채 조건 표 선택

사채 조건을 정해진 첫 표에서만 읽는다.
- `사채의 종류`, `사채의 권면`, `자금조달의 목적`을 모두 가진 첫 표를 사용한다.
- 후보 확인과 메인 표 field 추출은 `logical_rows`를 사용한다.

##### 사채 투자자 표 선택

표 한 곳에서 투자자명 열과 발행금액 열을 확정한다.
- 첫 줄에서 서로 다른 열에 `발행 대상자명`과 `발행권면`이 있는 첫 표를 사용한다.

##### 사채 종류 추출

사채 유형을 외부 제목에서 읽는다.
- `종류`는 외부 `title`에서 CB → EB → BW 순서로 확인하며 정확히 하나만 맞을 때 저장한다.
- `종류`는 표에서 읽지 않으므로 공통 값 위치 규칙을 따르지 않는다.
- 행사대상·행사가액·행사기간도 CB·EB·BW마다 대칭인 이름 순서를 유지한다.

##### 사채 회차 추출

사채 회차를 고정된 표 위치에서 읽는다.
- `회차`는 N=2가 정확히 `회차`인 첫 줄의 N=3 값을 사용한다.
- `회차` 값은 맨 오른쪽에 있지 않으므로 공통 값 위치 규칙을 따르지 않는다.

##### 발행금액 추출

권면총액을 첫 선택 위치에서 읽는다.
- 일반 양식은 N=1이 `사채의 권면`으로 시작하는 첫 줄의 맨 오른쪽 값을 사용한다.
- 외화·원화가 나뉜 해외사채 양식은 N=2가 정확히 `원화기준 (원)`인 줄의 맨 오른쪽 값을 사용한다.
- 두 양식은 라벨 위치가 달라 각 고정 위치를 사용한다. 선택한 줄 맨 오른쪽 값에서 숫자를 읽지 못해도 다른 줄로 바꾸지 않는다.

##### 만기일 추출

사채 만기일을 정해진 이름에서 읽는다.
- N=1이 정확히 `사채만기일` → `사채만기`인 첫 줄의 맨 오른쪽 값을 사용한다.

##### 행사대상 추출

CB·EB·BW 행사대상 기업이나 유가증권을 같은 규칙으로 읽는다.
- `전환대상`, `교환대상`, `인수권행사대상`, `전환에 따라`, `교환에 따라`, `인수권행사에 따라`, `전환으로 발행할`, `교환으로 발행할`, `인수권행사로 발행할`, `신주인수권행사에 따라` 순서로 확인한다.
- N=2가 해당 이름으로 시작하는 첫 줄의 맨 오른쪽 값을 사용한다.
- 먼저 찾은 이름에서 값이 비어 있어도 다음 이름 행으로 바꾸지 않는다.

##### 행사가액 추출

고정 이름 바로 오른쪽 끝 셀에서 행사 가격을 읽는다.
- N=2를 공백 제거 후 `전환가액 (원/주)`, `교환가액 (원/주)`, `행사가액 (원/주)`, `전환가격 (원/주)`, `교환가격 (원/주)`, `행사가격 (원/주)` 순서로 정확히 일치시킨다.
- 첫 일치 행의 맨 오른쪽 셀 하나만 숫자로 변환하며 변환할 수 없어도 다음 이름이나 행을 사용하지 않는다.

##### 납입일 추출

사채 납입일을 정해진 이름에서 읽는다.
- N=1이 정확히 `납입일`인 첫 줄의 맨 오른쪽 값을 사용한다.

##### 행사기간 추출

행사 시작일과 종료일을 각각 읽는다.
- N=2가 정확히 `전환청구기간`, `교환청구기간`, `권리행사기간`, `행사기간`인 순서로 찾는다.
- N=3이 정확히 `시작일`인 줄의 맨 오른쪽 값을 행사 시작일, `종료일`인 줄의 맨 오른쪽 값을 행사 종료일로 사용한다.
- 시작일과 종료일은 따로 읽으며 서로 바꿔 쓰거나 뒤에 나온 다른 기간 이름으로 보완하지 않는다.

##### 사채발행방법 추출

사채 발행 방법을 정해진 이름에서 읽는다.
- N=1이 정확히 `사채발행방법`인 첫 줄의 맨 오른쪽 값을 사용한다.

##### 발행목적 추출

자금조달 목적별 금액만 목록으로 저장한다.
- N=1이 정확히 `자금조달의 목적`인 줄만 사용한다.
- 목적명은 N=2, 금액은 맨 오른쪽 값에서 읽은 숫자를 사용한다.
- 0이나 `-`인 항목과 목적명만 있고 금액이 없는 줄은 결과에서 제외한다.
- 모든 줄에서 금액을 찾지 못하면 `발행목적` 전체를 `source_not_found`로 처리한다.
- 결과는 `[[이름, 금액], ...]` 구조다.

##### 투자자 추출

선택한 투자자 표에서 이름과 발행권면총액만 저장한다.
- 투자자명과 금액은 `positional_rows` 표 제목에서 확정한 열에서만 읽는다.
- 투자자는 column header에서 `발행 대상자명`과 `발행권면` 열을 각각 확정한 뒤 모든 데이터 줄에서 같은 열을 읽는다.
- 투자자 표에는 메인 표 field에 쓰는 고정 N 규칙을 적용하지 않는다.
- 이름이 빈 값·`-`·합계 표현이면 제외하고 금액 `-`는 0으로 남긴다.
- 첫 유효 투자자 표에 남길 줄이 없으면 `null`로 끝내며 다른 표나 열로 보완하지 않는다.
- 결과는 `[[이름, 금액], ...]` 구조다.

##### 사채 field 상태

사채 업무값을 읽은 결과를 field별로 기록한다.
- 모든 업무값에 상태를 기록하고 `발행금액`이 0이나 `-`이면 `explicit_zero`로 기록한다.
- 발행목적에 양수 항목이 있으면 `parsed`, 숫자는 있지만 남길 항목이 없으면 `explicit_zero`, 숫자가 없으면 `source_not_found`다.
- 이 parser는 medium warning을 직접 만들지 않는다.

##### 사채 합계 검증

발행목적·투자자 합계가 발행금액과 맞는지 확인한다.
- 발행목적 합계나 투자자 합계가 발행금액과 다르면 허용 오차 없이 weak warning을 만든다.
- 합계가 달라도 원본에서 읽은 값은 고치지 않는다.

## 유무상증자 변환

### 자료 흐름

- HTML·metadata·상태·warning·최종 payload의 공통 계약은 공시원문 변환을 따른다.
- 유형별 차이는 유상증자 변환, 무상증자 변환, 유무상증자 변환 절에서 설명한다.

### 처리 계약

#### 정상 동작

##### 증자유형 결정

외부 제목에서 적용할 유형별 규칙을 정한다.
- 제목의 공백을 정리한 뒤 `유무상증자` → `무상증자` → `유상증자` 순서로 확인한다.
- 확정한 유형은 결과의 `증자유형` 값이며 유형별 결과 규칙을 결정한다.

##### 증자 표 선택

핵심 수량·금액·대상자가 있는 표만 값 추출에 사용한다.
- 번호를 정규화한 한 칸 제목이 `유상증자`·`무상증자`인 표를 선택한다.
- 첫 줄에 `제3자배정 대상자`와 `배정주식수`가 있거나, 두 칸 이상인 줄의 `N=1`이 번호와 공백을 제외하고 `신주의 종류와 수`·`신주 발행가액`과 정확히 일치하는 표도 선택한다.
- 선택한 표의 `logical_rows`를 HTML 순서대로 합치며 선택하지 않은 표에서 값을 찾지 않는다.

##### 고정 N 행 탐색

설명 문장이나 다른 표의 같은 단어를 값 출처로 잘못 사용하는 일을 막는다.
- 행을 검사할 때 각 셀의 앞 번호를 제거하고 공백을 무시한다.
- 필드마다 정한 `N`번째 셀의 이름이 정확히 일치하는 첫 행만 사용하고 값은 그 행의 맨 오른쪽에서 읽는다.
- 주식 종류나 목적처럼 행을 더 구분해야 하는 필드는 정해진 다음 셀도 정확히 확인한다.
- 확인한 모든 라벨 셀보다 오른쪽에 있는 맨 끝 셀만 값으로 사용하며 값이 비어 있거나 숫자로 바꿀 수 없어도 다른 행으로 바꾸지 않는다.
- 증자유형은 외부 제목, 발행대상자는 열 헤더로 정하므로 이 행 탐색을 적용하지 않는다.

##### 공통 일정 추출

유상증자와 무상증자에서 같은 이름을 쓰는 일정값을 한 규칙으로 읽는다.
- `신주배정기준일`은 `N=1`이 같은 이름인 첫 행의 맨 오른쪽 값을 읽는다.
- `1주당 신주배정주식수`는 `N=1`이 `1주당 신주배정주식수 (주)` 또는 단위 없는 같은 이름인 첫 행의 맨 오른쪽 값을 읽는다.
- `N=2`에 주식 종류가 있으면 종류별 값을 저장하고 두 칸 양식은 보통주식 값으로 저장한다.
- `신주권교부예정일`은 `N=1`이 같은 이름인 첫 행의 맨 오른쪽 값을 읽는다.
- `상장예정일`은 공백을 뺀 `N=1`이 `신주의 상장 예정일`과 같은 첫 행의 맨 오른쪽 값을 읽는다.

다음 두 결과는 보통주식·기타주식 항목을 항상 유지한다. 첫 일치 행에서 읽은 0이나 `-`를 뒤 행에 있는 양수로 바꾸지 않는다.

##### 신주의 종류와 수 추출

발행할 보통주식과 기타주식 수량을 같은 구조로 저장한다.
- `N=1`이 `신주의 종류와 수`, `N=2`가 정해진 주식 종류인 첫 행의 맨 오른쪽 값을 읽는다.
- 보통주식은 `보통주식 (주)`·`보통주 (주)`, 기타주식은 `기타주식 (주)`·`기타주 (주)`·`우선주식 (주)`·`우선주 (주)`·`종류주식 (주)`·`종류주 (주)`를 정확한 이름으로 허용한다.

##### 증자 전 발행주식총수 추출

증자 전 보통주식과 기타주식 수량을 같은 구조로 저장한다.
- `N=1`이 `증자전 발행주식총수 (주)` 또는 `증자전 발행주식총수`, `N=2`가 정해진 주식 종류인 첫 행의 맨 오른쪽 값을 읽는다.
- 보통주식은 `보통주식`·`보통주`, 기타주식은 `기타주식`·`기타주`·`우선주식`·`우선주`·`종류주식`·`종류주`를 허용한다.

##### 발행대상자 표 추출

표에 적힌 대상자와 배정주식수를 원본 순서대로 저장한다.
- 첫 줄의 서로 다른 열 헤더에 `제3자배정 대상자`와 `배정주식수`가 있는 첫 표를 사용한다.
- 대상자나 수량이 없는 줄은 제외하고 한 수량 칸에 정수가 여러 개면 모두 더한다. 특정 단위나 기호가 붙은 숫자를 따로 제거하지 않는다.
- 대상자 합계가 신주 합계와 달라도 값을 저장하며 다음 후보 표로 바꾸지 않는다.

##### 발행대상자 특수 행 처리

대시 입력과 중복 총계 행을 실제 대상자와 구분한다.
- 모든 대상자명이 `-`이고 모든 수량을 읽을 수 없으면 `[["-", 0]]`과 `explicit_zero`를 반환한다.
- 대상자가 둘 이상이고 전체 수량이 신주 합계의 두 배이며 마지막 합계 이름·수량이 신주 합계와 맞으면 마지막 줄을 제거한다.
- 마지막 합계 이름은 `계`, `합계`, `소계`, `총계` 중 하나가 독립된 단어로 있을 때만 인정한다.

##### 발행대상자 누락 판정

제3자배정 공시의 필수 대상자 표 누락을 구분한다.
- 선택한 표에 저장할 대상자가 없으면 `null`, `source_not_found`와 strong warning을 기록한다.
- `증자방식`에 `제3자배정`이 있고 제목에 `종속회사`가 없는데 대상자 표가 없어도 같은 처리를 한다.
- 대상자 추출이 적용되지 않는 공시는 빈 목록을 반환한다.

##### 종류별 상태

수량과 가액의 전체 상태와 종류별 상태를 함께 기록한다.
- `신주의 종류와 수`, `증자 전 발행주식총수`, `발행가액`에 전체·종류별 상태를 만든다.
- 하나라도 양수이면 `parsed`, 양수 없이 0이나 `-`가 있으면 `explicit_zero`, 원본이 모두 없으면 `source_not_found`다.
- 종류별 원본 누락과 증자 전 보통주식이 0인 경우는 strong, 복수 종류가 양수면 medium, 전체 수량이 명시적 0이면 weak warning을 만든다.

##### 최상위 결과

모든 증자 유형이 같은 최상위 구조를 사용한다.
- 결과에는 `증자유형`, `신주의 종류와 수`, `증자 전 발행주식총수`, `발행목적`, `발행가액`, `증자방식`, `납입일`을 넣는다.
- 일정은 `신주권교부예정일`과 `상장예정일`, 대상자는 `발행대상자`에 넣는다.
- 유형별 상세 결과는 `유상증자`와 `무상증자`에 저장하며 적용하지 않는 상세 결과는 `null`이다.

##### 증자 관계 검증

수량·금액 관계를 확인하되 원본 값은 유지한다.
- 발행대상자 합계와 신주 합계가 다르면 차이 크기와 관계없이 weak warning을 만든다.
- 발행목적 합계와 `신주 수량 × 같은 종류의 양수 발행가액` 합계가 다르면 차이 크기와 관계없이 weak warning을 만든다.
- 관계가 달라도 값을 고치지 않으며 유형별 상세값에는 별도 상태나 warning을 만들지 않는다.

## 유상증자 변환

### 자료 흐름

- 표 선택, 주식 종류, 상태와 합계 검증은 유무상증자 공통 변환을 따른다.
- 외부 제목에서 `유상증자`를 확인한 공시에만 적용한다.

### 처리 계약

#### 정상 동작

##### 발행목적 추출

표에 적힌 자금 사용처와 금액을 그대로 저장한다.
- `N=1`이 `자금조달의 목적`과 정확히 일치하는 모든 행에서 `N=2`의 사용처명과 맨 오른쪽 금액을 HTML 순서대로 읽는다.
- 사용처명에서는 원 단위 표기만 제거하며 허용 이름이나 탐색 순서를 하드코딩하지 않는다.
- 0이나 `-`인 항목은 제외한다. 숫자를 하나도 읽지 못하면 `null`과 `source_not_found`, 숫자는 있지만 양수 항목이 없으면 빈 목록과 `explicit_zero`를 기록한다.

##### 발행가액 추출

설명과 예정일을 제외하고 종류별 확정 발행가액을 저장한다.
- 일반 양식은 `N=1`이 `신주 발행가액`, `N=2`가 주식 종류인 첫 행의 맨 오른쪽 값을 읽는다.
- 예정·확정 양식은 `N=1`이 `신주 발행가액`, `N=2`가 `확정발행가`, `N=3`이 주식 종류인 첫 행의 맨 오른쪽 값을 읽는다.
- `N=2`가 `예정발행가`인 행은 맨 오른쪽이 확정예정일이므로 사용하지 않는다.
- 보통주식·기타주식 두 항목을 항상 유지한다.
- 첫 일치 행의 0이나 `-`를 뒤 행의 양수로 바꾸지 않으며 숫자를 읽지 못한 종류는 `null`이다.

##### 증자방식 추출

유상증자 방식을 정해진 이름에서 읽는다.
- `N=1`이 `증자방식`과 정확히 일치하는 첫 행의 맨 오른쪽 값을 읽는다.

##### 납입일 추출

유상증자 납입일을 정해진 이름에서 읽는다.
- `N=1`이 `납입일`과 정확히 일치하는 첫 행의 맨 오른쪽 값을 읽는다.

##### 유상 상세 생성

유상증자에 쓰는 값을 `유상증자`에 모아 저장한다.
- 최상위 수량·목적·가액·방식·납입일·일정·발행대상자를 그대로 사용한다.
- `신주배정기준일`과 `1주당 신주배정주식수`는 유무상증자 공통 변환에 따라 유상증자 부분에서 따로 읽는다.
- `무상증자`는 `null`로 저장한다.

## 무상증자 변환

### 자료 흐름

- 표 선택, 주식 종류와 상태는 유무상증자 공통 변환을 따른다.
- 외부 제목에서 `무상증자`를 확인한 공시에만 적용한다.

### 처리 계약

#### 정상 동작

##### 무상증자 적용 제외

무상증자에 없는 유상증자 항목을 검색 결과 누락과 구분한다.
- `발행목적`, `발행가액`, `증자방식`, `납입일`, `발행대상자`는 검색하지 않는다.
- 각 값에는 `-`, 상태에는 `not_applicable`을 기록하며 warning과 합계 검증에서 제외한다.

##### 무상 상세 생성

무상증자에 쓰는 값을 `무상증자`에 모아 저장한다.
- `신주의 종류와 수`, `증자 전 발행주식총수`와 유무상증자 공통 변환을 무상증자 부분에서 읽어 최상위와 무상 상세에 저장한다.
- 최상위 값으로 상세 결과의 누락값을 채우지 않는다.
- `유상증자`는 `null`로 저장한다.

## 유무상증자 변환

### 자료 흐름

- 표 선택, 주식 종류, 상태와 합계 검증은 유무상증자 공통 변환을 따른다.
- 유상 부분의 값은 유상증자 변환, 무상 부분의 값은 무상증자 변환을 따른다.

### 처리 계약

#### 정상 동작

##### 유상·무상 section 분리

공시 한 건에 함께 있는 유상과 무상 값을 구분한다.
- 합친 줄에서 앞 번호와 공백을 제거한 `N=1`이 `무상증자`와 정확히 일치하는 첫 한 칸짜리 행을 구분점으로 사용한다. 앞 번호가 없는 `무상증자`도 같은 구분점이다.
- 구분점 앞은 유상 부분, 뒤는 무상 부분으로 처리한다.
- 선택하지 않은 표나 최상위 값으로 각 부분의 누락값을 채우지 않는다.

##### 유상 상세 생성

최상위 유상 값을 `유상증자`에 함께 저장한다.
- 최상위 수량·목적·가액·방식·납입일·일정·발행대상자를 사용한다.
- `신주배정기준일`과 `1주당 신주배정주식수`는 유상 부분에서 따로 읽는다.

##### 무상 상세 생성

무상 부분에 적힌 값만 `무상증자`에 저장한다.
- 수량, 증자 전 수량, 배정기준일, 1주당 배정수, 교부예정일과 상장예정일을 무상 부분에서 다시 읽는다.
- 최상위 또는 유상 상세값으로 무상 상세의 누락값을 채우지 않는다.

## 주주총회 변환

### 자료 흐름

- HTML·metadata·최종 payload의 공통 계약은 공시원문 변환을 따른다.
- 이 parser는 외부 `title`을 받지 않고 `field_parse_status`나 warning을 만들지 않는다.

### 처리 계약

#### 정상 동작

##### 주주총회 안건 추출

NOTICE·RESULT 형식의 안건을 같은 목록 구조로 만든다.
- 안건 원문은 확정한 이름의 바로 다음 `td`를 줄 단위로 읽고 빈 줄과 `-`를 제거한다.
- `제1호`, `안건`, `-제1`, `가.`, `나.`, `[`, `<`로 시작하는 줄은 새 안건으로 만들고 나머지는 앞 안건에 이어 붙인다.
- 결과는 `agendas`와 `agenda_items`에 저장한다.

##### 주주총회 선임 내역

이사·사외이사·감사 선임 표를 구분해 저장한다.
- 선임·사업목적 표는 모든 `span` 중 정확히 같은 첫 목차 제목 뒤의 첫 표를 사용한다. 중복 제목에는 `_1`, `_2`, 빈 제목에는 `unknown`을 붙인다.
- `이사선임 세부내역`, `사외이사선임 세부내역`, `감사선임 세부내역`은 각각 `director_elections`, `outside_director_elections`, `auditor_elections`에 저장한다.
- 세 목록은 위 순서로 `elections`에도 합친다. 성명이 비거나 `-`인 줄은 제외한다.
- 각 선임 항목에는 원래 표의 값과 `section_title`, `section_type`, `name`, `birth_month`, `term`, `is_new`, `is_full_time`, `major_career`, `other_company`를 넣는다.

##### 사업목적 변경 추출

변경 전·후 내용과 일반 사업목적 내용을 구분한다.
- 사업목적 변경은 `구분=사업목적 변경`일 때 `내용`과 `내용_1`을 `before`·`after`, 나머지는 `content`로 저장한다.
- 사업목적 항목에는 `category`와 `reason`을 넣고 `구분`이 비었거나 `내용`이 `변경전` 또는 `내용`인 제목 줄은 제외한다.
- `business_purpose_changes` key는 결과에 항상 만든다.

##### 주주총회 선택 항목 처리

NOTICE·RESULT의 실제 제목 변형과 선택적인 상세 목차를 구분한다.
- mode가 `RESULT`이면 `1. 결의사항`, `NOTICE`이면 `3. 의안 주요내용` 또는 `결의사항`을 정해진 순서로 확인한다. mode가 없으면 두 유형을 모두 확인한다.
- 안건·선임·사업목적 목차나 유효 행이 없으면 해당 선택 목록을 빈 목록으로 저장한다.

## 별도 schema가 없는 변환

### 자료 흐름

- HTML·metadata·최종 payload 계약은 공시원문 변환을 따른다.
- 두 mode 모두 전용 schema로 빈 객체를 반환한다.

### 처리 계약

#### 정상 동작

##### 공통 원본 표 구조 생성

상세 추출 규칙이 없어도 다른 parser와 같은 입력·결과 흐름을 사용한다.
- 공통 식별값과 원본 `raw_tables`를 만든다.
- mode 전용 업무값, `field_parse_status`와 parser warning은 만들지 않는다.
- 직접 parser 결과의 `raw_tables`는 공통 저장 과정에서 제거한다.
