# 공시원문 변환

공시 자동화 07단계에서 변환 유형을 고르고 목차 HTML을 구조화된 결과로 바꾼다. 저장 구조와 추출 규칙은 [동작 문서](behavior.md), 복구와 중단 조건은 [예외 문서](reference.md)에서 확인한다.

## 공시원문 변환

### 기능 범위

- 목차 HTML과 외부 metadata를 읽어 유형별 공시 결과를 저장한다. 화면에는 preview와 진단 정보도 제공한다.

## 공시원문 변환 함수

### 기능 범위

- 공시원문 변환에서 메인 함수와 보조 함수가 맡는 기능을 구분해 설명한다.

## 사채발행 변환

### 기능 범위

- `bond_issuance` mode가 CB·EB·BW 공시에서 조건, 목적과 투자자를 추출하는 규칙이다.

## 유무상증자 변환

### 기능 범위

- `rights_issuance` mode가 유상·무상·유무상증자 공시에 공통으로 적용하는 표 선택, 주식 종류, 상태와 검증 규칙이다.

## 유상증자 변환

### 기능 범위

- 유상증자 공시에서 자금 사용처, 발행가액, 방식, 일정과 발행대상자를 추출하는 규칙이다.

## 무상증자 변환

### 기능 범위

- 무상증자 공시에서 적용하지 않는 값과 무상 배정 수량·일정을 구분해 저장하는 규칙이다.

## 유무상증자 변환

### 기능 범위

- 유무상증자 공시의 유상 부분과 무상 부분을 나누어 두 상세 결과를 만드는 규칙이다.

## 주주총회 변환

### 기능 범위

- `shareholder_meeting` mode가 주주총회 안건, 선임 내역과 사업목적 변경을 추출하는 규칙이다.

## 별도 schema가 없는 변환

### 기능 범위

- `asset_transaction` mode는 유무형자산거래 공시, `security_transaction` mode는 발행증권거래 공시를 공통 parser 구조로 읽는다.

## 작업 안내

### parser 문제 조사하고 추출 규칙 고치기

#### 오류 재현하기

1. 제보받은 변환 유형과 접수번호를 확인한다.
2. 같은 입력으로 변환을 다시 실행한다.
3. [동작 문서](behavior.md)에서 저장 경로를 확인하고 해당 접수번호의 결과와 안내를 찾는다.

#### 원본과 규칙 대조하기

1. 접수번호에 해당하는 06단계 HTML을 연다.
2. `bond_issuance`와 `rights_issuance`는 `resources/KIND/bond_issuance`, `resources/KIND/rights_issuance`에 있는 실제 KIND 파일과도 대조한다.
3. 기대한 값이 어느 표와 칸에 있는지 확인한다.
4. 현재 parser가 그 위치를 어떻게 찾는지 [동작 문서](behavior.md)의 변환 유형별 계약과 비교한다.

#### 수정하고 검증하기

1. [동작 문서](behavior.md)의 함수 책임을 확인하고 해당 변환 유형의 추출 규칙을 고친다.
2. 실제 KIND 파일로 바뀐 결과를 확인한다.
3. test fixture와 합성 HTML로 기존 사례가 그대로 동작하는지 검사한다.
4. 변환을 다시 실행해 제보된 오류가 사라지고 다른 결과가 바뀌지 않았는지 확인한다.
