### **1. Summary**

#### **기능 요약**
- `bond_issuance` mode가 CB·EB·BW 공시의 조건, 목적과 투자자를 추출하는 규칙이다.

#### **세부 설명**
- HTML·metadata·상태·warning·최종 payload의 공통 계약은 [공시원문 변환 공통 규칙](../../README.md)을 따른다.
- 이 문서는 사채발행 parser가 추가하는 업무값과 mode별 검증만 설명한다.

### **2. Core**

#### **Feature**

**[Core Processing] 고정 셀 위치 추출 기능**
- **목적:** 원문 표의 각 field를 같은 순서로 찾고 읽는다.
- 라벨 검사는 해당 칸의 앞 번호와 공백을 제거한 뒤 수행한다.
- 메인 표 field의 `N`은 병합 셀의 연속 중복을 압축한 `logical_rows`를 기준으로 한다.
- field마다 왼쪽에서부터 셀 위치 `N`을 고정하고 그 위치에서만 라벨을 확인한다.
- 행을 찾은 뒤 값은 맨 오른쪽 셀에서 읽는다.
- 첫 일치 행을 찾으면 맨 오른쪽 셀이 비어 있거나 값을 변환할 수 없어도 다른 이름이나 뒤 행으로 바꾸지 않는다.
- 한 행에 여러 업무값이 있거나 값 열이 양식마다 달라 이 순서를 적용할 수 없는 field는 해당 기능에 예외를 명시한다.
<br>

**[Core Processing] 사채 조건 표 선택 기능**
- **목적:** 사채 조건을 정해진 첫 표에서만 읽는다.
- `사채의 종류`, `사채의 권면`, `자금조달의 목적`을 모두 가진 첫 표를 사용한다.
- 후보 확인과 메인 표 field 추출은 `logical_rows`를 사용한다.
<br>

**[Core Processing] 사채 투자자 표 선택 기능**
- **목적:** 투자자명과 발행금액의 열을 하나의 표에서 확정한다.
- 첫 줄의 서로 다른 열에 `발행 대상자명`과 `발행권면`이 있는 첫 표를 사용한다.
<br>

**[Core Processing] 사채 종류 추출 기능**
- **목적:** 사채 유형을 외부 제목에서 읽는다.
- `종류`는 외부 `title`에서 CB → EB → BW 순서로 확인하며 정확히 하나만 맞을 때 저장한다.
- `종류`는 표에서 읽는 값이 아니므로 공통 값 위치 규칙의 예외다.
- 행사대상·행사가액·행사기간도 CB·EB·BW의 대칭 이름 순서를 유지한다.
<br>

**[Core Processing] 사채 회차 추출 기능**
- **목적:** 사채 회차를 고정된 표 위치에서 읽는다.
- `회차`는 N=2가 정확히 `회차`인 첫 줄의 N=3 값을 사용한다.
- `회차`는 값이 맨 오른쪽에 있지 않으므로 공통 값 위치 규칙의 예외다.
<br>

**[Core Processing] 발행금액 추출 기능**
- **목적:** 권면총액을 첫 선택 위치에서 읽는다.
- 일반 양식은 N=1이 `사채의 권면`으로 시작하는 첫 줄의 맨 오른쪽 값을 사용한다.
- 외화·원화가 나뉜 해외사채 양식은 N=2가 정확히 `원화기준 (원)`인 줄의 맨 오른쪽 값을 사용한다.
- 두 양식의 라벨 위치가 달라 각각의 고정 위치를 사용하며, 선택한 줄의 맨 오른쪽 값에서 숫자를 읽지 못해도 다른 줄로 바꾸지 않는다.
<br>

**[Core Processing] 만기일 추출 기능**
- **목적:** 사채 만기일을 정해진 이름에서 읽는다.
- N=1이 정확히 `사채만기일` → `사채만기`인 첫 줄의 맨 오른쪽 값을 사용한다.
<br>

**[Core Processing] 행사대상 추출 기능**
- **목적:** CB·EB·BW의 행사대상 기업이나 유가증권을 같은 규칙으로 읽는다.
- `전환대상`, `교환대상`, `인수권행사대상`, `전환에 따라`, `교환에 따라`, `인수권행사에 따라`, `전환으로 발행할`, `교환으로 발행할`, `인수권행사로 발행할`, `신주인수권행사에 따라` 순서로 확인한다.
- N=2가 해당 이름으로 시작하는 첫 줄의 맨 오른쪽 값을 사용한다.
- 먼저 찾은 이름의 값이 비어 있어도 다음 이름의 행으로 바꾸지 않는다.
<br>

**[Core Processing] 행사가액 추출 기능**
- **목적:** 고정 이름의 맨 오른쪽 셀에서 행사 가격을 읽는다.
- N=2를 공백 제거 후 `전환가액 (원/주)`, `교환가액 (원/주)`, `행사가액 (원/주)`, `전환가격 (원/주)`, `교환가격 (원/주)`, `행사가격 (원/주)` 순서로 정확히 일치시킨다.
- 첫 일치 행의 맨 오른쪽 셀 하나만 숫자로 변환하며, 변환할 수 없어도 다음 이름이나 행을 사용하지 않는다.
<br>

**[Core Processing] 납입일 추출 기능**
- **목적:** 사채 납입일을 정해진 이름에서 읽는다.
- N=1이 정확히 `납입일`인 첫 줄의 맨 오른쪽 값을 사용한다.
<br>

**[Core Processing] 행사기간 추출 기능**
- **목적:** 행사 시작일과 종료일을 각각 읽는다.
- N=2가 정확히 `전환청구기간`, `교환청구기간`, `권리행사기간`, `행사기간`인 순서로 찾는다.
- N=3이 정확히 `시작일`인 줄의 맨 오른쪽 값을 행사 시작일, `종료일`인 줄의 맨 오른쪽 값을 행사 종료일로 사용한다.
- 시작일과 종료일은 따로 읽으며 서로의 값이나 뒤의 다른 기간 이름으로 보완하지 않는다.
<br>

**[Core Processing] 사채발행방법 추출 기능**
- **목적:** 사채 발행 방법을 정해진 이름에서 읽는다.
- N=1이 정확히 `사채발행방법`인 첫 줄의 맨 오른쪽 값을 사용한다.
<br>

**[Core Processing] 발행목적 추출 기능**
- **목적:** 자금조달 목적별 금액만 목록으로 저장한다.
- N=1이 정확히 `자금조달의 목적`인 줄만 사용한다.
- 목적명은 N=2, 금액은 맨 오른쪽 값에서 읽은 숫자를 사용한다.
- 0이나 `-`인 항목과 목적명만 있고 금액이 없는 줄은 결과에서 제외한다.
- 모든 줄에서 금액을 찾지 못하면 `발행목적` 전체를 `source_not_found`로 처리한다.
- 결과는 `[[이름, 금액], ...]` 구조다.
<br>

**[Core Processing] 투자자 추출 기능**
- **목적:** 선택한 투자자 표의 이름과 발행권면총액만 저장한다.
- 투자자명과 금액은 `positional_rows`의 표 제목에서 확정한 열에서만 읽는다.
- 투자자는 column header에서 `발행 대상자명`과 `발행권면` 열을 각각 확정한 뒤 모든 데이터 줄에서 같은 열을 읽는다.
- 따라서 투자자 표에는 메인 표 field의 고정 N 규칙을 적용하지 않는다.
- 이름이 빈 값·`-`·합계 표현이면 제외하고 금액 `-`는 0으로 남긴다.
- 첫 유효 투자자 표에 남길 줄이 없으면 `null`로 끝내며 다른 표나 열로 보완하지 않는다.
- 결과는 `[[이름, 금액], ...]` 구조다.
<br>

**[Core Processing] 사채 field 상태 기능**
- **목적:** 사채 업무값을 읽은 결과를 field별로 기록한다.
- 모든 업무값에 상태를 기록하고 `발행금액`의 0이나 `-`는 `explicit_zero`로 기록한다.
- 발행목적에 양수 항목이 있으면 `parsed`, 숫자는 있지만 남길 항목이 없으면 `explicit_zero`, 숫자가 없으면 `source_not_found`다.
- 이 parser는 medium warning을 직접 만들지 않는다.
<br>

**[Result Validation] 사채 합계 검증 기능**
- **목적:** 발행목적·투자자 합계와 발행금액의 관계를 확인한다.
- 발행목적 합계나 투자자 합계가 발행금액과 다르면 허용 오차 없이 weak warning을 만든다.
- 합계가 달라도 원본에서 읽은 값은 고치지 않는다.
<br>

#### **Fallback**

- 없음.

#### **Shutdown**

**[Core Processing] 사채 필수 표 누락시 중단하기**
- **목적:** 사채 조건이나 투자자를 확정하지 못한 원문에서 일부 값만 만들지 않는다.
- `사채의 종류`, `사채의 권면`, `자금조달의 목적`을 모두 가진 표가 없으면 즉시 실패 처리한다.
- 첫 줄의 서로 다른 열에 `발행 대상자명`과 `발행권면`이 있는 표가 없으면 즉시 실패 처리한다.

그 밖의 중단 규칙은 [공시원문 변환의 Core Shutdown](../../README.md#shutdown)을 따른다.
