## 1. 문서의 목적

이 문서는 `shareholder-meeting` 모드의 작동 방식과 다음 작업자를 위한 인계 사항을 기록한다.

- 작업의 목표는 주주총회 공시에서 안건과 주체(사람·기관)를 찾고, 이들 사이의 관계를 결정론적으로 추출하는 것이다. 로직 구현 과정에서 정답을 판정하고 반례를 검토할 때는 LLM을 사용했지만, 최종 로직은 LLM이나 외부 모델을 호출하지 않아야 한다.
- 
후보자를 현직 임원으로 잘못 판단하지 않고, 이름이 없는 주체를 추정하지 않으며, 파싱에 실패했을 때 다른 필드·문서 구조·메타데이터로 값을 메우지 않는 데 우선순위를 뒀다.

현재 골든 자료와 집중 테스트는 통과했다. 같은 코드로 2026년 외부·내부 HTML 4,389쌍도 예외 없이 파싱했다. 다만 이번 범위 변경 이후 전체 불변 조건과 2008–2026년 71,965쌍 전체 이력은 다시 감사하지 않았다. 현재 구현과 회귀 테스트는 인계할 수 있지만, 전체 이력 검증은 다음 작업으로 남아 있다.

## 2. 추출 범위

### 추출하는 정보

| 항목 | 처리 방식 |
| --- | --- |
| 안건 | 열 구조가 분명한 구조화 안건(structured agenda)과 라벨 옆 셀을 읽는 구형 안건(legacy agenda)을 처리한다. |
| 임원 후보와 선임 결과 | 이사·사외이사·감사·감사위원 후보를 찾는다. 결과공고(RESULT)에서 가결된 경우에만 실제 선임 관계를 만든다. |
| 해임·사임 | 대상자와 직책을 기록하고, 가결된 결과는 그래프의 임원 재직 기간에도 반영한다. |
| 다른 회사의 현직 | 후보자의 주요 경력에서 현재 다른 법인과 직책이 명확할 때 재직 관계를 만든다. |
| 외부감사인 | 현재 감사기관과 변경 전 감사기관을 구분한다. |
| 주식 거래 당사자 | 주주, 주식 양도인·양수인, 제3자배정 대상자를 역할별로 구분한다. |
| 기업 거래 대상 | 합병·인수·양도의 상대 회사가 원문에 명시된 경우에만 연결한다. |
| 근거와 참조 | 문서 안에서만 유효한 주체, 참조값, 원문 근거를 보존하고 그래프 연결 대상의 유형을 검사한다. |

### 추출하지 않는 정보

아래 내용은 분석 목적상 중요도가 낮아 추출하지 않는다.

- 안건 중 **주주제안자**: 안건은 남기되 주체나 관계를 남기지 않는다.
- 안건 중 **주식매수선택권 대상자**: 안건은 남기되 주체나 관계를 남기지 않는다.
- 투표 중 **전자투표 관리기관** 및 **시스템 제공기관**: 주체나 관계를 남기지 않는다.

## 3. 관계 계약

현재 문서 단위 의미 계약(semantic contract)은 다음 15개 관계를 사용한다.

| 관계 | 의미 |
| --- | --- |
| `includes` | 주주총회가 안건을 포함함 |
| `candidate_for` | 사람이 임원 후보로 올라감 |
| `elected_as` | 가결 결과에 따라 임원으로 선임됨 |
| `removed_from` | 가결 결과에 따라 직책에서 해임됨 |
| `resigned_from` | 가결 결과에 따라 직책에서 사임함 |
| `subject_of` | 사람이나 기관이 특정 안건의 대상임 |
| `serves_at` | 사람이 다른 회사에서 현재 근무함 |
| `external_auditor_of` | 회계법인이 보고회사의 외부감사인임 |
| `shareholder_of` | 사람이나 기관이 보고회사의 주주임 |
| `transferor_of` | 사람이나 기관이 주식 양도인임 |
| `transferee_of` | 사람이나 기관이 주식 양수인임 |
| `proposed_allottee_of` | 사람이나 기관이 제3자배정 대상임 |
| `merger_target_of` | 기관이 합병 대상임 |
| `acquisition_target_of` | 기관이 인수 안건의 대상임 |
| `divestment_target_of` | 기관이 양도 안건의 대상임 |

모든 관계에는 허용된 출발점과 도착점 유형, 문서 안에서만 유효한 참조값, 비어 있지 않은 원문 근거가 있어야 한다. 후보와 현재 임원은 구분한다. `elected_as`, `removed_from`, `resigned_from`은 결과공고에 `passed`가 명시된 경우에만 만든다.

## 4. 구현 원칙

### 안건과 두 개의 허용 대체 경로

기본 원본은 첫 번째로 확인된 구조화 안건 표 하나다. 표를 선택할 때 제목 열도 함께 고정한다. 행 값이 비어 있거나 형식이 맞지 않아도 다른 열, 후손 셀, 인접 셀, 뒤의 표로 바꾸거나 여러 표를 합치지 않는다.

실패 뒤 다른 원본을 찾는 대체 경로(fallback)는 두 개만 허용한다.

1. 문서에 구조화 안건 스키마가 아예 없을 때만, 정확한 라벨과 같은 행에 있는 두 개의 직접 자식 셀을 읽는다.
2. 이름으로 선임 상세와 안건을 연결한 결과가 0건이고, 같은 직책의 선임 상세와 이름 없는 호환 안건이 각각 한 건뿐일 때만 둘을 연결한다.

주식 양도, 외부감사인, 사업목적 합병처럼 표현이 여러 개인 항목은 첫 문법이 실패한 뒤 다른 문법을 시도하지 않는다. 같은 기준 원본에서 가능한 후보를 독립적으로 모은 뒤 중복을 제거한다.

### 인물 식별자 사전 결정

예전에는 생년월이 없는 사람을 먼저 만든 뒤 같은 이름과 생년월이 나오면 기존 주체를 변경하거나 합쳤다. 이 방법은 원문을 읽는 순서에 따라 결과가 달라지고 동명이인을 잘못 합칠 위험이 있었다.

현재는 선임 상세 행을 먼저 읽고, 같은 인물 키에 연결된 생년월을 모아 다음 규칙으로 식별자를 정한다.

- 생년월이 없으면 생년월 없는 식별자를 사용한다.
- 생년월이 하나면 그 값을 가진 식별자를 사용한다.
- 서로 다른 생년월이 둘 이상이면 동명이인일 수 있으므로 생년월이 없는 안건이나 선임 표면을 어느 한 사람에게 연결하지 않는다.
- 선임 상세 행에 생년월이 적혀 있으면 원문 값을 그대로 유지한다.

이 규칙은 선임 대상, 일반 안건 후보(`agenda_candidate`), 생년월이 빈 선임 상세 행에 똑같이 적용한다. 등록소가 나중에 기존 사람을 찾아 변경하는 방식이 아니므로 입력 순서에 따라 사람이 합쳐지지 않는다.

### 주요 경력과 다른 법인

`other_company`는 다른 법인명과 직위가 명시된 원본으로 우선 사용한다. `major_career`는 `<br>`로 구분한 한 줄 전체에 현재 표식, 기관 표지, 지원하는 직책이 모두 있을 때만 `serves_at` 관계로 만든다. 과거 경력, 학교·학과, 일반 전문직 설명, 여러 기관이 섞여 대상을 하나로 정할 수 없는 줄은 제외한다.

같은 셀에서 기관명과 직책이 줄바꿈된 경우에는 `기관명 줄 + 바로 다음 완전한 직위 줄` 전체가 명시 문법에 맞아야 한다. `사내\n이사`, `부\n회장`처럼 직책 단어가 중간에서 갈린 표면은 기관명과 직책의 조합으로 보지 않는다. 원문 기관명이 전달받은 보고회사명과 정확히 같을 때만 `@reporting_company`로 연결하며, 회사명을 모를 때 부서명이나 다른 메타데이터로 보완하지 않는다.

### 외부감사인

첫 번째로 확인한 `기타 투자판단에 참고할 사항`의 값 행에 회계법인 이름과 선임·변경 행위가 함께 있을 때만 외부감사인을 추출한다. 현재 감사기관과 변경 전 감사기관은 각각 `current`, `former`로 구분한다. 선택한 값이 비거나 해석되지 않아도 뒤의 같은 제목으로 바꾸지 않는다.

### 해임·사임과 그래프 수명주기

직책과 이름이 직접 붙은 해임·사임 안건만 종료 대상으로 삼는다. 상위 안건의 직책을 역할이 없는 하위 안건에 물려주지 않는다. `ROLE + 한국어 3음절 이름 + 의 + 해임·사임` 또는 영문·띄어쓴 이름의 명시 문법 밖에서는 이름 끝의 `의`를 목록 조회나 길이로 보정하지 않는다.

그래프에서는 결과공고, 가결, 유효한 회의일이 모두 있는 종료 관계만 사용한다. 같은 회사, 같은 사람 식별자, 같은 직책에 해당하는 더 이른 선임 관계가 정확히 맞을 때만 재직을 끝낸다. 이름만 같거나 직책이 다르거나, 동일일·미래의 선임 또는 구형 임원 관계에는 다시 연결하지 않는다.

### 거래 주체

현재 참고사항의 값 행, 선택된 안건, 이미 파싱한 사업목적 변경 이유에서 이름과 거래 행위가 직접 연결된 경우에만 주주, 양도·양수인, 제3자배정 대상, 합병·인수·양도 대상을 만든다. 이름 없는 역할, 관련공시 링크, 일반적인 인수합병 설명은 주체의 원본으로 사용하지 않는다.

합병은 방향을 확정할 수 있는 문장만 처리한다. 법인 표지가 붙은 단일 상대방, 명시적인 피합병·소멸 법인, 법인 표지가 붙은 흡수합병 대상, 보고회사가 정확히 한쪽인 두 당사자 문장이 여기에 해당한다. 취소·철회·중단·무산·백지화·폐기 문장은 관계로 만들지 않는다.

### 그래프 입력 계약

그래프는 현재 `agenda_records`, `entities`, `relationships` 배열만 사용한다. 구형 `agendas`, `elections`, 파싱된 메타데이터나 원문을 다시 해석해 빈자리를 메우지 않는다.

주주총회 노드를 만들려면 필터링된 레코드의 `company_id`, `company_name`, `disclosed_date`, `title`, 같은 접수번호의 파싱 결과, 유효한 `meeting_date`가 모두 필요하다. 이를 `company_key`, `submitter`, `disclosed_at`, 파싱된 제목·원본, 공시일로 대체하지 않는다. 예약 참조값 충돌, 중복 참조값, 관계 끝점 유형 불일치, 비어 있는 원문 근거가 있는 그래프 관계는 제외한다.

## 5. 검증 자료

### 실제 원문 골든 자료

작은 예문만으로는 실제 공시의 복잡한 표 구조와 표현 차이를 확인하기 어렵다. 그래서 실제 접수번호 34개의 외부·내부 HTML을 검증 기준 자료(golden corpus)로 고정했다. 전체 HTML은 68개이며 크기는 1,478,272바이트다.

`tests/fixtures/shareholder_meeting/golden`에는 다음 자료가 있다.

- `manifest.json`: 원본 경로, 원문 SHA-256, 정규화 출력 SHA-256, 양성·음성 검증 조건
- `adjudication.json`: 문서별 판정 근거, 의견 차이, 최종 합의
- `adjudication_prompt.md`: 판정 기준
- `sources/`: 데이터베이스 원본과 바이트가 같은 전체 HTML

같은 입력을 두 번 파싱해 정규화한 JSON이 같은지도 검사한다. 출력 SHA-256이 달라졌다고 목록 파일의 값만 바꾸면 안 된다. 먼저 이전 결과와 현재 결과를 비교하고 원문 검증 조건이 유지되는지 확인해야 한다.

관련 KIND·웹 통합 검사는 범위 변경 전에 `385 passed, 166 skipped`였다. 저장소 전체 검사의 이전 결과는 `1358 passed, 167 skipped, 4 failed`였으며, 실패한 4건은 주주총회 범위 밖의 분류용 SQLite 계약 2건과 HTML 다운로드 입력 검증 순서 2건이었다. 두 결과 모두 이번 범위 변경 뒤 다시 실행한 값이 아니므로 현재 전체 검증값으로 사용하면 안 된다.

## 6. 실패한 시도와 교훈

### 두 줄 머리글을 잘못 해석한 문제

- 시도: 두 줄 머리글이 나오면 둘째 줄의 특정 열을 안건 제목으로 사용한다.
- 문제: 실제로는 표결 수치 열만 묶인 결과 표에서도 제목 열을 잘못 골라, 골든 자료 4건의 안건 34개와 연결 관계가 사라졌다.
- 현재: 둘째 줄에 `안건` 열이 명시된 경우에만 그 열을 쓴다. 그렇지 않으면 첫 줄의 `회의목적사항`을 유지한다. 안건 수만 검사하지 않고 대표 번호, 제목, 상태까지 검증 조건으로 고정했다.

### `재선임` 처리로 후보자 이름 7개가 잘린 문제

- 시도: 접두어를 기반으로 주체를 추출한다.
- 문제: 접두어를 지우는 정규식의 경계가 지나치게 넓어 `이원재`를 `이원`으로 읽는 문제가 생겼다.
- 현재: `재선임` 같은 행위어는 독립된 단어일 때만 처리하고, 후보 수만 비교해서는 찾기 어려우므로 접수번호별 이름과 관계의 변경 내용을 함께 검사한다.

### 이름 끝 `의`를 목록과 길이로 보정한 문제

- 시도: 이름 끝의 `의`가 조사인지 이름 일부인지 판단하려고 선임 상세표를 조회하거나 이름 길이를 사용한다.
- 문제: 다른 원본을 참조하는 대체 경로가 생기고, 동명이인이나 실제 이름을 훼손할 수 있다.
- 현재: 종료 문장의 엄격한 문법에서 조사임이 분명할 때만 `의`를 처리한다. 모호한 표면은 추출하지 않으며, 새 예외가 생겨도 이름 길이, 후보 목록, 다른 필드를 차례로 조회하는 보정은 추가하지 않는다.

### 생년월 없는 사람을 나중에 합친 문제

- 시도: 안건에서 생년월이 없는 사람을 먼저 만든 뒤 선임 상세표에 나온 같은 이름과 생년월의 사람으로 변경하거나 병합한다.
- 문제: 입력 순서에 따라 결과가 달라지고 동명이인을 잘못 합칠 수 있다. 이 로직을 제거하자 `김한민`이 안건과 두 직책 상세에 함께 나온 골든 자료에서 중복 주체 또는 안건 근거 누락이 드러났다.
- 현재: 사람을 만들기 전에 고유한 생년월 값을 결정한다. 직책이 둘이어도 생년월이 하나면 같은 식별자를 쓰고, 생년월이 둘 이상이면 모호한 연결을 만들지 않는다. `20260105000566` 골든 자료와 별도 축약 테스트로 이 경계를 고정했다.

### 그래프에서 누락값을 대신 채운 문제

- 시도: 회사·날짜·제목·직책·근거가 비면 `company_key`, `submitter`, `disclosed_at`, 파싱된 메타데이터, 공시일 같은 다른 값으로 채운다. 이름과 생년월 존재 여부에 따라 종료 인물을 다른 사람 식별자로 다시 연결하기도 한다.
- 문제: 파서 계약 밖에서 의미를 새로 만들고 출처 없는 날짜와 신원이 생길 수 있다.
- 현재: 정규 입력이 없으면 해당 항목을 건너뛰고, 관계 근거에는 비어 있지 않은 `raw_text`를 요구한다. 복수 후보의 직책을 확정하지 못하면 안건 전체의 직책을 각 후보에게 대신 넣지 않는다. 그래프는 파서 원문을 다시 해석하지 않으며, 재직 기간을 끝낼 때도 같은 사람 식별자를 유지한다.

### 첫 원본 실패 뒤 다른 위치를 다시 찾은 문제

- 시도: 첫 줄 해석 실패 뒤 기관명 줄과 직책 줄을 재조합하고, 첫 회의일·참고사항·선임 제목·구형 안건 라벨이 비거나 형식에 맞지 않으면 뒤의 같은 항목을 다시 찾는다. `배정대상자` 값이 비면 다음 문장 조각을 대체값으로 사용한다.
- 문제: 모두 첫 원본이 실패한 뒤 다른 문서 위치로 이동하는 대체 경로다.
- 현재: 각 영역의 첫 기준 원본과 물리적인 줄 경계를 고정한다. 필요한 줄바꿈 형식은 조건부 재검색이 아니라 하나의 완전한 다중행 문법으로 정의한다.

### 넓은 키워드 문법이 만든 오탐

- 시도: 합병 대상이나 현재 경력을 단어 포함 여부만으로 찾는다.
- 문제: 일반 역할어, 취소된 합병, 복수 기관이 섞인 문장, 학교·부서·과거 경력이 기관 관계로 잘못 생성됐다. 추출 범위에서 제외한 전자투표 기관, 주주제안자, 주식매수선택권 대상자도 같은 이유로 다시 나타날 수 있었다.
- 현재: 값을 만들어야 하는 명시 문법과, 겉보기에는 비슷하지만 만들면 안 되는 음성 경계를 같은 테스트에 넣는다. 취소·부정·일반 역할·복수 당사자 문장은 양성 문법과 함께 검증한다.

### 문법을 단계식 대체 경로로 구현한 문제

- 시도: 첫 정규식이 실패할 때만 다음 정규식이나 인접 제목을 검사하는 방식으로 여러 합법 문법을 지원한다.
- 문제: 결과가 맞더라도 코드상 대체 경로가 늘고 문법 간 우선순위를 검증하기 어렵다.
- 현재: 주식 양도 당사자, 외부감사인 전환, 사업목적 합병 상대방 문법은 같은 원본에서 독립적으로 후보를 모은 뒤 중복을 제거한다. 다음 작업에서도 `A 실패 → B 시도`를 추가하기 전에 A와 B가 같은 기준 원본을 해석하는 독립 문법인지 확인해야 한다.

### 변경 중인 코드로 실행한 감사

- 시도: 코드가 바뀌는 동안 2026년 또는 전체 이력 감사를 실행한다.
- 문제: 시작과 종료 시점의 해시가 다르면 예외와 불변 조건 위반이 0건이어도 현재 코드의 검증 자료로 쓸 수 없다.
- 현재: 대상 파일의 해시를 두 번 확인한 뒤 변경되지 않는 스냅숏으로 복사하고, 종료할 때 스냅숏의 시작·종료 해시와 현재 작업 디렉터리의 해시를 비교한다. 하나라도 다르면 결과와 집계값을 폐기한다. 골든 출력 해시가 달라진 경우에도 값을 바로 갱신하지 않고 구조화 결과와 원문 검증 조건부터 비교한다.
