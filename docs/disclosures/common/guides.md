# 공시분석 공통 사양

## 목적

- 공시분석 단계별 문서와 담당 경로를 연결한다.
- 여러 단계가 함께 쓰는 작업공간, 저장 방식과 Web UI 규칙을 설명한다.
- 공시 처리 1~7단계를 차례로 실행하고 각 단계의 결과를 검증한다.

## 핵심 기능

### 단계 결과 게시

완성된 단계 결과만 현재 결과 위치에 게시한다.

- 기존 결과를 백업한 뒤 새 단계 폴더를 `.automation-current` 위치로 옮긴다.

### HTML 원본 metadata 연결

저장한 HTML을 같은 `acpt_no`의 원본 공시와 연결해 manifest를 만든다.

## 사용과 화면

### 단계별 자동화 실행

선택한 공시 처리 단계를 정해진 순서와 입력으로 실행한다.

- 선택한 1~7단계를 번호 순서대로 실행한다. 입력, 결과와 저장 규칙은 각 단계 문서를 따른다.

- 단계가 끝나면 실행 상태에 완료 기록을 남긴다.

- 자동화의 03단계는 프리셋 원본의 완료·중단 결과와 검사 완료 위치를 다음 실행 입력으로 전달한다.

### 기존 HTML 재사용

이미 저장한 KIND HTML을 구조와 단계별 manifest로 검증해 재사용 여부를 결정한다.

## 기존 HTML 확인

### 기존 HTML을 확인하고 기준 해시 만들기

기존 외부 HTML이나 본문 HTML에 바이트 수와 SHA-256 기준값이 없어 작업이 멈췄을 때 이 절차를 따른다.

1. 멈춘 단계가 외부 HTML 저장인지 본문 HTML 저장인지 확인한다.
2. 현재 HTML이 믿을 수 있는 원본인지 직접 확인한다.
3. 외부 HTML이면 `현재 외부 HTML 신뢰`, 본문 HTML이면 `현재 내부 HTML 신뢰` 체크박스를 고른다.
4. `기준 해시 생성`을 누르고 작업이 끝날 때까지 기다린다.
5. 작업이 끝나 화면에 저장 범위가 다시 표시되면 `기준 없음`이 0건이고 `해시 확인`이 기존 HTML 건수와 같은지 확인한다.
6. 다운로드 `실행`을 누르고 나머지 작업이 이어지는지 확인한다.
