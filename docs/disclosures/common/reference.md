# 공시분석 공통 사양

## 기능 범위

- 공시분석 단계별 문서와 담당 경로를 연결한다.
- 여러 단계가 함께 쓰는 작업공간, 저장 방식과 Web UI 규칙을 설명한다.
- 공시 처리 1~7단계를 차례로 실행하고 각 단계의 결과를 검증한다.
- 시스템 행동은 [문서 작성 기준](../../common/documentation/reference.md)의 `Layer → Behavior → Responsibility` 순서로 분류한다.

## 자료 흐름

- 단계 문서는 해당 단계만 따르는 규칙을 설명한다.
- 처음 작업하는 흐름은 [FINIQ 공통 흐름 익히기](../../common/getting-started/tutorials.md)에서 익힌다.

## 함께 쓰는 사양

### 작업공간

`<data_root>`는 화면에서 고른 `작업공간 디렉토리`다. 별도 저장 경로를 켜지 않으면 공시 단계는 아래 경로를 사용한다.

```text
<data_root>/
├── 01-list/
├── 02-table/
├── 03-filter/
├── 04-external-html-download/
├── 05-internal-html-download/
├── 06-sections/
├── 07-converted/
└── 09-disclosure-graph/
```

- 03단계 원본은 `03-filter/<workflow-name>.json`에 둔다.
- 03단계 전달 파일과 04·05·07단계 결과는 `<mode>` 폴더로 나눈다.
- 08단계는 07단계 결과를 읽는 조회 기능이므로 결과 폴더를 만들지 않는다.
- 09단계는 여러 mode 결과를 `disclosure-graph.json` 하나로 합친다.
- `저장 디렉토리 별도 설정하기`가 꺼져 있으면 표준 경로를 사용한다. 켜져 있으면 해당 화면에서 지정한 별도 경로를 사용한다.
- 화면이 별도 저장 경로를 받으면 입력과 결과 위치를 명시하며 이름순 탐색으로 대신하지 않는다.

### 비동기 작업

- 조건검색 프리셋 상태와 중단 결과는 [제목 조회와 공시 선택](../03-filter/reference.md)를 따른다.
- 04·05단계 취소는 이미 저장한 파일을 남기고 취소 상태를 돌려준다.
- worker 수는 양의 정수여야 한다. 기능 문서가 다른 기본값을 밝히면 그 값을 따른다.

### 화면 표시

- 공통 표시와 비동기 작업 복구 규칙은 [공통 화면 사양](../../common/common-ui/reference.md)를 따른다.
- 공시 화면은 빈 값을 `-`로 표시하고 숫자 `0`은 그대로 표시한다.

### 진행 내역

**공시 공통 상태** — 처음 10줄, 이후 최근 80줄

**공시 자동화** — 최근 30줄

**외부·본문 HTML 저장** — 최근 100줄

**목차 HTML 저장** — 최근 200줄

### 결과 예시

**KIND 저장 누락 페이지** — 20개

**SQLite 무결성 오류** — 10개

**공시 자동화 파일 문제** — 종류별 20개

**외부·본문 HTML 오류** — 종류별 10개

**변환 preview** — 기본 3건

**변환 필터 후보 접수번호** — 값별 20개

**변환 공시 시각 오류** — 종류별 10개

**정정내역 변경 항목 이름** — 5개

## 처리 계약

### 정상 동작

#### 단계 결과 게시

완성된 단계 결과만 현재 결과 위치에 게시한다.
- 기존 결과를 백업한 뒤 새 단계 폴더를 `.automation-current` 위치로 옮긴다.

#### HTML 원본 metadata 연결

저장한 HTML을 같은 `acpt_no`의 원본 공시와 연결해 manifest를 만든다.
- HTML 저장이 끝난 뒤 원본 JSON에서 같은 `acpt_no`의 공시를 찾아 manifest metadata로 사용한다.

### 중단 조건

#### 단계 결과를 교체하지 못하면 실행 중단

새 결과로 교체하지 못하면 기존 결과를 복원하고 자동화를 중단한다.
- `os.replace`가 실패했을 때 `.automation-current`가 비어 있고 백업이 남아 있으면 백업을 원래 위치로 되돌린 뒤 실패 처리한다.

#### HTML 저장 연결 오류가 나면 중단

저장한 HTML과 원본 공시를 연결할 수 없으면 manifest를 만들지 않는다.
- HTML 저장이 끝난 뒤 원본 JSON에서 같은 `acpt_no`의 공시를 찾지 못하면 요청 전체를 실패 처리한다.

## 화면과 서비스 계약

### 정상 동작

#### 단계별 자동화 실행

선택한 공시 처리 단계를 정해진 순서와 입력으로 실행한다.
- 선택한 1~7단계를 번호 순서대로 실행한다. 입력, 결과와 저장 규칙은 각 단계 문서를 따른다.
- 단계가 끝나면 실행 상태에 완료 기록을 남긴다.
- 처리할 공시가 0건이면 빈 결과를 정상 완료로 표시한다.
- 03단계부터 실행하는 계획은 저장된 `조건검색 프리셋`을 지정해야 한다. 자동화의 변환 유형·조건이 프리셋과 다르면 실행하지 않는다.
- 자동화의 03단계는 프리셋 원본의 완료·중단 결과와 검사 완료 위치를 다음 실행 입력으로 전달한다.

#### 사용자 판단 대기

06단계에서 저장 규칙이 없는 목차를 발견하면 사용자가 판단할 때까지 후속 단계의 실행 요청을 보류한다.
- 저장 규칙이 없는 목차를 발견하면 `needs_review` 상태와 이미 끝난 단계의 결과를 반환한다.
- 저장 규칙이 없는 목차가 있거나 이전 검토 결과가 없으면 `unmatched_policy=needs_review`로 실행하고 빈 검토 목록에서 시작한다.
- 모든 목차를 판단하면 기존 규칙과 새 결정을 다음 단계 입력으로 전달해 후속 실행을 시작한다.

#### 기존 HTML 재사용

이미 저장한 KIND HTML은 구조 검사와 단계별 manifest 검사를 모두 통과할 때만 재사용한다.
- 구조 검사는 파일을 UTF-8로 읽고 `<html` 또는 `openDisclsViewer`가 있는지 확인한다. UTF-8로 해석하지 못한 byte는 건너뛰며 파일 자체를 읽지 못하면 정상 HTML로 인정하지 않는다.
- 현재 파일에서 계산한 바이트 수와 SHA-256이 manifest 기준값과 같을 때만 건너뛴다. 파일 내용이 바뀌었으면 해당 HTML을 다시 받는다.
- 기준값이 없는 기존 파일은 자동으로 신뢰하지 않는다. 사용자가 확인한 파일만 기준값을 기록한다.
- 기준 해시는 현재 있고 구조 검사를 통과한 대상에만 만든다. 아직 없는 대상은 정상 다운로드에서 받는다.
- 기존 HTML은 바이트 수와 SHA-256 기준값이 없으면 사용자가 신뢰 여부를 정할 때까지 작업을 멈춘다.
- 실제 확인 순서는 [기존 HTML을 확인하고 기준 해시 만들기](../html-download/how-to-guides.md)에서 안내한다.
- 외부 HTML 기준은 [외부 HTML 저장](../04-external-html-download/reference.md), 본문 HTML 기준은 [본문 HTML 저장](../05-internal-html-download/reference.md)에서 확인한다.

### 복구 동작

#### 단계 결과 불일치 후 재실행

완료 기록이나 결과 파일이 현재 상태와 다르면 해당 단계부터 다시 실행한다.
- 불일치가 확인된 첫 단계부터 필요한 후속 단계를 번호 순서대로 다시 실행한다.

#### worker 기본값

CPU 수를 알 수 없어도 작업을 시작한다.
- CPU 수를 확인하지 못하면 worker를 1개 사용한다.

### 중단 조건

#### 자동화 설정 오류가 나면 중단

읽을 수 없는 자동화 설정을 임의로 고치지 않는다.
- 저장한 설정이 JSON이 아니거나 현재 형식이 아니면 화면을 열지 못한 것으로 처리한다.

#### 공통 설정 오류가 나면 중단

읽지 못한 설정을 이전 값이나 임의의 값으로 대신하지 않는다.
- 공통 설정을 가져오지 못하면 실패 처리한다.
- worker 수가 양의 정수가 아니면 실패 처리한다.
- 저장 경로를 읽을 수 없거나 작업 기록 보존 시간이 양의 정수가 아니면 실패 처리한다.
