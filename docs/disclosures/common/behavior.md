# 공시분석 공통 동작

기본 자료 흐름과 정상 실행 계약을 설명한다.

## 함께 쓰는 사양

### 작업공간

`<data_root>`는 화면에서 고른 `작업공간 디렉토리`다. 별도 저장 경로를 켜지 않으면 공시 단계는 아래 경로를 사용한다.

```text
<data_root>/
├── 01-list/
├── 02-table/
├── 03-filter/
├── 04-external-html-download/
├── 05-internal-html-download/
├── 06-sections/
├── 07-converted/
└── 09-disclosure-graph/
```

- 03단계 원본은 `03-filter/<workflow-name>.json`에 둔다.
- 03단계 전달 파일과 04·05·07단계 결과는 `<mode>` 폴더로 나눈다.
- 08단계는 07단계 결과를 읽는 조회 기능이므로 결과 폴더를 만들지 않는다.
- 09단계는 여러 mode 결과를 `disclosure-graph.json` 하나로 합친다.
- `저장 디렉토리 별도 설정하기`가 꺼져 있으면 표준 경로를 사용한다. 켜져 있으면 해당 화면에서 지정한 별도 경로를 사용한다.
- 화면이 별도 저장 경로를 받으면 입력과 결과 위치를 명시하며 이름순 탐색으로 대신하지 않는다.

### 비동기 작업

- 04·05단계 취소는 이미 저장한 파일을 남기고 취소 상태를 돌려준다.
- worker 수는 양의 정수여야 한다. 기능 문서가 다른 기본값을 밝히면 그 값을 따른다.
- 브라우저에 작업 ID가 남아 있으면 화면을 다시 열었을 때 같은 작업의 상태를 확인한다.

### 화면 표시

- 공시 화면은 빈 값을 `-`로 표시하고 숫자 `0`은 그대로 표시한다.
- 긴 파일 경로는 마지막 네 부분만 남기고 앞을 `.../`로 줄인다. 실제 경로와 저장 결과는 바꾸지 않는다.
- 진행 내역과 오류 예시는 화면별로 정한 개수만 보여 준다. 전체 개수와 성공·실패 판단은 줄이지 않는다.

### 진행 내역

**공시 공통 상태** — 처음 10줄, 이후 최근 80줄

**공시 자동화** — 최근 30줄

**외부·본문 HTML 저장** — 최근 100줄

**목차 HTML 저장** — 최근 200줄

### 결과 예시

**KIND 저장 누락 페이지** — 20개

**SQLite 무결성 오류** — 10개

**공시 자동화 파일 문제** — 종류별 20개

**외부·본문 HTML 오류** — 종류별 10개

**변환 preview** — 기본 3건

**변환 필터 후보 접수번호** — 값별 20개

**변환 공시 시각 오류** — 종류별 10개

**정정내역 변경 항목 이름** — 5개

## 처리 계약

### 정상 동작

#### 단계 결과 게시

완성된 단계 결과만 현재 결과 위치에 게시한다.
- 기존 결과를 백업한 뒤 새 단계 폴더를 `.automation-current` 위치로 옮긴다.

#### HTML 원본 metadata 연결

저장한 HTML을 같은 `acpt_no`의 원본 공시와 연결해 manifest를 만든다.
- HTML 저장이 끝난 뒤 원본 JSON에서 같은 `acpt_no`의 공시를 찾아 manifest metadata로 사용한다.

## 화면과 서비스 계약

### 정상 동작

#### 단계별 자동화 실행

선택한 공시 처리 단계를 정해진 순서와 입력으로 실행한다.
- 선택한 1~7단계를 번호 순서대로 실행한다. 입력, 결과와 저장 규칙은 각 단계 문서를 따른다.
- 단계가 끝나면 실행 상태에 완료 기록을 남긴다.
- 처리할 공시가 0건이면 빈 결과를 정상 완료로 표시한다.
- 03단계부터 실행하는 계획은 저장된 `조건검색 프리셋`을 지정해야 한다. 자동화의 변환 유형·조건이 프리셋과 다르면 실행하지 않는다.
- 자동화의 03단계는 프리셋 원본의 완료·중단 결과와 검사 완료 위치를 다음 실행 입력으로 전달한다.

#### 기존 HTML 재사용

이미 저장한 KIND HTML은 구조 검사와 단계별 manifest 검사를 모두 통과할 때만 재사용한다.
- 구조 검사는 파일을 UTF-8로 읽고 `<html` 또는 `openDisclsViewer`가 있는지 확인한다. UTF-8로 해석하지 못한 byte는 건너뛰며 파일 자체를 읽지 못하면 정상 HTML로 인정하지 않는다.
- 현재 파일에서 계산한 바이트 수와 SHA-256이 manifest 기준값과 같을 때만 건너뛴다. 파일 내용이 바뀌었으면 해당 HTML을 다시 받는다.
