# 공시 처리 공통 계약

공시 파이프라인이 공유하는 작업공간, 게시, 복구와 식별자 규칙이다.

## 작업공간과 공통 식별자

### 파일과 저장 형식

- `<data_root>`를 공시 작업공간 루트로 사용하면 각 단계의 기본 입력과 출력을 아래 폴더에 저장한다.
- 화면이 별도 경로를 받는 작업은 작업공간 밖의 입력·출력 경로도 실행 요청으로 지정할 수 있다.
- 어느 루트를 선택하더라도 단계별 하위 폴더, 파일명과 상대 배치는 아래 구조를 바꾸지 않는다. `06-sections`는 04·05단계와 같이 현재 소유 모드 폴더 아래에 연도 폴더를 두며, 이전 모드 폴더나 단계 루트의 연도 폴더로 우회하지 않는다.
- 실행 요청과 API 응답은 실제 경로를 전달할 수 있지만 저장 결과 JSON에는 절대 입력·출력 디렉터리를 기록하지 않는다. 파일 연결에는 결과 JSON 위치 기준의 상대 경로나 내용 fingerprint를 사용한다.

#### `<data_root>`

- `disclosure-workspace.json`은 공시 작업공간 설정을 저장한다.
- `01-list`는 KIND 조건검색 응답과 다운로드 metadata를 저장한다.
- `02-table`은 연도별 공시 SQLite와 변환 manifest를 저장한다.
- `03-filter`는 mode별 조건검색 filter와 선택 결과를 저장한다.
- `04-external-html-download`는 KIND 외부 HTML과 원본 연결 manifest를 저장한다.
- `04-external-html-compress`는 압축한 문서 선택 정보를 저장한다.
- `05-internal-html-download`는 KIND 본문 HTML과 원본 연결 manifest를 저장한다.
- `06-sections`는 조건검색 필터 mode별 목차 HTML을 `<mode>/<YYYY>/<acpt_no>.html`로 저장한다. `06-sections/<YYYY>/`는 허용하지 않는다.
- `07-converted`는 mode별 파싱 결과를 저장한다.
- `09-disclosure-graph`는 공시 graph를 저장한다.

```text
<data_root>/
├── disclosure-workspace.json
├── 01-list/
│   └── <YYYYMMDD>_<YYYYMMDD>/
│       ├── *_post_page_*.body
│       ├── kind_workflow.input.json
│       └── kind_workflow.checkpoint.json
├── 02-table/
│   ├── <YYYY>.sqlite
│   └── sqlite_manifest.json
├── 03-filter/
│   └── <mode>/
│       ├── filter.json
│       └── filtered.json
├── 04-external-html-download/
│   └── <mode>/
│       ├── <YYYY>/
│       │   └── <acpt_no>.html
│       └── kind_disclosure_html_manifest.json
├── 04-external-html-compress/
│   └── <mode>/
│       └── compressed-external-html.json
├── 05-internal-html-download/
│   └── <mode>/
│       ├── <YYYY>/
│       │   └── <acpt_no>.html
│       └── kind_disclosure_html_manifest.json
├── 06-sections/
│   └── <mode>/
│       └── <YYYY>/
│           └── <acpt_no>.html
├── 07-converted/
│   └── <mode>/
│       └── parsed-<mode>.json
└── 09-disclosure-graph/
    └── disclosure-graph.json
```

#### 단계별 작업공간 연결

- `01-list`부터 `07-converted`까지의 저장 폴더는 바로 아래의 `finiq-stage-link.json`으로 다른 작업공간의 같은 이름 폴더를 사용할 수 있다. 04단계는 원본 저장과 압축 결과를 독립적으로 연결할 수 있도록 `04-external-html-download`, `04-external-html-compress` 두 폴더를 사용한다.
- 연결 파일이 없는 단계는 `<data_root>` 아래의 로컬 단계 폴더를 사용한다.
- 연결된 단계의 읽기와 쓰기는 모두 대상 작업공간에서 수행한다. 연결 오류가 나도 로컬 단계 폴더로 우회하지 않는다.
- 연결된 단계에서는 저장 설정에 남아 있는 기존 명시 경로보다 연결 대상 경로를 우선한다. 연결되지 않은 단계의 명시 경로 동작은 유지한다.
- 연결을 추가할 때 대상 작업공간 아래에 같은 이름의 단계 폴더가 없으면 생성한다. 대상 단계가 다시 연결 파일을 포함하는 연쇄 연결은 허용하지 않는다.
- `target_workspace`가 상대 경로이면 선택한 `<data_root>`를 기준으로 해석한다.

```json
{
  "format": "finiq_stage_link_v1",
  "schema_version": 1,
  "target_workspace": "/Volumes/HDD/database-B"
}
```

예를 들어 `<data_root>/01-list/finiq-stage-link.json`이 위 작업공간을 가리키면 01단계의 실제 입출력 경로는 `/Volumes/HDD/database-B/01-list`가 된다. 다른 단계는 각각 연결 파일이 있을 때만 같은 방식으로 전환한다.

각 작업은 실제로 읽거나 쓰는 단계의 연결만 해석한다. 따라서 사용하지 않는 단계의 연결이 끊겨 있어도 현재 작업은 계속할 수 있으며, 끊어진 연결은 해당 단계를 사용하는 작업에서만 오류가 된다. 예를 들어 공시원문 목차 검사는 05단계만 확인하고, 목차 저장은 05·06단계만 확인한다.

각 01-07 세부 페이지의 `단계별 저장 위치`에서 연결을 관리한다. `공시원문 외부 저장`은 저장·압축 폴더를 따로 표시하고, `공시 자동화`는 여덟 폴더를 함께 표시한다. 대상 작업공간 루트를 선택하며, 연결을 해제해도 대상 데이터는 옮기거나 지우지 않는다.

### 식별자

KIND와 DART의 모든 식별자는 로마자를 포함할 수 있는 텍스트다. 숫자로 변환하거나 숫자 형식으로 제한하지 않는다.

#### KIND

- `company_id`는 회사 링크가 있는 공시에서 기업을 구분한다. 회사 링크가 없는 공시에는 `company_id`가 없을 수 있다.
- `acpt_no`와 `doc_no`는 문서를 구분한다.
- `company_cell_text`는 KIND 회사 칸의 원문 표시값이며 식별자가 아니다.

#### DART

- `corp_code`와 `stock_code`는 기업을 구분한다.
- `rcept_no`는 문서를 구분한다.

## 공통 실행 규칙

### 단계 결과 게시

완성된 단계 결과만 현재 결과 위치에 게시한다.

- 각 단계는 해당 세부 페이지와 같은 공식 폴더에 결과를 게시한다.

### 공시 자동화

선택한 1~7단계를 번호 순서대로 실행한다.

- 단계가 끝나면 실행 상태에 완료 기록을 남긴다.
- 각 단계는 세부 페이지와 같은 실행 함수와 공식 입출력 경로를 사용한다. 자동화 전용 단계 산출물이나 별도 처리 규칙은 두지 않는다.
- 03단계는 프리셋 원본의 완료·중단 결과와 검사 완료 위치를 다음 실행 입력으로 전달한다.

### KIND 다운로드 경로

04·05단계는 직접 연결 하나와 `kind_proxy_urls`에 등록한 로컬 프록시를 함께 사용한다.

- 프록시는 중복되지 않은 `http://127.0.0.1:<port>` 또는 `http://localhost:<port>` 형식이어야 하며 현재 CPU 개수보다 하나 적은 수까지 등록할 수 있다.
- 프록시가 없으면 직접 연결만 사용한다. 원격 프록시와 인증정보가 포함된 URL은 허용하지 않는다.
- 실제 경로 수는 대상 수와 `max_workers`를 넘지 않는다. worker는 경로별로 나누되 합계가 `max_workers`와 같아야 한다.
- 각 경로는 별도 HTTP 세션과 요청 제한 상태를 유지한다. 모든 연도의 대상을 한 실행에서 처리해 연도 경계에서 제한을 초기화하지 않는다.

### HTML 원본 연결과 재사용

저장한 HTML은 같은 `acpt_no`의 원본 공시와 manifest로 연결하고, 구조와 기준값을 검증해 재사용한다.

- 원본 JSON에서 같은 `acpt_no`의 공시를 찾아 manifest metadata로 사용한다. 찾지 못하면 manifest를 만들지 않고 요청 전체를 실패 처리한다.
- 구조 판별과 SHA-256 계산은 파일을 한 번 순차적으로 읽은 결과를 공유한다.

### 파생 필터의 HTML 재사용

파생 필터는 상위 기본 필터가 소유한 HTML과 manifest를 접수번호 부분집합으로 검증해 재사용하며 별도 출력을 만들지 않는다.

- 파생 필터가 stale이거나 `parent_result_fingerprint`가 현재 상위 결과와 다르거나, 상위 산출물이 없거나 미완료·손상 상태이면 실패 처리한다.
- 상위 폴더의 다른 파일은 대상 외로 보지 않는다. 부분집합에 원문이 없으면 미저장 건수로 보고하고, 손상·해시 불일치와 함께 재사용하지 않는다.
- 파생 필터 검사에서는 KIND를 다시 요청하지 않는다.

### HTML manifest

- 파일별 `source_size_bytes`와 `source_sha256`을 기록한다.
- `format`이 `finiq_disclosure_html_manifest_v2`인 manifest는 입력 JSON 전체의 `source_fingerprint`를 기록하지 않고 접수번호별 `source_sha256`로 재사용을 판정한다. 필터만 다시 실행했다는 이유로 기존 HTML을 무효화하지 않는다.
- `finiq_disclosure_html_manifest_v1`은 읽기만 지원하며, 이 형식에서만 `source_fingerprint`를 비교한다.

## 기존 HTML 확인

### 기준 해시 만들기

기존 외부 HTML이나 본문 HTML에 바이트 수와 SHA-256 기준값이 없어 작업이 멈췄을 때 이 절차를 따른다.

1. 멈춘 단계가 `공시원문 외부 저장`인지 `공시원문 내부 저장`인지 확인한다.
2. 현재 HTML이 믿을 수 있는 원본인지 직접 확인한다.
3. 외부 HTML이면 `현재 외부 HTML 신뢰`, 본문 HTML이면 `현재 내부 HTML 신뢰` 체크박스를 고른다.
4. `기준 해시 생성`을 누르고 작업이 끝날 때까지 기다린다.
5. 작업이 끝나 화면에 저장 범위가 다시 표시되면 `기준 없음`이 0건이고 `해시 확인`이 기존 HTML 건수와 같은지 확인한다.
6. 다운로드 `실행`을 누르고 나머지 작업이 이어지는지 확인한다.

## 공통 예외와 복구

### 실행 중단

#### 단계별 작업공간 연결 오류

- 연결 파일 형식이나 schema version이 다르면 실패 처리한다.
- 대상 작업공간이 없으면 실패 처리한다.
- UI에서 연결을 추가하거나 변경할 때 로컬 단계 폴더에 기존 데이터가 있으면 실패 처리하고 데이터를 자동으로 이동하지 않는다.

### 복구 동작

#### 비동기 작업 상태

읽을 수 없는 작업 상태를 성공으로 표시하지 않는다.

- 상태 조회가 `404`를 반환하면 저장한 작업 ID를 지운다.
- 결과 본문, 실패 이유나 완료 결과를 읽지 못하면 성공으로 처리하지 않는다.
- 서버가 오류 알림을 보내거나 결과 없이 전송을 끝내면 실패 처리한다.
- 서버가 실패 이유를 보내지 않으면 `Job failed`를 표시한다.
- 브라우저 저장 공간을 읽지 못하면 저장된 작업이 없는 것으로 본다. 저장 공간을 바꾸지 못해도 현재 작업 확인은 계속한다.

#### 단계 결과 불일치

완료 기록이나 결과 파일이 현재 상태와 다르면, 첫 불일치 단계부터 필요한 후속 단계를 번호 순서대로 다시 실행한다.

#### worker 기본값

CPU 수를 확인하지 못하면 worker 1개로 시작한다.

#### 설정 저장 실패

입력값은 화면에 남지만 서버 설정은 바뀌지 않았을 수 있다.

#### 기준값 없는 기존 HTML

- 사용자가 확인한 파일만 기준값을 기록한다.
- 기준 해시는 현재 있고 구조 검사를 통과한 대상에만 만든다. 아직 없는 대상은 정상 다운로드에서 받는다.
- 바이트 수와 SHA-256 기준값이 없으면 사용자가 확인할 때까지 작업을 멈춘다.

### 설정 오류

#### 자동화 설정

저장한 설정이 JSON이 아니거나 현재 형식이 아니면 임의로 고치지 않고 화면 열기를 실패 처리한다.

#### 공통 설정

- 공통 설정을 가져오지 못하면 실패 처리한다.
- worker 수가 양의 정수가 아니면 실패 처리한다.
- 저장 경로를 읽을 수 없거나 작업 기록 보존 시간이 양의 정수가 아니면 실패 처리한다.

### 조건부 동작

#### 저장 경로 선택

- 화면에서는 작업공간 디렉토리만 고른다. 저장 경로는 표준 DB 구조를 따른다. 입력/저장 경로를 따로 두는 것은 코드나 설정에서만 가능하며, 우측 설정 UI에는 노출하지 않는다.

#### 비동기 작업 이어받기

- 브라우저에 작업 ID가 남아 있으면 화면을 다시 열었을 때 같은 작업의 상태를 확인한다.

#### 단계별 자동화 실행

- 03단계부터 실행하는 계획은 저장된 `조건검색 프리셋`을 지정해야 한다. 자동화의 변환 유형·조건이 프리셋과 다르면 실행하지 않는다.

#### 기존 HTML 재사용

- 구조 검사는 파일을 UTF-8로 읽고 `<html`, `openDisclsViewer`, 또는 `<P>`로 시작해 `<TABLE>`을 포함하는 본문 조각인지 확인한다. 해석할 수 없는 byte는 건너뛰며 파일 자체를 읽지 못하면 정상 HTML로 인정하지 않는다.
- 현재 파일에서 계산한 바이트 수와 SHA-256이 manifest 기준값과 같을 때만 건너뛴다. 파일 내용이 바뀌었으면 해당 HTML을 다시 받는다.

## 공통 화면과 서비스 계약

### 작업공간

- 설정 조회와 일부 단계 자동화는 실제로 사용하는 단계 경로만 해석한다. 사용하지 않는 단계의 손상된 연결은 연결 상태 검사에는 오류로 남기되 다른 단계의 설정 조회나 실행을 막지 않는다.

### 비동기 작업

- `04-external-html-download`와 `05-internal-html-download` 취소는 이미 저장한 파일을 남기고 취소 상태를 돌려준다.
- worker 수는 양의 정수여야 한다. 기능 문서가 다른 기본값을 밝히면 그 값을 따른다.
- 실행 중인 작업 snapshot은 서버 기준 전체 경과시간과 마지막 상태·로그 갱신 뒤 경과시간을 제공한다.
- 상태 조회가 정상인 동안 10초 이상 새 로그가 없으면 화면은 작업 중단으로 단정하지 않고 무진행 시간을 표시한다.

### 기존 데이터 검토

- 번호가 붙은 01~07 화면은 페이지 진입이나 입력 변경만으로 기존 데이터 검사를 시작하지 않는다.
- 사용자가 `검사하기` 또는 해당 실행 동작을 눌렀을 때만 현재 입력에 대한 검사를 시작한다.
- 경로·조건·실행 설정이 바뀌면 이전 판정을 지우고, 늦게 도착한 이전 입력의 응답을 새 입력의 근거로 사용하지 않는다.
- 검사 결과를 받으면 같은 컨트롤에 `정상` 또는 `사용 불가` 판정을 표시하고, 해당 판정을 누르면 같은 입력을 다시 검사한다.
- 요청이나 비동기 작업이 검사 결과 없이 실패하면 오류를 표시하고, `사용 불가` 판정을 누르면 같은 입력을 다시 검사한다.
- 외부·내부 HTML 정리 검사의 삭제 확인값은 대상·삭제 후보의 크기, 수정 시각과 파일 식별자를 고정한다. 삭제 전 값이 달라지거나 출력 트리에 symbolic link가 있으면 삭제하지 않고 다시 검사한다.

### 화면 표시

- 공시 화면은 빈 값을 `-`로 표시하고 숫자 `0`은 그대로 표시한다.
- 긴 파일 경로는 마지막 네 부분만 남기고 앞을 `.../`로 줄인다. 실제 경로와 저장 결과는 바꾸지 않는다.
- 진행 내역과 오류 예시는 화면별로 정한 개수만 보여 준다. 전체 개수와 성공·실패 판단은 줄이지 않는다.

### 진행 내역

- 공시 자동화와 06 공시원문 목차 분리 화면은 우측 설정의 `진행 확인 간격 (건)`을 실행 요청에 전달한다. 공시 자동화는 같은 값을 03~07단계의 주기형 진행 로그에 사용하며, 07단계는 중간 저장을 사용하지 않는 실행에서도 이 간격마다 로그를 남긴다.

**공시 공통 상태** — 처음 10줄, 이후 최근 80줄

**공시 자동화** — 최근 30줄

**외부·본문 HTML 저장** — 최근 100줄

**목차 HTML 저장** — 최근 200줄
