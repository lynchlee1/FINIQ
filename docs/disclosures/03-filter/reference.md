# 제목 조회와 공시 선택

## 기능 범위

- 연도별 SQLite에서 제목 후보를 조회하고, 검색 조건에 맞는 공시를 원문 저장 대상으로 고른다.

## 자료 흐름

- 입력 경로는 `<data_root>/02-table`, 원본 저장 경로는 `<data_root>/03-filter/<workflow-name>.json`이다. 조건, 실행 상태, 완료 결과 또는 중단 결과를 한 JSON에서 관리한다.
- 현재 04단계 연결을 위해 `<data_root>/03-filter/<mode>/filtered.json`도 만든다. 이 파일은 원본 결과에서 만든 파생 전달 파일이다.
```text
<data_root>/
├── 02-table/
│   ├── <YYYY>.sqlite
│   └── sqlite_manifest.json
└── 03-filter/
    ├── <workflow-name>.json       # 조건·상태·결과 원본
    ├── ...
    └── <mode>/filtered.json       # 04단계 호환용 파생 파일
```

## 처리 계약

### 정상 동작

#### SQLite 입력 검증

변환 결과가 원본 행을 빠짐없이 설명하는지 확인한 뒤 조건을 적용한다.
- SQLite와 manifest는 [연도별 SQLite 변환](../02-table/reference.md)의 검사를 통과해야 한다.

#### 증분 검색 입력 범위 확정

같은 조건으로 이미 완료한 02단계 행을 반복 검색하지 않는다.
- 완료 결과의 원본 검사 건수를 다음 실행의 시작 위치로 사용한다.
- 02단계 원본 건수가 이전에 확인한 건수 이상일 때만 그 시작 위치 뒤에 추가된 새 행을 검색한다.
- 이 규칙은 현재 실행이 받을 SQLite 행의 범위만 정한다. 조건 검색은 이 범위에서 일치하는 공시를 고른다.

#### 증분 입력 경계 정책

장기간 누적 작업에서 다시 확보할 수 있는 입력 정보만으로 증분 시작 위치를 정한다.
- 운영 과정에서 과거 정정·오래된 공시를 원본에 계속 보관했고 삭제 사례를 찾지 못했다는 전제에서 원본 건수 감소를 무결성 실패로 판단한다.
- 새 기간은 기존 기간 뒤에 추가되고 02단계가 기존 행 순서를 유지한다는 운영 전제를 사용한다. 과거 기간을 끼워 넣거나 기존 행 순서를 바꾸는 갱신은 증분 실행 대상이 아니다.
- 과거 전 구간을 다시 다운로드하지 않으므로 현재 데이터만으로는 과거 멤버십 해시를 제대로 재검증할 수 없다. 멤버십 해시는 저장하지 않고 건수로 검증한다.
- 이 정책은 건수가 같은 원본 교체를 식별하지 못한다. 해당 변경이 의심되면 02단계 데이터베이스를 초기화하고 01단계부터 다시 실행한다.

#### 조건 검색

원문을 저장할 공시를 필터링한다.
- 시장, 공시일, 회사명, 제출인과 제목을 사용한 조건식을 작성한다.
- `acpt_no`는 빈 값이 아닌 텍스트로 읽으며 로마자도 허용한다.
- 조건과 일치한 항목 중 `acpt_no`가 같은 항목은 같은 공시로 보고 먼저 읽은 항목만 남긴다.
- 결과에는 조건식, 원본·중복·선택·반환 공시 건수와 고른 공시 접수번호를 기록한다.

#### 제목 후보 조회

연도별 SQLite에 같은 조건을 적용하고 원문 제목별 공시 건수를 조회한다.
- 필터 결과 파일을 훑지 않고 `sqlite_manifest.json`이 가리키는 SQLite를 직접 조회한다.
- 제목별 `COUNT(DISTINCT acpt_no)`를 합쳐 `finiq_disclosure_title_search_v1` 결과를 만든다.
- 결과에는 원본 공시 수, 일치 공시 수, 제목 수와 제목별 공시 수를 기록한다.
- 조회 결과는 작업 상태에만 보관하며 `03-filter` 파일을 만들거나 바꾸지 않는다.

#### 단일 JSON 상태·결과 저장

조건 파일과 결과 파일의 생명주기가 어긋나지 않게 한다.
- 원본 JSON 하나에 조건만 있는 `ready`, 검색 중인 `running`, 일부 결과가 있는 `interrupted`, 전체 결과가 있는 `completed`, 오류가 기록된 `failed` 상태를 저장한다.
- 완료 목록은 `result`, 중단된 증분 목록은 `pending.result`에 저장한다.
- 실행 중에는 원본을 바꾸지 않고 같은 폴더의 숨김 임시 JSON에서 상태와 증분 결과를 만든다.
- 기존 결과, 중단 결과, 새 결과를 임시 JSON에서 합친다.

#### 검색 문자열 정리

괄호 표기가 다른 검색값을 같은 기준으로 비교한다.
- `clean_search=true`인 조건은 검색 대상과 입력값에서 괄호와 괄호 안의 내용을 제거한 뒤 비교한다. 닫히지 않은 괄호가 나오면 그 위치부터 끝까지 제거한다.

#### 모드별 전달 파일 저장

현재 04단계가 원본에 병합된 전체 결과를 기존 입력 형식으로 읽게 한다.
- 원본 JSON에 결과를 모두 병합하면 선택한 mode 이름의 폴더인 `<data_root>/03-filter/<mode>/filtered.json`에 파생 전달 파일을 저장한다.
- `03-filter` 바로 아래에는 `filtered.json`을 만들지 않는다.
- 별도 결과 경로도 파일이 아니라 폴더를 지정하고 그 아래에 `<mode>/filtered.json`을 만든다.

#### 건수 기반 결과 무결성 확인

증분 검색을 마친 뒤 분모·검사 완료 건수·분자가 실제 결과와 일치하는지 확인한다.
- 결과에는 적용한 조건, 원본 공시 건수, 검색 시작 위치, 검색 대상 건수(분모), 검사 완료 건수와 검색 결과 건수(분자)를 명시한다.
- 저장 직전에 `원본 건수 - 시작 위치 = 검색 대상 건수`, `검사 완료 건수 = 검색 대상 건수`, `결과 건수 = 실제 결과 배열 길이`를 확인한다.
- 모든 건수 검증을 통과한 완료 결과만 원본 JSON으로 원자적으로 교체한다.

### 복구 동작

#### 중단된 검색 이어받기

이전 실행이 중단된 뒤 이미 검사한 증분 행을 반복하지 않고 검색을 계속한다.
- 중단 결과가 있으면 중단 전에 검사한 행 수까지 시작 위치에 더해 나머지 새 행을 검색한다.

### 중단 조건

#### SQLite 입력 오류가 나면 공시 선택 중단

원본 공시와 선택 결과가 달라질 수 있는 SQLite를 사용하지 않는다.
- `<data_root>/02-table/sqlite_manifest.json`이 없거나 FINIQ SQLite manifest 형식이 아니면 실패 처리한다.
- [연도별 SQLite 변환](../02-table/reference.md)에 적은 조건을 검증하지 못하면 실패 처리한다.
- 입력은 `data_root`로 지정한 작업공간의 `02-table/sqlite_manifest.json`만 사용한다.
- manifest가 가리키는 SQLite 조각이 없거나 필수 열이 없으면 실패 처리한다.
- manifest의 연도별 저장 행 수 합과 전체 저장 행 수가 다르거나, 실제 SQLite 행 수와 manifest의 저장 행 수가 다르면 실패 처리한다.
- 페이지별 또는 전체 원본 행 수가 저장 행 수와 중복 행 수의 합과 다르면 실패 처리한다.
- 현재 원본 공시 건수가 완료 또는 중단 결과에 저장된 이전 확인 건수보다 작으면 즉시 실패 처리한다. 오류는 02단계 데이터베이스를 초기화하고 01단계부터 다시 실행하도록 안내한다.

#### 검색 조건 오류가 나면 실패 처리

해석할 수 없는 조건을 임의로 바꾸지 않는다.
- 제목 조건 결합 방식이 `or` 또는 `and`가 아니면 실패 처리한다.
- `filter_blocks`가 목록이 아니면 실패 처리한다.
- 조건 블록이 객체가 아니거나 field·연산자·연결자·괄호 수·boolean 제어값이 누락되거나 유효하지 않으면 실패 처리한다.
- `between` 연산자에 두 값을 지정하지 않으면 실패 처리한다.

#### 전달 폴더 오류가 나면 실패 처리

파생 전달 파일이 서로 덮어쓰거나 mode를 알 수 없는 상태를 막는다.
- mode가 없거나 폴더 이름에 사용할 수 없는 값이면 실패 처리한다.
- 결과 경로가 없거나 JSON 파일 경로를 직접 지정하면 실패 처리한다.

#### 공시 식별자 오류가 나면 공시 선택 중단

공시를 정확하게 중복 판정할 수 없으면 결과를 만들지 않는다.
- 공시에 `acpt_no`가 없으면 실패 처리한다.

#### 날짜 검색 대상 오류가 나면 실패 처리

날짜 조건을 적용하는 중 비교값을 확정할 수 없는 공시를 임의로 포함하거나 제외하지 않는다.
- 날짜 조건을 사용한 공시에 공시일이 없으면 실패 처리한다.

#### 워크플로우 실행 중단 기록

처리 중 중단된 실행을 완료 결과로 저장하지 않고 이전 원본을 보존한다.
- 실행 중 클라이언트 연결이 끊기면 지금까지 검사한 증분 결과를 `interrupted`로 저장한다. 검사 전에 끊겨 부분 결과가 없으면 원본은 실행 전 상태를 유지한다.
- 일반 실행 오류는 원본의 기존 완료·중단 결과를 유지한 채 `failed` 상태와 오류를 기록한다.

#### 증분 결과 무결성 오류가 나면 공시 선택 중단

이어지지 않는 증분 구간이나 실제 데이터와 맞지 않는 병합 결과를 원본으로 저장하지 않는다.
- 증분 구간이 이전 검사 완료 위치와 이어지지 않거나 병합 뒤 분모·검사 완료 건수·분자가 실제 데이터와 다르면 같은 초기화 오류로 실패 처리한다.

## 화면과 서비스 계약

### 정상 동작

#### 화면 검색 문자열 정리

저장 결과를 바꾸지 않고 화면의 제목 후보를 검색 조건과 같은 기준으로 묶는다.
- 괄호 안 내용만 다른 제목은 후보 하나로 묶어 표시한다.

#### 화면 변환 유형 적용

변환 유형을 다시 고르지 않게 한다.
- 화면은 선택한 조건검색 프리셋의 변환 유형을 사용한다.

#### 조건검색 워크플로우 선택

저장한 검색 조건을 목록에서 찾아 다시 입력으로 사용한다.
- 선택 목록은 `03-filter` 바로 아래의 조건검색 프리셋만 읽는다.
- 파일 이름을 프리셋 이름으로 사용하며, 선택하면 조건을 바로 적용한다.
- 이전 형식의 결과 파일은 프리셋 목록에서 제외하며 자동으로 바꾸지 않는다.

#### 조건검색 워크플로우 저장

검색 조건을 이름을 붙여 저장하고 변경 여부에 맞는 실행 상태를 만든다.
- `프리셋 이름`으로 처음 저장하면 변환 유형과 조건을 기록하고 상태를 대기로 만든다.
- 기존 프리셋과 변환 유형·조건이 같으면 완료·중단 결과를 유지하고, 둘 중 하나가 달라지면 상태와 결과를 대기로 초기화한다.

#### 조건검색 워크플로우 화면 공유

관련 화면에서 같은 조건검색 프리셋 목록을 제공한다.
- 공시내역 필터링 화면에는 수동 `불러오기` 버튼을 표시하지 않는다.
- 공시내역 필터링, 공시원문 변환과 공시 자동화는 같은 프리셋 목록을 사용한다.

#### 조건검색 워크플로우 실행 입력

선택한 프리셋을 조건검색과 자동화의 실행 입력으로 사용한다.
- 저장한 변환 유형과 조건이 화면 입력과 같을 때만 검색을 시작한다.
- 공시 자동화는 03단계 또는 후속 단계를 실행할 때 선택한 프리셋 이름도 실행 설정에 기록한다.

#### 실행 상태 전이 기록

화면을 다시 열어도 작업이 어디까지 진행됐는지 보여 준다.
- 작업은 조건 입력, 데이터베이스 검색, 결과 기록 순서로 진행한다.
- 상태는 대기 `ready`, 실행 중 `running`, 중단 `interrupted`, 완료 `completed`, 실패 `failed`로 기록한다.

#### 실행 기록

실행 상태를 화면에서 확인할 수 있는 metadata를 기록한다.
- 검색과 결과 기록의 시작·완료·중단 시각, 입력 경로, 원본 JSON 경로와 요약을 기록한다.

#### 실행 중 워크플로우 보호

실행 중인 조건과 결과가 다른 요청으로 바뀌지 않게 한다.
- 실행 중인 워크플로우는 동시에 다시 실행하거나 저장·이름변경·삭제할 수 없다.

#### 제목 조회 작업 이어받기

화면을 옮겼다가 돌아와도 실행 중인 제목 조회를 계속 확인한다.
- 제목 조회는 비동기 작업으로 실행하며 작업 ID, 진행 내역과 완료 결과를 보관한다.
- 취소 요청을 받으면 SQLite 조회를 끝내고 취소 상태를 기록한다.

### 중단 조건

#### 진행 알림 오류가 나면 중단

읽을 수 없는 진행 상태를 정상으로 표시하지 않는다.
- 진행 단위나 숫자가 없거나 형식이 다르면 실패 처리한다.

#### 워크플로우 파일 오류가 나면 실패 처리

손상된 프리셋을 임의로 고치거나 결과 파일로 대신하지 않는다.
- 프리셋에는 변환 유형, 전체 상태, 세 단계 상태, 조건 목록, 완료 또는 중단 상태에 맞는 결과와 무결성 건수가 있어야 한다.
- 프리셋이 손상됐거나 필요한 상태가 없으면 실패 처리한다.
- 파일명에 경로 구분자를 사용하거나 저장된 조건과 실행 요청 조건이 다르면 실행을 실패 처리한다.
