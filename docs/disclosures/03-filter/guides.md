# 제목 조회와 공시 선택

## 목적

- 연도별 SQLite에서 제목 후보를 조회하고 검색 조건에 맞는 공시를 원문 저장 대상으로 고른다.

공시 자동화 03단계에서 조건검색 워크플로우를 만들고 실행한다.

## 핵심 기능

### SQLite 입력 검증

변환 결과가 원본 행을 빠짐없이 설명하는지 확인한 뒤 조건을 적용한다.

### 증분 검색 입력 범위 확정

같은 조건으로 이미 완료한 02단계 행을 반복 검색하지 않는다.

- 완료 결과의 원본 검사 건수를 다음 실행의 시작 위치로 사용한다.

- 이 규칙은 현재 실행이 받을 SQLite 행의 범위만 정한다. 조건 검색은 이 범위에서 일치하는 공시를 고른다.

### 조건 검색

원문을 저장할 공시를 필터링한다.

- 시장, 공시일, 회사명, 제출인과 제목을 사용한 조건식을 작성한다.

- `acpt_no`는 빈 값이 아닌 텍스트로 읽으며 로마자도 허용한다.

- 결과에는 조건식, 원본·중복·선택·반환 공시 건수와 고른 공시 접수번호를 기록한다.

### 제목 후보 조회

연도별 SQLite에 같은 조건을 적용하고 원문 제목별 공시 건수를 조회한다.

- 필터 결과 파일을 훑지 않고 `sqlite_manifest.json`이 가리키는 SQLite를 직접 조회한다.

- 제목별 `COUNT(DISTINCT acpt_no)`를 합쳐 `finiq_disclosure_title_search_v1` 결과를 만든다.

- 결과에는 원본 공시 수, 일치 공시 수, 제목 수와 제목별 공시 수를 기록한다.

- 조회 결과는 작업 상태에만 보관하며 `03-filter` 파일을 만들거나 바꾸지 않는다.

### 단일 JSON 상태·결과 저장

조건 파일과 결과 파일의 생명주기가 어긋나지 않게 한다.

- 완료 목록은 `result`, 중단된 증분 목록은 `pending.result`에 저장한다.

- 기존 결과, 중단 결과, 새 결과를 임시 JSON에서 합친다.

- 실행 중에는 원본을 바꾸지 않고 같은 폴더의 숨김 임시 JSON에서 상태와 증분 결과를 만든다.

### 검색 문자열 정리

괄호 표기가 다른 검색값을 같은 기준으로 비교한다.

### 모드별 전달 파일 저장

현재 04단계가 원본에 병합된 전체 결과를 기존 입력 형식으로 읽게 한다.

- 파생 전달 파일의 저장 경로는 `<data_root>/03-filter/<mode>/filtered.json`이다. `<mode>`에는 선택한 mode 이름을 쓴다.

- 별도 결과 경로도 파일이 아니라 폴더를 지정하고 그 아래에 `<mode>/filtered.json`을 만든다.

### 건수 기반 결과 무결성 확인

증분 검색을 마친 뒤 분모·검사 완료 건수·분자가 실제 결과와 일치하는지 확인한다.

- 결과에는 적용한 조건, 원본 공시 건수, 검색 시작 위치, 검색 대상 건수(분모), 검사 완료 건수와 검색 결과 건수(분자)를 명시한다.

- 저장 직전에 `원본 건수 - 시작 위치 = 검색 대상 건수`, `검사 완료 건수 = 검색 대상 건수`, `결과 건수 = 실제 결과 배열 길이`를 확인한다.

- 모든 건수 검증을 통과한 완료 결과만 원본 JSON으로 원자적으로 교체한다.

## 사용과 화면

### 화면 검색 문자열 정리

저장 결과를 바꾸지 않고 화면의 제목 후보를 검색 조건과 같은 기준으로 묶는다.

- 괄호 안 내용만 다른 제목은 후보 하나로 묶어 표시한다.

### 화면 변환 유형 적용

변환 유형을 다시 고르지 않게 한다.

- 화면은 선택한 조건검색 프리셋의 변환 유형을 사용한다.

### 조건검색 워크플로우 선택

저장한 검색 조건을 목록에서 찾아 다시 입력으로 사용한다.

- 선택 목록은 `03-filter` 바로 아래의 조건검색 프리셋만 읽는다.

### 조건검색 워크플로우 저장

검색 조건을 이름을 붙여 저장하고 변경 여부에 맞는 실행 상태를 만든다.

- 새 프리셋의 초기 상태는 대기이며 변환 유형과 조건을 함께 기록한다.

### 조건검색 워크플로우 화면 공유

관련 화면에서 같은 조건검색 프리셋 목록을 제공한다.

- 공시내역 필터링 화면에는 수동 `불러오기` 버튼을 표시하지 않는다.

- 공시내역 필터링, 공시원문 변환과 공시 자동화는 같은 프리셋 목록을 사용한다.

### 조건검색 워크플로우 실행 입력

선택한 프리셋을 조건검색과 자동화의 실행 입력으로 사용한다.

- 03단계와 후속 단계의 실행 설정에는 선택한 프리셋 이름이 들어간다.

### 실행 상태 전이 기록

화면을 다시 열어도 작업이 어디까지 진행됐는지 보여 준다.

- 작업은 조건 입력, 데이터베이스 검색, 결과 기록 순서로 진행한다.

### 실행 기록

실행 상태를 화면에서 확인할 수 있는 metadata를 기록한다.

- 검색과 결과 기록의 시작·완료·중단 시각, 입력 경로, 원본 JSON 경로와 요약을 기록한다.

### 실행 중 워크플로우 보호

실행 중인 조건과 결과가 다른 요청으로 바뀌지 않게 한다.

### 제목 조회 작업 이어받기

화면을 옮겼다가 돌아와도 실행 중인 제목 조회를 계속 확인한다.

- 제목 조회는 비동기 작업으로 실행하며 작업 ID, 진행 내역과 완료 결과를 보관한다.

- 취소 요청을 받으면 SQLite 조회를 끝내고 취소 상태를 기록한다.
