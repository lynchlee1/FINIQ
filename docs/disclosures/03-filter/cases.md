# 제목 조회와 공시 선택 Cases

## 처리 계약

### 한계

#### 증분 입력 경계

장기간 누적 작업에서는 다시 확보할 수 있는 입력 정보만으로 증분 시작 위치를 정한다.
- 운영 과정에서 과거 정정·오래된 공시를 원본에 계속 보관했고 삭제 사례를 찾지 못했다는 전제에서 원본 건수 감소를 무결성 실패로 판단한다.
- 새 기간은 기존 기간 뒤에 추가되고 02단계가 기존 행 순서를 유지한다는 운영 전제를 사용한다. 과거 기간을 끼워 넣거나 기존 행 순서를 바꾸는 갱신은 증분 실행 대상이 아니다.
- 과거 전 구간을 다시 다운로드하지 않으므로 현재 데이터만으로는 과거 멤버십 해시를 제대로 재검증할 수 없다. 멤버십 해시는 저장하지 않고 건수로 검증한다.
- 이 정책은 건수가 같은 원본 교체를 식별하지 못한다. 해당 변경이 의심되면 02단계 데이터베이스를 초기화하고 01단계부터 다시 실행한다.

### 복구 동작

#### 중단된 검색 이어받기

이전 실행이 중단된 뒤 이미 검사한 증분 행을 반복하지 않고 검색을 계속한다.
- 중단 결과가 있으면 중단 전에 검사한 행 수까지 시작 위치에 더해 나머지 새 행을 검색한다.

### 중단 조건

#### SQLite 입력 오류가 나면 공시 선택 중단

원본 공시와 선택 결과가 달라질 수 있는 SQLite를 사용하지 않는다.
- `<data_root>/02-table/sqlite_manifest.json`이 없거나 FINIQ SQLite manifest 형식이 아니면 실패 처리한다.
- 입력은 `data_root`로 지정한 작업공간의 `02-table/sqlite_manifest.json`만 사용한다.
- manifest가 가리키는 SQLite 조각이 없거나 필수 열이 없으면 실패 처리한다.
- manifest의 연도별 저장 행 수 합과 전체 저장 행 수가 다르거나, 실제 SQLite 행 수와 manifest의 저장 행 수가 다르면 실패 처리한다.
- 페이지별 또는 전체 원본 행 수가 저장 행 수와 중복 행 수의 합과 다르면 실패 처리한다.
- 현재 원본 공시 건수가 완료 또는 중단 결과에 저장된 이전 확인 건수보다 작으면 즉시 실패 처리한다. 오류는 02단계 데이터베이스를 초기화하고 01단계부터 다시 실행하도록 안내한다.

#### 검색 조건 오류가 나면 실패 처리

해석할 수 없는 조건을 임의로 바꾸지 않는다.
- 제목 조건 결합 방식이 `or` 또는 `and`가 아니면 실패 처리한다.
- `filter_blocks`가 목록이 아니면 실패 처리한다.
- 조건 블록이 객체가 아니거나 field·연산자·연결자·괄호 수·boolean 제어값이 누락되거나 유효하지 않으면 실패 처리한다.
- `between` 연산자에 두 값을 지정하지 않으면 실패 처리한다.

#### 전달 폴더 오류가 나면 실패 처리

파생 전달 파일이 서로 덮어쓰거나 mode를 알 수 없는 상태를 막는다.
- mode가 없거나 폴더 이름에 사용할 수 없는 값이면 실패 처리한다.
- 결과 경로가 없거나 JSON 파일 경로를 직접 지정하면 실패 처리한다.

#### 공시 식별자 오류가 나면 공시 선택 중단

공시를 정확하게 중복 판정할 수 없으면 결과를 만들지 않는다.
- 공시에 `acpt_no`가 없으면 실패 처리한다.

#### 날짜 검색 대상 오류가 나면 실패 처리

날짜 조건을 적용하는 중 비교값을 확정할 수 없는 공시를 임의로 포함하거나 제외하지 않는다.
- 날짜 조건을 사용한 공시에 공시일이 없으면 실패 처리한다.

#### 워크플로우 실행 중단 기록

처리 중 중단된 실행을 완료 결과로 저장하지 않고 이전 원본을 보존한다.
- 실행 중 클라이언트 연결이 끊기면 지금까지 검사한 증분 결과를 `interrupted`로 저장한다. 검사 전에 끊겨 부분 결과가 없으면 원본은 실행 전 상태를 유지한다.
- 일반 실행 오류는 원본의 기존 완료·중단 결과를 유지한 채 `failed` 상태와 오류를 기록한다.

#### 증분 결과 무결성 오류가 나면 공시 선택 중단

이어지지 않는 증분 구간이나 실제 데이터와 맞지 않는 병합 결과를 원본으로 저장하지 않는다.
- 증분 구간이 이전 검사 완료 위치와 이어지지 않거나 병합 뒤 분모·검사 완료 건수·분자가 실제 데이터와 다르면 같은 초기화 오류로 실패 처리한다.

## 화면과 서비스 계약

### 한계

#### 이전 형식의 결과 파일

- 이전 형식의 결과 파일은 프리셋 목록에서 제외하며 자동으로 바꾸지 않는다.

### 중단 조건

#### 진행 알림 오류가 나면 중단

읽을 수 없는 진행 상태를 정상으로 표시하지 않는다.
- 진행 단위나 숫자가 없거나 형식이 다르면 실패 처리한다.

#### 워크플로우 파일 오류가 나면 실패 처리

손상된 프리셋을 임의로 고치거나 결과 파일로 대신하지 않는다.
- 프리셋에는 변환 유형, 전체 상태, 세 단계 상태, 조건 목록, 완료 또는 중단 상태에 맞는 결과와 무결성 건수가 있어야 한다.
- 프리셋이 손상됐거나 필요한 상태가 없으면 실패 처리한다.
- 파일명에 경로 구분자를 사용하거나 저장된 조건과 실행 요청 조건이 다르면 실행을 실패 처리한다.

## 조건부 동작

### 증분 검색 입력 범위 확정

- 02단계 원본 건수가 이전에 확인한 건수 이상일 때만 그 시작 위치 뒤에 추가된 새 행을 검색한다.

### 단일 JSON 상태·결과 저장

- 원본 JSON 하나에 조건만 있는 `ready`, 검색 중인 `running`, 일부 결과가 있는 `interrupted`, 전체 결과가 있는 `completed`, 오류가 기록된 `failed` 상태를 저장한다.

### 조건검색 워크플로우 선택

- 파일 이름을 프리셋 이름으로 사용하며 선택하면 조건을 바로 적용한다.

### 조건검색 워크플로우 저장

- 기존 프리셋과 변환 유형·조건이 같으면 완료·중단 결과를 유지하고 둘 중 하나가 달라지면 상태와 결과를 대기로 초기화한다.

### 조건검색 워크플로우 실행 입력

- 저장한 변환 유형과 조건이 화면 입력과 같을 때만 검색을 시작한다.

### 조건 검색

- 조건과 일치한 항목 중 `acpt_no`가 같은 항목은 같은 공시로 보고 먼저 읽은 항목만 남긴다.

### 검색 문자열 정리

- `clean_search=true`인 조건은 검색 대상과 입력값에서 괄호와 괄호 안의 내용을 제거한 뒤 비교한다. 닫히지 않은 괄호가 나오면 그 위치부터 끝까지 제거한다.

### 실행 중 워크플로우 보호

- 실행 중인 워크플로우는 동시에 다시 실행하거나 저장·이름변경·삭제할 수 없다.
