# 유무상증자 파서 로직 규칙

작성일: 2026-07-06

## 결론

`rights_issuance` 파서는 제목으로 증자 유형을 먼저 판정한 뒤, 기존 flat 필드와
타입별 상세 블록을 함께 출력한다.

핵심 판단 순서:

1. 제목에서 `유무상증자`/`무상증자`/`유상증자`를 판정한다.
2. 유무상증자 필드 라벨이나 대상자 헤더가 있는 표 행에서 flat 필드를 추출한다.
3. `mixed`이면 무상증자 섹션 시작점을 찾아 유상/무상 상세 블록을 나눈다.
4. 무상증자에 구조적으로 없는 유상 전용 필드는 `not_applicable`로 둔다.
5. 추출 실패는 예외로 처리하지 않고 `None`, 빈 목록, 0, `field_parse_status`,
   warning에 기록한다.

## 공통 규칙

HTML은 공통 parser에서 복구 파싱하고 table을 `logical_rows`로 정규화한다.
필드 추출에는 `rights_issuance` 전용 추출 대상 table만 사용한다. 추출 대상은
다음 중 하나다.

- 첫 셀에 유무상증자 본문 필드 라벨이 있는 table
- `Ⅰ. 유상증자`/`Ⅱ. 무상증자` 섹션 표시 table
- 첫 행에 `제3자배정 대상자`와 `배정주식수`가 있는 table

정정 이력이나 비교표처럼 관련 단어가 있더라도 위 조건을 만족하지 않으면 추출에
쓰지 않는다.

행/숫자 규칙:

- `row_contains()`: 행 전체 텍스트 또는 공백 제거 텍스트가 모든 검색어를 포함하면 match.
- `row_containing()`: 처음 match된 행만 사용.
- `last_value()`: match된 행의 마지막 셀.
- `parse_int()`: 문자열에서 첫 정수만 읽고 쉼표를 제거. `dash_as_zero=True`이면 `-`와 빈 값은 0.
- 주식 계열 필드는 항상 `보통주식`, `기타주식` 순서로 반환한다.

주식 라벨 정규화:

| 출력 라벨 | 인식 라벨 |
| --- | --- |
| `보통주식` | `보통주식`, `보통주` |
| `기타주식` | `기타주식`, `기타주`, `우선주식`, `우선주`, `종류주식`, `종류주` |

## 타입 판정

제목의 공백을 제거한 뒤 아래 순서로 판정한다. 본문 값은 타입 판정에 쓰지 않는다.

| 제목 문구 | 내부 타입 | 출력 `증자유형` |
| --- | --- | --- |
| `유무상증자` | `mixed` | `유무상증자` |
| `무상증자` | `bonus` | `무상증자` |
| `유상증자` | `paid` | `유상증자` |
| 없음 | `unknown` | `unknown` |

`unknown`이면 strong warning을 먼저 넣고, 나머지 필드 추출은 계속한다.

## 출력 필드

### 공통 필드

| 필드 | 로직 | 실패/주의 |
| --- | --- | --- |
| `correction_families` | 기본 `{}` | 단독 parser는 계산하지 않음 |
| `rcept_no` | 기본 `None` | 단독 parser는 계산하지 않음 |
| `acpt_no` | 파일명 stem에서 `_` 앞의 숫자 prefix | 숫자가 아니면 빈 문자열 |
| `source_file` | `file_path.resolve()` | warning 없음 |
| `mode` | `rights_issuance` | 고정값 |
| `title` | 첫 `SECTION-1` 문단, 없으면 `<title>` | 없으면 타입이 `unknown` |
| `상장시장` | 기본 `None` | 이 parser는 채우지 않음 |
| `raw_tables` | 전체 table 정규화 결과 | 정정 이력 table 포함 |
| `raw_rows` | 전체 `logical_rows` 병합 | 실제 추출에는 전용 포함 조건을 만족한 표 행 사용 |

### flat 비즈니스 필드

| 필드 | 추출 로직 | 실패/status/warning |
| --- | --- | --- |
| `증자유형` | 제목 기반 타입 판정 | 실패하면 `unknown` strong warning |
| `신주의 종류와 수` | `신주의 종류와 수` 행에서 주식 라벨 오른쪽 정수를 읽음 | 양수가 있으면 `parsed`; 명시 0만 있으면 `explicit_zero`; 원천 행이 없으면 strong warning |
| `증자 전 발행주식총수` | `증자전 발행주식총수` 행에서 주식 라벨 오른쪽 정수를 읽음 | stock 필드와 같은 status 규칙 |
| `발행목적` | `자금조달의 목적`과 목적 라벨 행에서 마지막 금액을 읽음. 목적 순서: 시설자금, 영업양수자금, 운영자금, 채무상환자금, 타법인 증권 취득자금, 기타자금 | 0 금액은 목록에서 제외. 무상증자에서 원천이 없으면 `not_applicable`; 그 밖에 원천이 없으면 strong warning |
| `발행가액` | `신주 발행가액` 행에서 주식 라벨 오른쪽 정수를 읽음 | 무상증자에서 원천이 없으면 `not_applicable`; 그 밖에 원천이 없으면 strong warning |
| `기준주가` | `기준주가` 행에서 주식 라벨 오른쪽 정수를 읽음 | 무상증자에서 원천이 없으면 `not_applicable`; 그 밖에 원천이 없으면 strong warning |
| `증자방식` | `증자방식` 행의 마지막 값 | 무상증자에서 없으면 제목을 근거로 `무상증자`를 사용; 그래도 없으면 strong warning |
| `납입일` | `납입일` 행의 마지막 값 | 무상증자에서 없으면 `not_applicable`; 그 밖에 없으면 strong warning |
| `신주권교부예정일` | `신주권교부예정일` 행의 마지막 값 | 없으면 strong warning |
| `상장예정일` | `신주의 상장 예정일` 행의 마지막 값. 공백 제거 매칭으로 `신주의 상장예정일`도 대응 | 없으면 strong warning |
| `발행대상자` | 첫 행에 `제3자배정 대상자`와 `배정주식수`가 있는 표에서 대상자명과 수량을 추출. 후보가 여러 개면 `신주의 종류와 수` 합계와 일치하는 표를 우선 사용 | `-`만 있고 수량이 없으면 `[["-", 0]]`; 표는 있으나 추출값이 없으면 `source_found_empty`; 제3자배정인데 표가 없으면 strong warning |

발행대상자 총계 제거:

- 마지막 행 이름이 공백 분리 토큰 기준 `계`, `합계`, `소계`, `총계` 중 하나이고,
- 대상자 합계가 신주 합계의 2배이며,
- 마지막 행 금액이 신주 합계와 같으면 마지막 행을 제거한다.

### 상세 블록

| 타입 | `유상증자` | `무상증자` | flat 필드 기준 |
| --- | --- | --- | --- |
| `paid` | 생성 | `None` | 전체 rows |
| `bonus` | `None` | 생성 | 전체 rows |
| `mixed` | 생성 | 생성 | 유상 섹션 값 |
| `unknown` | `None` | `None` | 추출 가능한 값만 사용 |

`mixed` 섹션 분리 규칙:

- `무상증자`를 포함하고 `유무상증자`는 포함하지 않는 첫 행을 찾는다.
- 그 앞은 유상 섹션, 그 행부터는 무상 섹션으로 본다.
- 찾지 못하면 유상 섹션은 전체 rows, 무상 섹션은 빈 rows로 둔다.

상세 블록 필드:

| 블록 | 필드 | 로직 |
| --- | --- | --- |
| `유상증자` | `신주의 종류와 수`, `증자 전 발행주식총수`, `발행목적`, `발행가액`, `증자방식`, `납입일`, `신주권교부예정일`, `상장예정일`, `발행대상자` | flat 값을 그대로 사용 |
| `유상증자` | `신주배정기준일` | 유상 섹션에서 해당 행의 마지막 값 |
| `유상증자` | `1주당 신주배정주식수` | 유상 섹션에서 주식 라벨 오른쪽 텍스트를 읽음. 없으면 마지막 값을 보통주식 값으로 사용 |
| `무상증자` | `신주의 종류와 수`, `증자 전 발행주식총수` | 무상 섹션에서 주식 라벨 오른쪽 정수를 읽음. 없으면 0 |
| `무상증자` | `신주배정기준일`, `신주권교부예정일`, `상장예정일` | 무상 섹션에서 해당 행의 마지막 값 |
| `무상증자` | `1주당 신주배정주식수` | 무상 섹션에서 주식 라벨 오른쪽 텍스트를 읽음. 없으면 마지막 값을 보통주식 값으로 사용 |

상세 블록 내부 필드는 별도 `field_parse_status`를 만들지 않는다.

## 경고와 상태

| 출력 필드 | 생성 조건 |
| --- | --- |
| `field_parse_status` | flat 비즈니스 필드 상태가 하나 이상 기록될 때 출력. |
| `parse_warnings` | 타입 판정에 실패하거나 extractor warning이 발생하면 출력. |
| `weak_warning` | 발행대상자 합계 불일치, 자금조달 목적 합계 불일치, 명시적 0 신주 수량. |
| `medium_warning` | `신주의 종류와 수`에서 0이 아닌 주식 종류가 둘 이상. |
| `strong_warning` | 타입 판정 실패 또는 필드 원천을 찾지 못했을 때 사용. |

상태값:

| status | 의미 |
| --- | --- |
| `parsed` | 유효 값을 추출함 |
| `explicit_zero` | 원천은 있으나 값이 `-` 또는 0 |
| `source_not_found` | 정해진 원천을 찾지 못함 |
| `not_applicable` | 해당 타입에 구조적으로 없는 필드 |
| `source_found_empty` | 표는 있으나 추출 가능한 값이 없음 |

일관성 검증:

- `발행대상자` 합계와 `신주의 종류와 수` 합계가 다르면 weak warning.
- `신주의 종류와 수 * 기준주가`와 `발행목적` 합계 차이가 9원을 넘으면 weak warning.
- `신주의 종류와 수`가 명시적으로 모두 0이면 weak warning.
