# Ontology 처리 구조

Ontology 화면은 공시 단계 결과와 주가 자료를 읽어 회사, 사건과 시장 움직임을 함께 살펴보게 한다. 공시 원문을 다시 처리하지 않고 검증을 끝낸 결과만 입력으로 사용한다.

## 자료를 합치는 원칙

같은 회사 ID를 여러 입력에서 찾으면 먼저 읽은 식별값을 유지한다. 빈 값만 뒤 자료로 채우고 badge는 겹치지 않게 합친다. 같은 `acpt_no`를 다시 찾으면 먼저 읽은 공시 한 건을 남긴다.

이 순서는 입력마다 값이 다를 때 결과가 실행 순서에 따라 흔들리지 않게 한다. 각 화면이 허용하는 입력과 결과 구조는 [Ontology 공통 사양](reference.md)에서 찾는다.

## Cache를 다시 만드는 까닭

분류 cache는 원본 signature와 검증 상태가 현재 입력과 맞을 때만 사용한다. 둘 가운데 하나라도 다르면 원본 결과 페이지를 다시 읽는다.

오래된 cache를 억지로 읽으면 빠진 공시나 이전 회사 정보가 정상 결과처럼 보일 수 있다. cache 오류는 자료를 복구해야 한다는 신호일 뿐, 업무값을 다른 원천에서 채워도 된다는 근거가 아니다.

## 병렬 처리와 직렬 복구

회사 분류, 보조 JSON 내보내기와 페이지 검증은 여러 process로 나눌 수 있다. process pool 자체를 만들거나 사용할 수 없는 환경에서는 같은 전체 대상을 직렬로 다시 처리한다.

직렬 복구는 결과 산식이나 입력 범위를 바꾸지 않는다. 정해 둔 runtime 오류에만 적용하며 자료 형식 오류를 감추지 않는다.

## 불완전한 입력

SQLite manifest가 가리키는 조각이 하나라도 없으면 분석을 시작하지 않는다. 일부 조각만 읽은 결과는 전체 자료처럼 해석하기 어렵기 때문이다.

화면에서 비어 있는 입력은 저장한 설정이 있다는 뜻이 아니다. 요청값, 공통 설정과 작업공간 기본값 가운데 무엇을 쓸지는 각 Reference가 정한 우선순위를 따른다.
