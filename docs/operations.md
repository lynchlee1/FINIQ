# 운영 안내

## 기본 원칙

재처리 전에 해당 단계의 `기존 데이터 검토`와 선행 결과의 유효성을 확인한다. stale인 선행 결과는 사용하지 않는다.

- 게시 전에 실패한 작업은 기존 정상 결과를 보존한다.
- 게시가 끝난 뒤 백업이나 임시 파일 정리만 실패했다면 새 결과를 유지하고 정리 경고를 확인한다.
- 경로 연결 오류가 발생해도 로컬 단계로 우회하지 않는다.

## 실패 진단

1. 실패한 단계와 작업공간을 확인한다.
2. 해당 단계 문서에서 입력, 중단 조건, 재실행 규칙을 찾는다.
3. 입력 artifact와 manifest가 같은 세대인지 확인한다.
4. 로그의 첫 원인과 마지막 게시 상태를 구분한다.
5. 정상 결과가 보존됐는지 확인한 뒤 재실행 범위를 정한다.

단계별 세부 조건은 [공시 파이프라인](disclosures/index.md), 공통 저장·복구 규칙은 [공시 처리 공통 계약](disclosures/common/index.md)을 따른다.

## 재처리 범위

선행 계약이나 결과가 바뀌면 저장 fingerprint, membership와 manifest를 검사해 재사용할 수 없는 소비 단계만 다시 실행한다.

## 데이터 보존

삭제나 재다운로드는 화면에 표시된 대상과 현재 실행 입력이 일치할 때만 진행한다. 작업공간 연결을 해제해도 대상 작업공간의 데이터는 지우거나 옮기지 않는다. 게시와 복원 규칙은 단계 문서에 명시된 범위를 넘겨 추정하지 않는다.
