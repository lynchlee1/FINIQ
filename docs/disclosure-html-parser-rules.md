# 공시 HTML 파서 작성 규칙

KIND HTML 파서를 작성하거나 수정할 때 확인할 규칙.

## 공통 원칙

- parsing 동작은 `resources/KIND/bond_issuance`와 `resources/KIND/rights_issuance` 아래 실제 자료를 직접 확인해 결정한다.
- 테스트 fixture와 합성 HTML은 이미 결정한 동작의 회귀 여부만 확인하며, parsing 규칙을 결정하는 실제 예시로 사용하지 않는다.
- 값이 `-`로 명시된 경우와 값이 아예 없는 경우를 구분한다. 금액/수량 필드에서 `-`가 해당 항목의 명시적 0 의미라면 `parse_int(..., dash_as_zero=True)`를 사용한다.
- HTML `span`, `rowspan`, `colspan` 때문에 숫자 내부 공백이 생길 수 있다. 직접 문자열을 쪼개지 말고 공통 `parse_int()`를 사용한다.
- 필터 적용 후 제외된 레코드의 `parse_warnings`는 결과 경고에 포함하지 않는다. 경고는 최종 결과 레코드와 같은 필터 기준을 따라야 한다.
- 파서 입력은 section pre-cleaning이 끝난 HTML을 사용하며, 파서에서 정정 이력/비교표를 다시 필터링하지 않는다.

## 라벨 매핑

- 같은 의미의 라벨이 시대/양식별로 다르게 나온다. 예: `기타주식`, `우선주식`, `종류주식`은 유무상증자 출력 스키마의 `기타주식` 계열로 취급한다.
- 새 라벨을 발견하면 단일 샘플에만 맞춘 조건을 넣지 말고, 기존 출력 스키마의 어느 의미 그룹에 들어가는지 먼저 확인한다.
- 라벨 탐색은 공백 제거 비교를 고려한다. `배정주식수 (주)`와 `배정주식수(주)`는 같은 필드로 취급되어야 한다.

## 빈 표와 누락 경고

- 표의 헤더를 찾았다는 사실만으로 필드 추출 성공으로 처리하지 않는다. 유효한 데이터 행이 없거나 행이 `-`뿐이면 누락으로 본다.
- 제3자배정 공시에서 `제3자배정 대상자` 표가 비었으면 `발행대상자` 누락 경고를 남긴다. 다만 종속회사 주요경영사항처럼 주식 발행 정보가 의도적으로 생략되는 제목/설명은 별도 예외가 될 수 있다.

## 해외/외화 공시

- 같은 필드에 외화 금액과 원화기준 금액이 함께 있으면 원화 기준 값을 우선한다.
- 원화기준 행이 별도 행으로 분리될 수 있으므로 첫 번째 매칭 행만 사용하지 말고 후보 행 우선순위를 둔다.

## 검증 기준

- 동작 판단은 위 두 실제 리소스 디렉토리의 관련 자료를 직접 확인한 결과로 기록한다.
- 단위 테스트와 합성 fixture는 동작을 결정한 뒤 회귀 검증으로만 실행한다.
- 코드 변경의 기본 정적 검증에는 관련 모듈 `py_compile`을 포함한다.
- 실제 리소스 확인 결과와 테스트 회귀 결과를 같은 근거로 합치지 않고 따로 보고한다.
