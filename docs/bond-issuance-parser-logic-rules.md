# 사채발행 파서 로직 규칙

작성일: 2026-07-06
최종 업데이트: 2026-07-07

## 결론

사채 발행 HTML 파싱 워크플로우는 주변 메타데이터 파일에서 공시 제목을 먼저
확인해 파서에 주입하고, HTML 본문에서 직접 읽을 수 있는 사채 발행 필드를 만든다.
이후 주변 메타데이터 파일이 있으면 회사명, 상장구분, 정정공시 묶음 정보를 보강한다.
전환사채, 교환사채, 신주인수권부사채별로 별도 하위 객체를 만들지 않고 같은 필드
구조를 사용한다.

워크플로우 단계:

1. `filtered.json`, `compressed-external-html.json`, 다운로드 manifest 같은 주변 파일을
   읽어 `acpt_no` 기준 메타데이터 index를 만든다.
2. 주변 파일의 제목이 있으면 파서에 제목을 주입하고, 없으면 HTML 본문 제목을 쓴다.
3. HTML 본문을 읽어 제목, 원문 표, 접수번호 후보인 `acpt_no`를 만든다.
4. 사채 발행 메인 테이블과 투자자 상세 표에서 사채 발행 필드를 추출한다.
5. 추출 결과에 누락 상태, 경고 메시지, `발행목적` 합계 검증 결과를 붙인다.
6. 전체 HTML 파싱 작업에서 주변 파일을 찾을 수 있으면 회사명, 상장구분, 문서 선택
   번호, 정정공시 묶음 정보를 보강한다.

책임 경계:

- `extractor.py`: HTML 테이블/행/라벨을 기준으로 원천을 찾고 필드 값을 추출한다.
  하드코딩된 표 요소, 행 라벨, 출처 설명은 추출 규칙이므로 여기 둔다.
- `postprocess.py`: extractor가 만든 값과 원천 존재 여부를 바탕으로
  `field_parse_status`, 경고 메시지, 검증 결과를 최종 출력 JSON에 붙인다.
- `__init__.py`: 기본 출력값 생성, extractor 호출, 사채 발행 필드 조립, 후처리 호출을
  순서대로 연결한다.

사채 발행 필드 추출 순서:

1. 제목, 접수번호, 원본 테이블이 들어간 기본 출력값을 만든다. 외부에서 주입된
   제목이 있으면 기본 출력값의 제목을 주입값으로 교체한다.
2. `사채의 종류`, `사채의 권면`, `자금조달의 목적`이 모두 들어 있는 첫 번째
   테이블을 메인 테이블로 쓴다.
3. 대부분의 필드는 메인 테이블 행에서 읽고, `투자자`만 별도 상세 표에서 읽는다.
4. 추출값으로 사채 발행 출력 필드를 만든다.
5. 후처리에서 `field_parse_status`, 경고 메시지, `발행목적` 합계 검증을 최종
   출력 JSON에 반영한다.
6. 값을 찾지 못해도 파싱을 중단하지 않는다. 값이 없는 필드는 `null`, 빈 목록,
   또는 0으로 남기고, 후처리에서 어떤 필드를 찾지 못했는지 기록한다.

## 출력 필드

### 워크플로우 메타데이터

이 필드들은 HTML 본문 표에서 직접 추출하는 사채 발행 조건이 아니라, 전체 HTML
파싱 워크플로우가 주변 파일을 찾을 수 있을 때 보강하는 값이다.

| 필드 | 출처 | 기본값 |
| --- | --- | --- |
| `correction_families` | `filtered.json`의 공시 행을 기준으로 만든 원공시/정정공시 묶음 | `{}` |
| `rcept_no` | KIND HTML 워크플로우에서는 사용하지 않음 | `null` |
| `기업명(발행사)` | 다운로드 manifest, `filtered.json`, `compressed-external-html.json` | `null` |
| `상장구분` | 다운로드 manifest, `filtered.json`, `compressed-external-html.json` | `null` |

메모:

- KIND HTML 워크플로우의 기준 식별자는 `acpt_no`다.
- KIND HTML 워크플로우는 DART `rcept_no`를 만들거나 보강하지 않는다.
- `mainDoc` 값은 viewer 안의 문서 선택 번호로만 다루며, DART 접수번호로
  해석하지 않는다.
- KIND HTML 본문, viewer HTML, `filtered.json`, `compressed-external-html.json`만으로
  DART `rcept_no`를 복원하지 않는다.

### 저장 JSON 공통 필드

이 필드들은 `parsed-bond_issuance.json`의 `records` 항목에 저장된다.

| 필드 | 값 |
| --- | --- |
| `acpt_no` | 확장자를 뺀 파일명에서 `_` 앞에 있는 숫자 부분. 숫자로 시작하지 않으면 빈 문자열 |
| `source_file` | 입력 HTML 파일의 절대 경로 |
| `mode` | `bond_issuance` |
| `title` | 파서 호출자가 주입한 제목. 없으면 첫 `SECTION-1` 문단. 둘 다 없으면 빈 문자열 |

메모:

- `source_file`은 파싱한 HTML 파일 경로이며 HTML 원문 내용 자체를 보존하지 않는다.
- 전체 HTML 파싱 작업에서는 다운로드 manifest, `filtered.json`,
  `compressed-external-html.json`의 `title` 계열 값을 `acpt_no`로 찾아 파서에 먼저
  주입한다.
- 주입 제목이 없을 때만 사채 발행 파서는 본문 `SECTION-1` 문단을 제목 원천으로
  사용한다. `<title>` 태그는 제목 원천으로 사용하지 않는다.

### 파서 내부 원문 구조 필드

이 필드들은 사채 발행 파서가 필드 추출에 사용하지만, 웹 파싱 저장 단계에서
`records`에 남기지 않는다.

| 필드 | 값 | 저장 여부 |
| --- | --- | --- |
| `raw_tables` | HTML의 모든 표를 행/셀 구조로 정리한 값 | 저장하지 않음 |
| `raw_rows` | 모든 표의 행을 한 목록으로 합친 값 | 저장하지 않음 |

메모:

- `raw_tables`와 `raw_rows`는 `parse_bond_issuance()`의 직접 반환값에는 포함될 수
  있지만, `parse_disclosure_html_payload()`가 저장 JSON을 만들 때 제거한다.
- 실제 사채 발행 필드 추출은 전체 행이 아니라 `raw_tables`에서 고른 메인 테이블
  행을 기준으로 수행한다.

### 사채 발행 필드

| 필드 | 읽는 위치 | 없을 때 |
| --- | --- | --- |
| `회차` | 메인 테이블의 `사채의 종류` 행에서 `회차` 셀 오른쪽 값 | 강한 경고 |
| `종류` | 제목의 `신주인수권부사채`, `교환사채`, `전환사채` 문구 | 강한 경고 |
| `기업명(행사대상)` | `교환대상` 행, 또는 전환/인수권 행사 대상 주식 종류 행 | 강한 경고 |
| `발행금액` | `사채의 권면` 행. `원화기준` 행을 우선하고, 없으면 첫 권면 행 선택 | 강한 경고 |
| `발행목적` | `자금조달의 목적` 행의 목적명과 금액 | 강한 경고 또는 0원 상태 |
| `행사가액` | `전환가액`, `교환가액`, `행사가액`, `행사가격` 행 | 강한 경고 |
| `납입일` | 라벨이 정확히 `납입일`인 행의 마지막 값 | 강한 경고 |
| `만기일` | `사채만기일` 행. 없으면 `사채만기` 행 | 강한 경고 |
| `사채발행방법` | `사채발행방법` 행의 마지막 값 | 강한 경고 |
| `행사시작일` | 청구/행사 기간 행의 `시작일` 값 | 강한 경고 |
| `행사종료일` | 청구/행사 기간 행의 `종료일` 값 | 강한 경고 |
| `투자자` | 첫 logical row에 `발행 대상자명`과 `발행권면`이 있는 별도 상세 표 | 강한 경고 또는 0원 상태 |

세부 규칙:

- `종류`는 본문 종류값을 쓰지 않는다. 제목 기준으로 `BW`, `EB`, `CB` 순서로 판정한다.
- `기업명(행사대상)`은 법인 형태와 주식 종류 표현을 제거해 반환한다.
- `발행금액`이 0이면 원문에서 실제 0 또는 대시를 읽은 것으로 보고 0원 상태로 기록한다.
- `발행목적` 금액이 0인 목적은 결과 목록에서 제외한다.

### 투자자 표 규칙

투자자는 특정인 대상 사채발행 표에서 대상자명과 발행권면총액을 읽는다.

- 첫 logical row에 `발행 대상자명`과 `발행권면`이 모두 있어야 투자자 표로
  인정한다.
- `-`, `합계`, `총계`, `계` 행은 제외한다.
- 금액은 첫 logical row에서 찾은 `발행권면` 열의 값을 읽는다.
- 대상자명 행이 있고 금액 셀이 `-`이면 대상자명을 보존하고 금액을 0으로 기록한다.
- `투자자` 목록이 비어 있지 않으면 금액이 0이어도 `parsed` 상태로 기록한다.

| 상황 | 출력 `투자자` | 상태 | 경고 |
| --- | --- | --- | --- |
| 투자자 표를 찾지 못함 | `[]` | `source_not_found` | 강한 경고 |
| 표를 찾았지만 보존할 대상자 행이 없음 | `[]` | `explicit_zero` | 없음 |
| 표를 찾았고 일부 행의 대상자명이 `-`임 | `-` 행은 제외하고 나머지 대상자만 기록 | 남은 대상자가 있으면 `parsed`, 없으면 `explicit_zero` | 없음 |
| 표를 찾았고 일부 행의 금액만 `-`임 | 해당 행은 `[대상자명, 0]`, 숫자 행은 실제 금액 | `parsed` | 없음 |
| 표를 찾았고 모든 보존 대상 행의 금액이 `-`임 | 각 대상자를 `[대상자명, 0]`으로 기록 | `parsed` | 없음 |
| 표를 찾았고 대상자명과 금액이 있음 | `[대상자명, 발행권면총액]` 목록 | `parsed` | 없음 |

## 경고와 상태

### 상태 코드

| 코드 | 의미 |
| --- | --- |
| `parsed` | 값을 찾았다. |
| `explicit_zero` | 원문에서 0 또는 대시를 읽어 0으로 해석했다. |
| `source_not_found` | 정해진 위치에서 값을 찾지 못했다. |

### 경고 출력 필드

| 출력 필드 | 들어가는 내용 |
| --- | --- |
| `field_parse_status` | 필드별 상태 코드 |
| `parse_warnings` | 모든 경고를 한 곳에 모은 목록 |
| `weak_warning` | 추출은 됐지만 값 사이의 관계가 맞지 않는 경우 |
| `medium_warning` | 현재 사채 발행 파서에서는 만들지 않음 |
| `strong_warning` | 메인 테이블이 없거나 정해진 위치에서 필드 값을 찾지 못한 경우 |

`parse_warnings`에는 메인 테이블 누락, 필드 원천 누락, 검증 실패가 들어간다.
현재 `weak_warning`은 `발행목적` 합계 또는 `투자자` 발행권면총액 합계가
`발행금액`과 다를 때 사용한다.

`발행목적` 검증은 목적별 금액 목록이 있고 `발행금액`도 숫자로 추출된 경우에만
수행한다. 목적별 금액 합계가 발행금액과 정확히 같지 않으면 “추출은 됐지만 값
사이의 관계가 맞지 않는다”는 경고를 남긴다. 오차는 허용하지 않는다.

`투자자` 검증은 투자자 목록이 있고 `발행금액`도 숫자로 추출된 경우에만 수행한다.
투자자별 발행권면총액 합계가 발행금액과 정확히 같지 않으면 같은 방식의 약한
경고를 남긴다. 오차는 허용하지 않는다.

저장 결과의 `warnings` 항목에는 알림 패널에서 경고를 코드별/페이지별로 열 수
있도록 `warning_code`를 함께 둔다. 사채 발행 파서의 합계 검증 코드는
`bond_funding_purpose_sum_mismatch`와 `bond_investor_sum_mismatch`다.

후처리는 원천 테이블을 직접 다시 찾지 않는다. 예를 들어 `발행목적`에 0원 값이
실제로 있었는지, `투자자` 상세 표가 있었는지는 추출 단계에서 먼저 판단한다.
후처리는 그 참/거짓 결과만 받아서 `field_parse_status`와 경고 메시지를 만든다.
