# 사채발행 파서 로직 규칙

작성일: 2026-07-06

## 결론

`bond_issuance` 파서는 사채 발행 메인 테이블을 먼저 찾은 뒤, 해당 테이블과
일부 상세 표에서 flat 필드를 만든다. 타입별 상세 블록은 따로 만들지 않는다.

핵심 판단 순서:

1. 제목, 접수번호, 원본 테이블이 들어간 공통 record를 만든다.
2. `사채의 종류`, `사채의 권면`, `자금조달의 목적`이 모두 들어 있는 첫 번째
   테이블을 메인 테이블로 쓴다.
3. 대부분의 필드는 메인 테이블 행에서 읽고, `투자자`만 별도 상세 표에서 읽는다.
4. `발행목적` 합계와 `발행금액`만 검증한다.
5. 추출 실패는 예외로 처리하지 않고 `None`, 빈 목록, 0, `field_parse_status`,
   warning에 기록한다.

## 출력 필드

### 공통 필드

| 필드 | 로직 | 실패/주의 |
| --- | --- | --- |
| `correction_families` | 기본 `{}` | 단독 parser는 계산하지 않음 |
| `rcept_no` | 기본 `None` | 단독 parser는 계산하지 않음 |
| `acpt_no` | 파일명 stem에서 `_` 앞의 숫자 prefix | 숫자가 아니면 빈 문자열 |
| `source_file` | `file_path.resolve()` | warning 없음 |
| `mode` | `bond_issuance` | 고정값 |
| `title` | 첫 `SECTION-1` 문단, 없으면 `<title>` | 없으면 빈 문자열이며 `종류` 판정이 실패할 수 있음 |
| `raw_tables` | 전체 table 정규화 결과 | 추출 디버깅용 |
| `raw_rows` | 전체 `logical_rows` 병합 | 메인 추출용 rows와 다름 |

### 비즈니스 필드

| 필드 | 추출 로직 | 실패/status/warning |
| --- | --- | --- |
| `기업명(발행사)` | 기존 record의 `기업명(발행사)`를 그대로 전달 | 보통 `None`; extractor status 없음 |
| `회차` | 메인 테이블의 `사채의 종류` 행에서 정확히 `회차` 셀 오른쪽 값을 읽음 | 값이 있으면 `parsed`; 없으면 `source_not_found` strong warning |
| `종류` | 제목에서 `신주인수권부사채` -> `BW`, `교환사채` -> `EB`, `전환사채` -> `CB` 순서로 판정 | 본문 종류값은 쓰지 않음; 실패하면 strong warning |
| `기업명(행사대상)` | `교환대상` 행을 우선 사용하고, 없으면 `전환에 따라`/`전환으로 발행할`/`인수권행사에 따라`와 `종류`가 함께 있는 행의 마지막 값을 사용 | 법인/주식 표현을 제거해 반환; 원천 행이 없으면 strong warning |
| `상장구분` | 공통 record의 `상장시장` 값을 pop해서 전달 | 현재 단독 parser에서는 보통 `None`; status 없음 |
| `발행금액` | `사채의 권면` 행 중 `원화기준`을 우선 사용하고, 없으면 `(원)`, 그다음 첫 권면 행을 사용. 첫 셀 오른쪽에서 처음 나오는 정수를 읽음 | 0이면 `explicit_zero`; 값이 없으면 strong warning |
| `발행목적` | `자금조달의 목적` 행마다 오른쪽 셀을 목적명으로, 그 뒤에서 처음 나오는 정수를 금액으로 읽음 | 0 금액은 목록에서 제외. 원천이 있으면 `parsed`/`explicit_zero`; 없으면 strong warning |
| `행사가액` | `전환가액`, `교환가액`, `행사가액`, `행사가격` 순서로 `원`이 포함된 행을 찾고 오른쪽 첫 정수를 읽음 | 없으면 strong warning |
| `납입일` | 목차 번호를 제거한 뒤 라벨이 정확히 `납입일`인 행의 마지막 값을 읽음 | 라벨 변형에 민감함; 없으면 strong warning |
| `만기일` | `사채만기일` 행의 마지막 값, 없으면 `사채만기` 행의 마지막 값 | 없으면 strong warning |
| `사채발행방법` | `사채발행방법` 행의 마지막 값 | 없으면 strong warning |
| `행사시작일` | `전환청구기간`/`교환청구기간`/`권리행사기간`/`행사기간` 중 `시작일`이 포함된 행의 마지막 값 | 없으면 strong warning |
| `행사종료일` | 같은 기간 라벨 중 `종료일`이 포함된 행의 마지막 값 | 없으면 strong warning |
| `투자자` | 정정 표가 아니면서 첫 행에 `발행 대상자명`과 `발행권면`이 있는 표를 사용. `-`, `합계`, `총계`, `계` 행은 제외하고 오른쪽 첫 정수를 금액으로 읽음 | 표가 없으면 strong warning. 표는 있으나 결과가 없으면 `explicit_zero`, warning 없음 |

## 경고와 상태

| 출력 필드 | 생성 조건 |
| --- | --- |
| `field_parse_status` | 하나 이상 필드 상태가 기록될 때 출력. 값은 `parsed`, `explicit_zero`, `source_not_found`. |
| `parse_warnings` | 메인 테이블이 없거나 extractor warning이 발생하면 출력. |
| `weak_warning` | 현재는 `발행목적` 합계와 `발행금액`이 다를 때만 사용. |
| `medium_warning` | 현재 bond parser에는 발생 로직 없음. |
| `strong_warning` | 메인 테이블이 없거나 필드 원천을 찾지 못했을 때 사용. |

`발행목적` 검증은 목적 목록이 있고 `발행금액`이 `None`이 아닐 때만 수행한다.
합계가 정확히 같지 않으면 weak warning이며, 오차는 허용하지 않는다. `투자자`
합계와 `발행금액`은 비교하지 않는다.
