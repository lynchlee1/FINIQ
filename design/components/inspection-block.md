# 검사 블록 기능 디자인

## 1. 목적과 범위

이 문서는 공시 워크플로우의 `기존 데이터 검토` 검사 블록에 대한 단일 디자인 계약이다. 검사 단계의 순서, 상태 보존, 복구 동작, 재검사 범위와 페이지 배치는 이 문서를 따른다. UI 명칭은 [디자인 시스템](../README.md)의 UI Terminology를 따른다.

검사 블록의 핵심 원칙은 다음과 같다.

> 완료된 단계의 근거 입력이 바뀌지 않았다면 그 단계를 다시 검사하게 만들지 않는다.

검사 실패를 해결하는 블록 내부 동작은 전체 검사를 초기화하는 새 입력으로 취급하지 않는다. 사용자는 실패한 단계에서 문제를 해결한 뒤 그 다음 단계부터 이어갈 수 있어야 한다.

## 2. 페이지 배치

번호가 있는 공시 워크플로우 페이지에서는 다음 순서를 지킨다.

1. `세부 페이지 선택`이 있으면 이를 첫 컨트롤로 두고, `기존 데이터 검토`를 바로 다음 블록에 둔다.
2. `세부 페이지 선택`이 없으면 `기존 데이터 검토`를 페이지의 최상단 콘텐츠 블록에 둔다.
3. 검색 조건, 필터 선택, 경로 설정과 실행 카드는 항상 `기존 데이터 검토` 다음에 둔다.

페이지 제목, 설명과 앱 내비게이션은 콘텐츠 블록으로 보지 않는다. `세부 페이지 선택` 외의 입력 카드나 요약 카드를 검사 블록 위에 두지 않는다.

## 3. 블록 구조

`기존 데이터 검토` 카드 하나가 다음 요소를 소유한다.

- 전체 판정 한 개
- 의존 순서대로 나열한 검사 단계
- 현재 실행할 수 있는 단계의 검사 동작
- 실패한 단계 바로 아래의 원인, 영향 범위와 복구 동작

성공한 단계는 한 줄 요약으로 접고, 비교표나 영향받은 파일·기간은 실패한 단계 아래에서만 보여준다. 검사 블록은 검색 조건 카드와 실행 카드에서 분리한다.

단계 상태는 `대기`, `검사 중`, `정상`, `사용 불가`를 기본으로 하고, 비교 실패의 `불일치`처럼 단계에 맞는 구체적인 실패 문구를 사용할 수 있다. 색상만으로 상태를 표현하지 않고 아이콘과 상태 문구를 함께 표시한다. 전체 판정은 모든 페이지 소유 단계가 끝난 뒤에만 `정상`이 된다.

## 4. 단계와 실행 순서

`공시내역 다운로드`의 기본 순서는 다음과 같다.

1. `메타데이터 읽기`
2. `현재 설정과 비교`
3. `저장 파일 구성 검사`
4. `KIND 건수 비교`

각 단계는 자신이 필요로 하는 앞 단계가 `정상`일 때만 실행할 수 있다. 한 단계의 `검사하기`는 그 단계만 실행한다. `메타데이터 읽기`에서 본문 파일 구성 검사나 KIND 조회를 함께 시작하지 않는다.

`1`, `2`, `3`처럼 순번이 표시된 행은 서로 독립적으로 실행하는 검사 단계다. 순번이 있는 행의 `검사하기`는 같은 순번의 검사만 실행하며 다른 순번의 검사를 함께 시작하지 않는다.

계산 비용이나 처리 속도 때문에 여러 결과를 한 요청에서 반드시 함께 계산하는 경우에는 다음과 같이 하나의 묶음 검사로 표현한다.

- 묶음을 시작하는 `검사하기`는 첫 행 한 곳에만 둔다.
- 같은 요청에서 계산되는 나머지 행은 검사 전 `대기` 상태만 표시하고 별도의 `검사하기`를 두지 않는다.
- 묶음에 속한 모든 행은 순번 영역을 비우고 `1`, `2`, `3` 같은 번호를 표시하지 않는다.
- 검사 완료 뒤 결과에 따른 복구·실행 동작은 해당 결과 행에 둘 수 있지만, 이를 별도 검사 단계로 표시하지 않는다.

한 검사 버튼이 여러 행을 실행하면서 그 행들에 순번을 표시하면 독립 단계로 오해되므로 허용하지 않는다. 여러 행에 순번이 필요하면 API와 상태를 분리해 각 행을 개별 실행할 수 있게 해야 한다.

`현재 설정과 비교`처럼 이미 읽은 메타데이터와 화면 상태만으로 판단할 수 있는 단계는 별도 네트워크 검사를 만들지 않는다. 비교 입력이 바뀌면 보유한 메타데이터를 사용해 즉시 다시 계산한다.

페이지별 추가 단계가 있으면 같은 원칙으로 마지막에 연결한다. 추가 단계가 남아 있으면 앞선 행이 `정상`이어도 전체 판정은 `정상`이 아니다.

## 5. 검사 근거와 상태 보존

각 단계의 완료 상태는 그 단계가 사용한 근거 입력과 함께 보관한다. 입력 변경은 실제로 영향을 받는 첫 단계와 그 뒤 단계만 무효화한다.

| 사건 | 유지하는 단계 | 다시 판단하거나 검사하는 단계 |
| --- | --- | --- |
| `저장된 설정 적용` | `메타데이터 읽기` | `현재 설정과 비교`를 즉시 다시 계산하고, 이후 미완료 단계부터 계속한다. |
| 사용자가 검색 조건을 직접 변경 | `메타데이터 읽기` | `현재 설정과 비교`와 그 뒤 단계만 무효화한다. |
| 데이터 경로 변경 | 없음 | `메타데이터 읽기`부터 다시 시작한다. |
| `세부 페이지 선택` 변경 | 없음 | 새 세부 페이지의 첫 단계부터 시작한다. |
| 파일 삭제·복구 동작 완료 | 메타데이터와 설정 비교 | `저장 파일 구성 검사`와 그 뒤 단계만 다시 검사한다. |
| 완료된 단계의 결과 버튼을 눌러 명시적으로 재검사 | 그 앞 단계 | 선택한 단계와 그 뒤 단계만 무효화한다. |

상위 단계의 근거 입력이 실제로 바뀐 경우에만 그 단계부터 다시 검사한다. 단순 상태 갱신, 상태 문구 변경, 패널 열기, 블록 내부 복구 동작을 이유로 전체 검사 상태를 비우지 않는다.

## 6. 복구 동작 계약

복구 동작은 실패한 단계의 컨텍스트 안에서 실행하고 다음 조건을 만족해야 한다.

- 복구에 사용한 검사 결과와 그 결과를 만든 입력 스냅샷을 유지한다.
- 복구가 바꾸는 필드와 영향을 받는 첫 단계를 명시한다.
- 영향받지 않는 앞 단계의 상태, 요약과 근거를 그대로 유지한다.
- 복구 직후 로컬에서 판단할 수 있는 단계는 즉시 다시 계산한다.
- 다음 네트워크 검사가 필요하면 그 단계만 `대기` 또는 실행 가능 상태로 만든다.
- 전체 블록 초기화나 첫 단계 자동 재호출을 복구의 부수 효과로 만들지 않는다.

`저장된 설정 적용`은 저장된 메타데이터에서 읽은 검색 설정을 현재 설정에 원자적으로 반영하는 복구 동작이다. 적용 직후 `메타데이터 읽기`는 계속 `정상`이어야 하고, `현재 설정과 비교`는 같은 메타데이터로 즉시 `정상`이 되어야 한다. 이어서 `저장 파일 구성 검사`의 `검사하기`를 사용할 수 있어야 하며 `메타데이터 읽기` API를 다시 호출해서는 안 된다.

구현에서 일반 입력 변경 감지기를 사용하더라도 블록 내부 복구 동작을 임의의 사용자 입력 변경과 구분해야 한다. 여러 필드를 적용하는 동안 중간 렌더 상태가 전체 검사 초기화를 일으켜서는 안 된다.

## 7. 비동기 결과 보호

검사 요청은 시작 시점의 입력 스냅샷과 단계 ID에 결합한다.

- 새 요청이 시작된 뒤 도착한 이전 요청의 응답은 현재 단계 상태를 덮어쓰지 않는다.
- 검사 중 사용자가 입력을 바꾸더라도 진행 중 요청의 스냅샷은 바뀌지 않는다.
- 완료 결과가 현재 입력과 맞지 않으면 성공 상태로 게시하지 않는다.
- 실패나 취소 뒤에는 같은 단계에서 다시 검사할 수 있어야 한다.

## 8. 표시와 반응형 규칙

- 전체 판정과 단계 사이에는 16px, 단계 행에는 16px 안쪽 여백을 사용한다.
- 전체 판정은 16px, 단계 제목은 15px, 설명·근거·동작은 13px을 기준으로 한다.
- 좁은 화면에서는 단계 상태를 요약 아래로 내리고, 비교표는 카드 내부에서 가로 스크롤한다.
- 긴 문제 목록은 높이가 제한된 스크롤 영역에 둔다.
- 레이아웃 전환 애니메이션은 사용하지 않는다. 로딩 표시와 기존 포커스·누름 피드백만 유지한다.
- 공통 검사 패널이 목록과 상태 표현을 소유하고, 각 페이지는 판정, 단계별 근거와 복구 동작만 제공한다.

## 9. 필수 회귀 시나리오

다음 시나리오는 검사 블록을 변경할 때 반드시 검증한다.

### 설정 불일치 복구

1. `메타데이터 읽기`가 `정상`이다.
2. `현재 설정과 비교`가 `불일치`이고 전체 판정은 `사용 불가`이며, 실패 단계에 `저장된 설정 적용`이 보인다.
3. 사용자가 `저장된 설정 적용`을 누른다.
4. `메타데이터 읽기`가 `정상`으로 유지된다.
5. `현재 설정과 비교`가 추가 API 호출 없이 `정상`이 된다.
6. `저장 파일 구성 검사`에서 이어서 `검사하기`를 누를 수 있다.
7. 이 과정에서 메타데이터 읽기 요청이 다시 발생하지 않는다.

### 영향 범위만 무효화

1. 여러 단계가 `정상`인 상태에서 검색 조건만 직접 바꾼다.
2. 메타데이터 결과는 유지되고 설정 비교와 뒤 단계만 무효화된다.
3. 데이터 경로를 바꾸면 모든 단계가 초기화된다.

### 단계별 실행

1. 첫 `검사하기`를 누른다.
2. 메타데이터 읽기 요청만 발생한다.
3. 파일 구성 검사와 KIND 조회는 각 단계의 명시적 검사 동작 전에는 발생하지 않는다.

### 묶음 검사 표시

1. 한 요청에서 여러 검사 결과를 함께 계산하는 화면을 연다.
2. 묶음의 첫 행에만 `검사하기`가 보인다.
3. 실행 전 나머지 행은 별도 검사 버튼 없이 `대기`다.
4. 묶음에 속한 모든 행의 순번 영역은 비어 있고 `1`, `2`, `3`이 표시되지 않는다.
5. 순번이 표시된 행이 있다면 그 행은 다른 순번의 검사와 독립적으로 실행된다.

### 페이지 배치

1. `세부 페이지 선택`이 있는 페이지에서는 해당 컨트롤 바로 다음이 `기존 데이터 검토`다.
2. 해당 컨트롤이 없는 페이지에서는 `기존 데이터 검토`가 첫 콘텐츠 블록이다.
3. 검색 조건, 필터, 경로와 실행 카드는 검사 블록 아래에 있다.
