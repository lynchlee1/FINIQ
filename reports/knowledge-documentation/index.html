지식은 한 문서에 살지 않는다

메모, 현재 답, 기록, 검사, 접근 화면을 한 체계로 관리하는 짧은 안내서.

한 체계, 다섯 층

좋은 지식 체계는 모든 내용을 한 도구에 넣지 않는다. 각 층이 맡을 질문과 갱신 시점을 분명히 둔다.

노트
관찰과 생각을 빠르게 잡는다. 연결은 나중 검색과 재사용을 돕는다.
현재 답
지금 따라야 할 절차와 설명을 짧게 쓴다. 낡으면 고쳐서 한 답만 남긴다.
기록
결정 당시 맥락, 선택, 결과를 시간 순서로 남긴다. 지난 판단을 새 답처럼 꾸미지 않는다.
실행 검사
코드, 스키마, 테스트가 중요한 규칙을 직접 확인한다. 설명과 실제 동작 사이 간격을 줄인다.
접근 화면
HTML, 검색, 질의응답, 번역이 같은 원천을 독자 상황에 맞춰 보여 준다.

방법보다 역할을 먼저 고른다

도구 이름부터 고르면 같은 내용을 여러 곳에 베끼기 쉽다. 아래 여섯 역할을 먼저 나누면 선택 기준이 단순해진다.

역할 주요 질문 알맞은 방법 고칠 때
생각 포착 무엇을 발견했나 상호 연결 노트, 에버그린 노트 새 연결이나 반례를 찾을 때
현재 안내 지금 무엇을 해야 하나 질의응답, Diátaxis 설명과 사용법 행동이나 정책이 바뀔 때
결정 기록 왜 이 선택을 했나 아키텍처 결정 기록 새 결정을 추가할 때
규칙 검사 실제가 약속과 맞나 테스트, 스키마, API 계약 구현이나 계약이 바뀔 때
분류 이 자료를 어디에 둘까 PARA 일 상태가 바뀔 때
접근 이 독자는 어떻게 찾나 HTML, 검색, 지식 그래프, RAG 독자와 탐색 경로가 바뀔 때

복사보다 갱신 경로를 설계한다

문서 수보다 원천과 파생물 관계가 중요하다. 세 규칙이면 대부분 유지 비용을 줄일 수 있다.

  1. 원천을 한 곳에 둔다

    정책, 스키마, 결정처럼 핵심 사실마다 고칠 곳을 하나 정한다. 다른 화면은 링크하거나 변환한다.

  2. 수명을 표시한다

    현재 답과 과거 기록을 섞지 않는다. 현재 답은 교체하고 기록은 새 항목을 더한다.

  3. 검사를 가까이 둔다

    깨지면 큰 비용이 드는 규칙은 실행 검사로 옮긴다. 문장은 이유와 사용 맥락을 맡는다.

접근 화면은 원천이 아니다

웹 문서, 검색, AI 답변, 번역은 읽기 문턱을 낮춘다. 그러나 원천을 복제하면 편리함이 곧 불일치로 바뀐다.

HTML
구조, 링크, 표, 인쇄를 한 화면에 담는다.
RAG
질문에 맞는 원천 조각을 찾아 답을 만든다.
번역
내용 식별자와 원문 판을 함께 기록해 추적성을 지킨다.
