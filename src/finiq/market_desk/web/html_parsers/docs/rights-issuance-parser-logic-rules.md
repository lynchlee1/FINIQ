# 유무상증자 파서 로직 규칙
- 이 문서는 작성 및 검토가 완료되었으므로 사용자의 명시적 허락이 있지 않는 한 **절대로** 수정하지 않는다.

이 문서는 유상증자·무상증자·유무상증자 공시에서만 사용하는 table 선택, 유형 판정, 필드 추출, 대체 경로, 특수 보정 규칙을 설명한다.
여기서 대체 경로는 정상적인 위치나 결과를 얻지 못했을 때 다른 label, section 또는 table 후보를 사용하는 모든 로직을 뜻한다.
`table`은 표, `row`는 표의 가로줄, `cell`은 표의 한 칸, `column`은 표의 세로줄, `title`은 외부에서 전달받은 공시 제목, `section`은 유상증자와 무상증자를 나눈 구역이다.

### 문서 경계
- HTML 디코딩, 손상된 HTML 복구, 공백 정리, `rowspan`·`colspan`, 공통 row·숫자 함수는 [HTML 파서 공통 로직 규칙](./common/common-html-parser-logic-rules.md)을 따른다.
- `raw_tables`, base record, parser 직접 반환값, 저장 payload 구조는 [HTML 파서 공통 데이터 구조](./common/common-html-parser-data-structure.md)를 따른다.
- `parsed`, `explicit_zero`, `source_not_found`, `not_applicable`의 뜻과 저장값, 공통 warning·실행 오류 처리는 [HTML 파서 공통 예외 처리 규칙](./common/common-html-parser-exception-handling.md)을 따른다.
- 외부 metadata의 위치와 필드별 Only SoT는 [외부 메타데이터 병합 규칙](./external-metadata.md)을 따른다.
- 이 문서는 위 공통 규칙을 반복하지 않고 유무상증자 parser가 **어떤 원천을 먼저 선택하고, 실패하면 무엇을 대신 시도하는지**만 정한다.

### 유형 판정과 실패 처리
1. **판정 순서**
- 주입된 `title`의 앞뒤 공백을 제거해 record에 저장하고, 일반 공백을 제거한 제목에서 `유무상증자` → `무상증자` → `유상증자` 순서로 확인한다.
- 각각 `유무상증자`, `무상증자`, `유상증자`로 출력한다.
- 긴 문구인 `유무상증자`를 먼저 확인해 그 안의 `무상증자` 또는 `유상증자` 부분을 잘못 선택하지 않는다.
2. **판정 실패**
- 세 문구를 모두 찾지 못하면 `증자유형`은 `unknown`, 두 상세 객체는 모두 `null`이다.
- `unknown`이어도 최상위 필드 추출은 계속한다.
- `title`이 비어 있으면 title 누락과 유형 판정 실패를 각각 strong warning으로 남긴다.
- 본문 제목, section 제목, 외부 metadata의 다른 field로 `title`이나 유형을 보완하지 않는다.
  - 의도 : 유형 판정 실패와 본문 field 추출 가능성을 분리하고, 제목의 출처를 하나로 고정한다.

### 추출 table 경계
1. **table 선택 조건**
- 아래 조건 중 하나를 만족하는 table만 선택한다.
  - cell 하나로 된 row가 공백 제거 후 `Ⅰ.유상증자`, `I.유상증자`, `1.유상증자`, `Ⅱ.무상증자`, `II.무상증자`, `2.무상증자` 중 하나와 정확히 같음
  - 첫 row에 `제3자배정 대상자`와 `배정주식수`가 모두 있음
  - 두 cell 이상인 row의 첫 cell에서 핵심 field 종류를 하나 이상 찾음
  - 두 cell 이상인 row들의 첫 cell에서 서로 다른 일반 field 종류를 두 개 이상 찾음
- 핵심 field는 `신주의 종류와 수`, `증자전 발행주식총수`, `자금조달의 목적`, `증자방식`, `신주 발행가액`, `신주배정기준일`, `1주당 신주배정`이다.
- 일반 field에는 핵심 field와 함께 `납입일`, `신주권교부예정일`, `신주의 상장 예정일`이 포함된다.
- field 종류는 첫 cell에서만 판정한다. 다른 column에 label과 비슷한 문구가 있다는 이유로 table을 선택하지 않는다.
2. **선택 후 검색 범위**
- 선택한 모든 table의 `logical_rows`를 HTML 순서대로 합쳐 최상위 field를 검색한다.
- 같은 field 후보가 여러 개이면 각 추출 규칙에서 정한 첫 일치 row 또는 첫 유효 값을 사용한다.
- 정정 이력 table이라는 이유만으로 별도 제외하지 않는다. 위 선택 조건을 만족할 때만 다른 table과 같은 방식으로 포함한다.
  - 의도 : 여러 table에 나뉜 증자 본문은 함께 읽되, 관련 없는 table까지 대체 원천으로 넓히지 않는다.

### 대체 경로와 선택 순서

| 대상 | 먼저 사용하는 경로 | 찾지 못하거나 기대와 다를 때 | 최종 결과 |
|---|---|---|---|
| 주식 종류 이름 | `보통주식`, `기타주식` | `보통주`; `기타주`, `우선주식`, `우선주`, `종류주식`, `종류주` | 두 출력 이름으로 표준화 |
| 종류별 수량·가액 | 해당 label과 주식 종류 label 바로 오른쪽의 첫 숫자 | 0 또는 `-`를 먼저 만나도 뒤의 같은 종류 후보에서 양수를 계속 찾음 | 양수 우선, 없으면 0 또는 `null` |
| 발행목적 이름 | 정해진 여섯 목적 label | `타법인 증권 취득자금`은 `타법인유가증권취득자금`도 허용 | 정해진 이름과 순서로 출력 |
| `상장예정일` | `신주의 상장 예정일` | 공통 공백 제거 비교로 `신주의 상장예정일`도 같은 label로 봄 | 첫 일치 row의 마지막 값 |
| mixed section | 첫 `무상증자` 포함 row를 경계로 분리 | 경계가 없으면 전체 row를 유상 section으로 사용 | 무상 section은 빈 목록 |
| `1주당 신주배정주식수` | 주식 종류 label 바로 오른쪽 text | 두 종류를 모두 못 찾으면 row 마지막 값을 `보통주식`에 사용 | 값이 없거나 `-`이면 보완하지 않음 |
| 발행대상자 table | 신주 합계와 일치하는 첫 후보 | 일치 후보가 없으면 값이 있는 첫 불일치 후보 | 후보도 없으면 조건에 따라 `null` 또는 빈 목록 |

### 종류별 수량과 금액의 특수 처리
1. **고정 출력 구조**
- `신주의 종류와 수`, `증자 전 발행주식총수`, `발행가액`은 `보통주식`, `기타주식` 순서의 두 항목을 유지한다.
- 한 종류의 원천이 없으면 그 값은 `null`이며, 다른 종류의 값으로 채우지 않는다.
2. **양수 우선 규칙**
- 같은 주식 종류의 후보를 앞에서부터 확인한다.
- 0 또는 `-`를 만나면 기억만 하고 계속 찾는다. 뒤에서 양수를 찾으면 양수를 사용한다.
- 끝까지 양수가 없고 0 또는 `-`가 있었으면 0, 아무 숫자 원천도 없으면 `null`이다.
  - 의도 : 앞쪽의 빈 종류 행 때문에 뒤쪽의 실제 발행 수량을 놓치지 않으면서, 원천 누락과 명시적 0을 구분한다.
3. **발행목적**
- 유상증자 또는 유무상증자는 시설자금 → 영업양수자금 → 운영자금 → 채무상환자금 → 타법인 증권 취득자금 → 기타자금 순서로 찾는다.
- `자금조달의 목적`과 목적 label을 함께 포함한 첫 row의 마지막 cell만 금액 원천으로 사용한다.
- 금액이 0 또는 `-`이면 원천은 존재한 것으로 보되 결과 목록에서는 제외한다.
- 다른 목적, 다른 row의 금액 또는 발행금액으로 누락값을 보완하지 않는다.
4. **무상증자의 유상 조건 field**
- 유형이 무상증자이면 `발행목적`, `발행가액`, `증자방식`, `납입일`, `발행대상자`를 `-`와 `not_applicable`로 기록한다.
- 이때 본문에 값이 있더라도 추출하지 않고, 누락 warning이나 합계 검증도 만들지 않는다.
- `증자방식`을 `무상증자`라는 문자열로 보완하지 않는다.
  - 의도 : 적용되지 않는 field와 찾지 못한 field를 구분한다.

### 유상·무상 상세 객체의 경계
1. **유상증자 상세**
- 유상증자 또는 유무상증자일 때 생성한다.
- 최상위에서 이미 추출한 수량, 발행목적, 발행가액, 증자방식, 납입일, 일정, 발행대상자를 그대로 재사용한다.
- `신주배정기준일`과 `1주당 신주배정주식수`만 유상 section에서 별도로 읽는다.
2. **무상증자 상세**
- 무상증자 또는 유무상증자일 때 생성한다.
- 무상 section에서 수량, 증자 전 수량, 배정기준일, 1주당 배정수, 교부예정일, 상장예정일을 다시 읽는다.
- 상세 객체 안의 누락값은 `null`로 두며, 최상위 값을 대신 복사하지 않는다.
3. **유무상증자 section 분리**
- 합친 row 목록에서 `무상증자`를 포함하고 `유무상증자`를 포함하지 않는 첫 row를 경계로 사용한다.
- 경계 앞은 유상 section, 경계 뒤는 무상 section이며 경계 row 자체는 어느 쪽에도 넣지 않는다.
- 경계 row는 cell 하나의 정확한 section 제목일 필요가 없다.
- 경계를 찾지 못하면 유상 section은 전체 row, 무상 section은 빈 목록이다. 다른 제목이나 field 배치로 경계를 추측하지 않는다.
- 최상위 field는 section 분리 전에 전체 row에서 읽으므로 반드시 유상 section의 값이라고 보장하지 않는다.
  - 의도 : 최상위 검색과 상세 section 검색의 책임을 섞지 않는다.
4. **1주당 신주배정주식수 대체 경로**
- 먼저 section 안에서 `1주당 신주배정` row의 주식 종류 label 바로 오른쪽 text를 종류별로 읽는다.
- 두 종류를 모두 찾지 못했을 때만 같은 label을 포함한 첫 row의 마지막 값을 `보통주식` 값으로 사용한다.
- 마지막 값이 빈 값 또는 `-`이면 사용하지 않는다. 한 종류라도 기본 경로에서 찾았으면 마지막 값 대체 경로는 실행하지 않는다.
  - 의도 : 주식 종류 column이 없는 과거 양식만 제한적으로 지원한다.

### 발행대상자 table의 대체·보정 규칙
1. **유효한 후보**
- 첫 row에 `제3자배정 대상자`와 `배정주식수`가 모두 있고 두 header가 서로 다른 column에 있어야 한다.
- 후보 확인에는 검색하기 쉽게 정리한 `logical_rows`를 사용하고, 실제 header 위치와 값은 원래 column 위치를 유지한 `positional_rows`에서 읽는다.
- 대상자명과 수량은 선언된 각 column에서만 읽는다. 다른 column이나 row 마지막 숫자는 대체 원천이 아니다.
2. **수량 cell 보정**
- 수량 cell에서 `%`가 붙은 숫자를 먼저 제거한 뒤 남은 모든 정수를 합산한다.
- 숫자가 하나도 남지 않으면 그 row는 결과에서 제외한다.
  - 의도 : 배정 비율을 주식수에 더하지 않고, 줄바꿈 등으로 한 cell에 나뉜 여러 수량은 합친다.
3. **대상자 미공개 형식**
- data row가 하나 이상이고 모든 대상자명이 정확히 `-`이며 모든 수량 cell에서 숫자를 읽을 수 없으면 즉시 `[["-", 0]]`과 `explicit_zero`를 반환한다.
- 대상자명 하나라도 `-`이 아니거나 수량 하나라도 숫자로 읽히면 이 규칙을 적용하지 않는다.
- 이 형식은 뒤 후보의 합계 일치 여부보다 먼저 확정한다.
  - 의도 : 의도적으로 공개하지 않은 표를 일반적인 파싱 실패와 구분한다.
4. **하단 중복 총계 제거**
- 대상자가 두 건 이상이고 신주 합계가 양수일 때만 검사한다.
- 마지막 대상자명의 공백 분리 단어 중 `계`, `합계`, `소계`, `총계`가 정확히 있어야 한다.
- 대상자 전체 합계가 신주 합계의 두 배이고 마지막 row 수량이 신주 합계와 같을 때만 마지막 row를 제거한다.
- 세 조건 중 하나라도 다르면 실제 대상자일 수 있으므로 보존한다.
5. **여러 후보의 선택 순서**
- 각 후보를 HTML 순서대로 읽고, 중복 총계 제거까지 끝낸 결과를 신주 합계와 비교한다.
- 합계가 일치하는 첫 후보를 즉시 사용한다.
- 일치하지 않지만 값이 있는 첫 후보는 예비 결과로 기억한다. 뒤에서도 일치 후보를 찾지 못하면 이 예비 결과를 사용하고 합계 불일치 weak warning을 만든다.
- 빈 후보가 하나라도 있었고 값이 있는 후보가 전혀 없으면 `null`, `source_not_found`, strong warning이다.
- 유효 후보 자체가 없을 때 `증자방식`에 `제3자배정`이 있고 title에 `종속회사`가 없으면 대상자 table이 필수라고 보고 같은 누락 처리를 한다.
- 위 조건이 아니면 빈 목록을 반환하고 `발행대상자` 상태와 누락 warning을 만들지 않는다.
  - 의도 : 합계가 맞는 table을 우선하되, 사용할 수 있는 실제 값까지 버리거나 필요하지 않은 table을 누락으로 판단하지 않는다.

### 상태와 관계 검증
- `신주의 종류와 수`, `증자 전 발행주식총수`, `발행가액`은 field 전체 상태와 주식 종류별 세부 상태를 함께 기록한다.
- 하나라도 양수이면 field 전체는 `parsed`, 양수는 없고 0 또는 `-`가 하나라도 있으면 `explicit_zero`, 모든 종류의 원천이 없으면 `source_not_found`이다.
- 종류별 원천 누락은 field 전체가 `parsed`여도 별도의 strong warning으로 남는다.
- `증자 전 발행주식총수`의 보통주식이 0 또는 `-`이면 다른 종류가 양수여도 strong warning을 만든다.
- 신주 종류가 둘 이상 양수이면 medium warning을 만든다.
- 신주 수량 전체 또는 증자 전 수량 전체가 명시적 0이면 weak warning을 만든다.
- 발행대상자 합계와 신주 합계가 다르면 weak warning을 만든다.
- 발행목적 합계와 `신주 수량 × 같은 종류의 양수 발행가액` 합계 차이가 9원 이하면 허용하고, 10원 이상이면 weak warning을 만든다.
- 관계가 맞지 않아도 추출값은 수정하지 않는다.
- 상세 객체 내부에는 별도의 상태나 warning을 만들지 않는다.

### 결과 구조와 warning code
1. **유무상증자 고유 필드**
- 유형과 관계없이 최상위에 `증자유형`, `신주의 종류와 수`, `증자 전 발행주식총수`, `발행목적`, `발행가액`, `증자방식`, `납입일`, `신주권교부예정일`, `상장예정일`, `발행대상자`, `유상증자`, `무상증자`를 만든다.
- `신주권교부예정일`과 `상장예정일`은 무상증자도 최상위에서 추출한다. 원천이 없으면 다른 일정으로 보완하지 않고 누락 처리한다.
- 유형에 맞지 않는 상세 객체는 `null`이다. 유형에 맞는 상세 객체의 구성과 누락 처리는 앞의 `유상·무상 상세 객체의 경계` 절이 정한다.
- 식별자, 원문 table, 외부 metadata, 저장 단계 필드는 문서 경계에 연결한 공통 문서가 정한다.
2. **workflow warning code**
- 아래 code는 parser record 자체가 아니라 공통 workflow가 `warnings[]`를 만들 때 사용한다.

| 상황 | `warning_code` |
|---|---|
| 유형 판정 실패 | `rights_issue_type_missing` |
| 필드 원천 누락 | `source_not_found:<필드명>` |
| title 누락, 합계 불일치, 복수 주식 종류, 0 검증 | `parse_warning` |

### 명시적으로 사용하지 않는 대체 경로
- 유형 판정에 본문 제목, section 제목 또는 다른 metadata field를 사용하지 않는다.
- 선택 조건을 만족하지 않는 table에서 누락 field를 찾지 않는다.
- 한 주식 종류의 값을 다른 종류에 복사하지 않는다.
- 무상증자에 적용되지 않는 유상 조건 field를 본문 값이나 기본 문자열로 채우지 않는다.
- 유무상증자 section 경계가 없을 때 다른 문구나 field 순서로 무상 section을 추측하지 않는다.
- 발행대상자 수량을 다른 column의 숫자나 배정 비율로 보완하지 않는다.
- 합계 검증 실패 시 수량·금액을 서로 맞도록 보정하지 않는다.
