# 유무상증자 파서 로직 규칙

작성일: 2026-07-06
최종 업데이트: 2026-07-10

이 파서(HTML에서 필요한 값을 읽는 프로그램)는 KIND 유무상증자 공시의 표에서 새로 발행할 주식 수, 돈을 쓸 목적,
주요 일정, 주식을 받을 사람을 읽어 하나의 결과로 정리한다.
이 문서에서 `table`은 표, `row`는 표의 가로줄, `cell`은 표의 한 칸을 뜻한다.
`record`는 파싱 결과 전체, `field`는 그 결과에 저장하는 각 항목을 뜻한다.
`title`은 외부에서 전달받은 공시 제목, `section`은 유상증자와 무상증자를 나눈 구역이다.
`logical_rows`는 빈 칸과 연속 중복을 줄여 검색하기 쉽게 만든 row이고,
`positional_rows`는 실제 column(세로줄) 위치를 유지한 row이다.
`raw_tables`는 원문의 모든 table을 뜻한다.
`metadata`는 HTML 본문 밖에서 가져오는 정보, `workflow`는 여러 파싱 결과를 모아 저장하는 처리 과정이다.
`null`은 저장할 값이 없다는 뜻이다.

HTML parsing(표에서 필요한 값을 읽는 동작)은
[HTML 파서 공통 로직 규칙](./common/common-html-parser-logic-rules.md)을 따르고,
공통 table, base record(기본 결과), 저장 payload(저장 결과 묶음)의 필드 구조는
[HTML 파서 공통 데이터 구조](./common/common-html-parser-data-structure.md)를 따른다.
공통 상태, 경고, 실행 오류 처리는
[HTML 파서 공통 예외 처리 규칙](./common/common-html-parser-exception-handling.md)을 따른다.
외부 metadata의 위치와 필드별 Only SoT는
[외부 메타데이터 병합 규칙](./external-metadata.md)을 따른다.

### 처리 흐름
1. **공통 구조 생성**
- `build_base_record()`로 파일명 전체에서 만든 `acpt_no`와 모든 `raw_tables`를 만든다.
  - 의도 : 개별 값을 찾기 전에도 파일 식별자와 원문의 모든 표를 그대로 확인할 수 있게 한다.
2. **title과 유형 고정**
- 호출한 쪽에서 전달한 `title`의 앞뒤 공백을 제거해 record에 저장한다.
- 저장한 `title`만으로 증자 유형을 판정한다.
  - 의도 : 제목의 출처와 유형 판정 기준을 하나로 고정한다.
3. **추출 대상 table 선택**
- 증자 field 또는 section 조건을 만족하는 table만 선택한다.
- 선택한 table의 `logical_rows`를 HTML 순서대로 하나의 row 목록으로 합친다.
  - 의도 : 모든 원문 표는 보존하되, 값 검색은 증자와 관련된 표로만 좁혀 잘못된 값을 읽는 일을 줄인다.
4. **최상위 필드 추출**
- 최상위 필드를 추출하면서 필드 상태와 원천 누락 경고를 만든다.
  - 의도 : 실제 값과 함께 그 값을 제대로 찾았는지도 확인할 수 있게 한다.
5. **관계 검증**
- 신주 수량, 발행가액, 발행목적, 발행대상자의 합계·관계를 검증해 수준별 경고를 만든다.
  - 의도 : 읽은 값을 임의로 고치지 않고, 서로 맞지 않는 값만 확인 대상으로 표시한다.
6. **상세 객체 생성**
- 유형과 section row에 따라 `유상증자`, `무상증자` 상세 객체를 만든다.
  - 의도 : 한 공시에 유상증자와 무상증자가 함께 있어도 두 내용을 나누어 볼 수 있게 한다.
7. **직접 반환**
- 증자 parser는 공통 `acpt_no`, `mode`, `title`, `상장구분`, `raw_tables`와 증자 업무 필드·상태·경고를 반환한다.
- 증자 parser는 `source_file`, `raw_rows`, `correction_families`, `rcept_no`를 반환하지 않는다.
- 저장 workflow는 `raw_tables`를 제거한 뒤 외부 metadata와 family 참조를 연결한다.
  - 의도 : 직접 parser 반환 구조와 저장 workflow가 담당하는 필드를 확정한다.

### 증자 유형 판정
1. **판정 순서**
- 전달받은 `title`에서 일반 공백(` `)을 제거한 뒤 `유무상증자` → `무상증자` → `유상증자` 순서로 확인한다.
- 각각 `mixed` → `bonus` → `paid`로 판정하고 어느 문구도 없으면 `unknown`으로 판정한다.
  - 의도 : `유무상증자`가 더 짧은 `무상증자` 또는 `유상증자` 문구에 먼저 걸리지 않게 한다.
2. **유형별 출력**

| 내부 유형 | 출력 `증자유형` | `유상증자` 상세 | `무상증자` 상세 |
|---|---|---|---|
| `paid` | `유상증자` | 객체 | `null` |
| `bonus` | `무상증자` | `null` | 객체 |
| `mixed` | `유무상증자` | 객체 | 객체 |
| `unknown` | `unknown` | `null` | `null` |

- `unknown`이어도 최상위 필드 추출과 상태·경고 생성은 계속한다.
- `증자유형` 자체에는 `field_parse_status`를 만들지 않고 유형 판정 실패 warning만 만든다.
  - 의도 : 유형을 확인하지 못한 사실과 본문에서 개별 값을 찾을 수 있는 가능성을 따로 기록한다.
3. **title 누락**
- 전달받은 `title`이 비어 있으면 `주입 제목이 없습니다.`와 유형 판정 실패 warning을 각각 strong 수준으로 기록한다.
- `title`은 있지만 세 증자 문구가 모두 없으면 유형 판정 실패 warning만 기록한다.
- parsing 후 외부 metadata나 본문 text로 `title`을 다시 채우지 않는다.
  - 의도 : title 부재와 유형 판정 실패를 별도 원인으로 확인할 수 있게 한다.

### 추출 대상 table
1. **table 선택 조건**
- 아래 조건 중 하나를 만족하는 table만 `extraction_tables`에 포함한다.

  - cell 하나로 된 row에서 일반 공백을 제거한 값이 `Ⅰ.유상증자`, `I.유상증자`, `1.유상증자`, `Ⅱ.무상증자`, `II.무상증자`, `2.무상증자` 중 하나와 정확히 일치함
  - `logical_rows`의 첫 row에 `제3자배정 대상자`와 `배정주식수`가 모두 존재
  - table 안의 cell이 두 개 이상인 row 중, 첫 cell에서 핵심 field 종류가 하나 이상 식별됨
  - table 전체의 cell이 두 개 이상인 row들에서, 첫 cell로 식별한 서로 다른 field 종류가 두 개 이상 존재함

- 핵심 field 종류는 `신주의 종류와 수`, `증자전 발행주식총수`, `자금조달의 목적`, `증자방식`, `신주 발행가액`, `신주배정기준일`, `1주당 신주배정`이다.
- 그 밖에 field 종류 판정에 쓰는 label은 `납입일`, `신주권교부예정일`, `신주의 상장 예정일`이다.
- field 종류 판정은 cell이 두 개 이상인 row의 첫 cell에서만 수행한다.
  - 의도 : 증자 본문과 대상자 table은 포함하되 label이 다른 column에 우연히 나타난 일반 table은 제외한다.
2. **row 사용 범위**
- 선택된 모든 table의 `logical_rows`를 HTML 순서대로 합치고 최상위 field 검색은 이 전체 목록에서 수행한다.
- 같은 field 후보가 여러 개이면 각 추출 함수가 정한 첫 일치 row 또는 첫 유효 값을 사용한다.
  - 의도 : table 선택 경계는 유지하면서 여러 증자 본문 table에 나뉜 필드를 한 번의 파싱 범위에서 검색한다.
3. **정정 이력 table**
- 정정 이력이라는 이유만으로 table을 따로 걸러 내지 않는다.
- 정정 이력 table도 위의 선택 조건을 만족할 때만 추출 대상이 된다. 예를 들어 `납입일`만 우연히 들어 있는 정정 이력 table은 선택하지 않는다.
  - 의도 : 공통 규칙대로 별도의 정정공시 필터를 만들지 않고, 증자 field 선택 조건 하나만 사용한다.

### 최상위 출력 필드

`최상위`는 `유상증자`나 `무상증자` 상세 객체 안쪽이 아니라 record 바로 아래를 뜻한다.

1. **항상 생성하는 구조**
- 아래 증자 필드는 증자 유형과 관계없이 최상위 record에 같은 항목 이름(key)으로 생성한다.

| 필드 | 값 형식 | 기본값 |
|---|---|---|
| `mode` | `rights_issuance` | 고정값 |
| `title` | 주입된 제목 | 빈 문자열 |
| `증자유형` | `유상증자`, `무상증자`, `유무상증자`, `unknown` | `unknown` |
| `신주의 종류와 수` | 주식 종류별 수량 목록 | 원천 누락 종류는 `null` |
| `증자 전 발행주식총수` | 주식 종류별 수량 목록 | 원천 누락 종류는 `null` |
| `발행목적` | 목적별 금액 목록 또는 `-` | 원천 누락은 `null` |
| `발행가액` | 주식 종류별 금액 목록 또는 `-` | 원천 누락 종류는 `null` |
| `증자방식` | 원문 text 또는 `-` | `null` |
| `납입일` | 원문 text 또는 `-` | `null` |
| `신주권교부예정일` | 원문 text | `null` |
| `상장예정일` | 원문 text | `null` |
| `발행대상자` | 대상자별 수량 목록 또는 `-` | 필수 원천 누락은 `null` |
| `유상증자` | 유형별 상세 객체 | `null` |
| `무상증자` | 유형별 상세 객체 | `null` |

  - 의도 : 값이 없더라도 항목 이름과 자료 모양을 일정하게 유지해 뒤 단계에서 같은 방식으로 읽을 수 있게 한다.

### 최상위 필드 추출 규칙
1. **주식 종류 표준화**
- 주식 종류는 `보통주식`, `기타주식` 순서로 항상 두 항목을 반환한다.
- `보통주식`, `보통주`는 `보통주식`으로 기록한다.
- `기타주식`, `기타주`, `우선주식`, `우선주`, `종류주식`, `종류주`는 `기타주식`으로 기록한다.
  - 의도 : KIND 양식의 주식 종류 표현을 두 출력 key로 고정한다.
2. **주식 수량과 발행가액**
- `신주의 종류와 수`, `증자전 발행주식총수`, `신주 발행가액`을 포함하는 row에서 주식 종류 label 바로 오른쪽 cell의 첫 번째 정수를 읽는다.
- 같은 주식 종류에서 0 또는 `-`를 먼저 읽어도 뒤에서 양수를 찾으면 양수를 사용한다.
- 각 주식 종류의 추출 결과에는 공통 상태·저장값·경고 규칙을 적용한다.
- `field_parse_status_detail`은 `신주의 종류와 수`, `증자 전 발행주식총수`, `발행가액`에 주식 종류별로 생성한다.
  - 의도 : 출력 목록의 형태는 유지하면서 원천 누락과 명시적인 0을 값과 상태에서 모두 구분한다.
3. **발행목적**
- `bonus`이면 `발행목적`에 공통 `not_applicable` 규칙을 적용한다.
- 그 밖의 유형은 시설자금 → 영업양수자금 → 운영자금 → 채무상환자금 → 타법인 증권 취득자금 → 기타자금 순서로 확인한다.
- 각 목적은 `자금조달의 목적`과 목적 label을 함께 포함하는 첫 row의 마지막 cell에서 금액을 읽는다.
- `타법인유가증권취득자금`은 `타법인 증권 취득자금`으로 기록한다.
- 금액이 0이면 목록에는 넣지 않지만 원천은 존재한 것으로 기록한다.
  - 의도 : 출력 목적 순서와 명칭을 고정하고 0원 목적은 결과 목록에서 제외한다.
4. **유상 조건 필드**
- `bonus`이면 `발행가액`, `증자방식`, `납입일`, `발행대상자`에 공통 `not_applicable` 규칙을 적용한다.
- 그 밖의 유형에서 `증자방식`과 `납입일`은 해당 label을 포함하는 첫 row의 마지막 값을 사용한다.
- `bonus`의 `증자방식`을 `무상증자` 같은 값으로 보완하지 않는다.
  - 의도 : 무상증자에 적용되지 않는 유상 조건과 원천 누락을 구분한다.
5. **공통 일정 필드**
- `신주권교부예정일`은 해당 label을 포함하는 첫 row의 마지막 값을 사용한다.
- `상장예정일`은 공백 제거 비교로 `신주의 상장 예정일` 또는 `신주의 상장예정일`을 포함하는 첫 row의 마지막 값을 사용한다.
- 이 두 필드는 `bonus`에서도 최상위 값을 추출하고 원천이 없으면 경고를 만든다.
  - 의도 : 유상·무상 유형 모두에 필요한 일정을 같은 최상위 key로 제공한다.

### 유형별 상세 객체
1. **유상증자 상세**
- `paid` 또는 `mixed`에서 생성한다.
- `신주의 종류와 수`, `증자 전 발행주식총수`, `발행목적`, `발행가액`, `증자방식`, `납입일`, `신주권교부예정일`, `상장예정일`, `발행대상자`는 최상위에서 추출한 값을 그대로 재사용한다.
- `신주배정기준일`, `1주당 신주배정주식수`만 유상 section row에서 별도로 추출한다.
  - 의도 : 최상위 값과 유상증자 상세의 공통 필드가 서로 다르게 저장되지 않게 한다.
2. **무상증자 상세**
- `bonus` 또는 `mixed`에서 생성한다.
- 무상 section row에서 `신주의 종류와 수`, `증자 전 발행주식총수`, `신주배정기준일`, `1주당 신주배정주식수`, `신주권교부예정일`, `상장예정일`을 다시 추출한다.
- 수량·날짜·주식 종류별 배정수 원천을 찾지 못하면 `null`을 사용한다.
  - 의도 : 무상 section의 조건을 최상위 유상 조건과 별도로 보존한다.
3. **mixed 구역 분리**
- 선택된 전체 row에서 `무상증자`를 포함하고 `유무상증자`를 포함하지 않는 첫 row를 경계로 사용한다.
- 경계 이전은 유상 section, 경계 이후는 무상 section이며 경계 row 자체는 두 section에서 제외한다.
- 경계 row는 cell 하나로 된 정확한 구역 제목일 필요는 없다.
- 경계 row가 없으면 유상 section은 전체 선택 row, 무상 section은 빈 목록을 사용한다.
- 최상위 field는 section으로 나누기 전에 전체 선택 row에서 추출하므로 항상 유상 section 값이라는 보장은 없다.
  - 의도 : 유상·무상 구역 분리는 상세 객체에만 적용된다는 경계를 분명히 한다.
4. **1주당 신주배정주식수**
- section row에서 보통주식·기타주식 label 바로 오른쪽의 text를 각각 읽는다.
- 두 주식 종류의 값을 모두 찾지 못하면 `1주당 신주배정`을 포함하는 첫 row의 마지막 값이 빈 값이나 `-`가 아닐 때 `보통주식` 값으로 사용한다.
  - 의도 : 주식 종류별 column이 없는 예전 양식도 현재 코드가 읽는 방식 그대로 설명한다.
5. **상세 상태**
- 상세 객체 내부 필드에는 별도의 `field_parse_status`, detail 상태, warning을 만들지 않는다.
  - 의도 : 현재 상태 계약이 최상위 field에만 적용된다는 경계를 명확히 한다.

### 발행대상자 table
1. **후보 인정**
- `bonus`의 최상위 `발행대상자`에는 공통 `not_applicable` 규칙을 적용한다.
- 그 밖의 유형은 `logical_rows`의 첫 row에 `제3자배정 대상자`와 `배정주식수`가 모두 있는 table을 후보로 본다.
- 실제 header(세로줄 제목)의 위치와 data는 `positional_rows`에서 읽는다.
- `제3자배정 대상자` column과 `배정주식수` column을 모두 찾고 두 위치가 다를 때만 유효한 후보로 인정한다.
  - 의도 : 두 header가 한 cell에 합쳐진 설명 table을 거부하고 실제 선언 column만 사용한다.
2. **대상자와 수량 추출**
- 대상자명은 선언된 `제3자배정 대상자` column에서만 읽고 빈 값과 `-`는 제외한다.
- 수량은 선언된 `배정주식수` column에서만 읽고 다른 column이나 row의 마지막 숫자를 대신 사용하지 않는다.
- 수량 cell의 `%` 숫자를 먼저 제거하고 남은 모든 정수를 합산한다.
- 수량을 parsing할 수 없는 row는 결과에서 제외한다.
  - 의도 : 배정 비율 주석을 주식수에 더하지 않고 한 cell에 줄바꿈된 여러 수량은 합산한다.
3. **미공개 대상자**
- header 아래의 data row가 하나 이상이고 모든 row의 대상자명이 정확히 `-`이며, 모든 배정주식수 cell에서 `%` 숫자를 제거한 뒤 정수를 하나도 읽을 수 없으면 즉시 `[["-", 0]]`과 `explicit_zero`를 반환한다.
- 대상자명 column에 `-`이 아닌 값이 있거나 배정주식수에서 정수를 하나라도 parsing할 수 있으면 이 규칙을 적용하지 않는다.
  - 의도 : 대상자가 공개되지 않은 표와 보존할 수 없는 일반 빈 결과를 구분한다.
4. **후보 선택 순서**
- 각 후보를 HTML 순서대로 확인한다.
- 미공개 대상자 조건을 만나면 즉시 반환한다.
- 보존한 대상자 수량 합계가 `신주의 종류와 수` 합계와 일치하면 즉시 해당 후보를 반환한다.
- 합계가 일치하는 후보가 없으면 값이 있는 첫 불일치 후보를 사용하고 이후 관계 검증에서 weak 경고를 만든다.
- 값이 있는 후보도 없으면 `null`, `source_not_found`, strong 경고를 기록한다.
  - 의도 : 정확히 일치하는 표를 가장 먼저 쓰고, 사용할 값을 찾지 못한 결과를 빈 목록이나 0으로 숨기지 않는다.
5. **하단 총계 row 제거**
- 대상자 목록이 두 개 이상이고 신주 합계가 양수일 때만 검사한다.
- 마지막 대상자명을 공백으로 나눈 단어 중 `계`, `합계`, `소계`, `총계`와 정확히 같은 단어가 하나라도 있어야 한다.
- 전체 대상자 합계가 신주 합계의 두 배이고 마지막 row 수량이 신주 합계와 같으면 마지막 row를 중복 총계로 제거한다.
  - 의도 : 특정한 중복 합계 형태만 제거하고 이름에 비슷한 글자가 있는 실제 대상자는 보존한다.
6. **사용할 대상자 table이 없음**
- 끝까지 반환할 후보가 없고 `증자방식`에 `제3자배정`이 있으며 전달받은 `title`에 `종속회사`가 없으면 `null`, `source_not_found`, strong 경고를 기록한다.
- 이 조건이 아니면 빈 목록을 반환하고 `발행대상자` 상태와 원천 누락 경고를 만들지 않는다.
  - 의도 : 제3자배정 대상자 table이 필수인 경우에만 누락으로 판단한다.

### 상태와 경고

상태의 뜻, 저장값, 경고, 검증 제외 규칙은
[HTML 파서 공통 예외 처리 규칙](./common/common-html-parser-exception-handling.md)을 따른다.
이 문서에서는 증자 parser가 각 상태를 적용할 필드별 조건과 추가 진단 경고만 정한다.

1. **수량형 상태 적용 조건**
- `신주의 종류와 수`, `증자 전 발행주식총수`, `발행가액`은 하나라도 양수이면 `parsed`로 기록한다.
- 양수는 없고 하나라도 원문 0 또는 `-`를 읽으면 `explicit_zero`로 기록한다.
- 모든 주식 종류의 원천을 찾지 못하면 `source_not_found`로 기록한다.
  - 의도 : 일부 종류의 명시적 0보다 실제 양수 추출을 우선한다.
2. **detail 상태 적용 필드**
- `field_parse_status_detail`은 `신주의 종류와 수`, `증자 전 발행주식총수`, `발행가액`에 `보통주식`·`기타주식`별 `parsed`, `explicit_zero`, `source_not_found`를 기록한다.
- 세부 상태의 저장값과 경고는 공통 예외 처리 규칙을 그대로 적용한다.
  - 의도 : 전체 field가 `parsed`여도 특정 주식 종류가 0이거나 누락된 사실을 보존한다.
3. **strong warning**
- 전달받은 title 누락과 유형 판정 실패를 strong 수준으로 기록한다.
- `source_not_found` 경고는 공통 예외 처리 규칙을 그대로 적용한다.
- `발행대상자` 출처 누락은 앞에서 설명한 제3자배정 조건을 만족할 때만 기록한다.
- `증자 전 발행주식총수`의 `보통주식`이 원문에서 0 또는 `-`이면 다른 주식 종류가 양수여도 strong 경고를 만든다.
  - 의도 : 유형과 핵심 보통주 수량을 확인할 수 없는 경우를 가장 높은 수준으로 표시한다.
4. **medium warning**
- `신주의 종류와 수`에서 0이 아닌 주식 종류가 둘 이상이면 해당 종류를 표시하는 medium 경고를 만든다.
  - 의도 : 복수 주식 종류 발행을 오류로 보정하지 않고 확인 대상으로 표시한다.
5. **weak warning**
- 공통 `not_applicable` 검증 제외 규칙을 적용한 뒤, `발행대상자`가 비어 있지 않고 합계가 신주 합계와 다르면 weak 경고를 만든다.
- `발행목적` 목록이 있고 양수 발행가액과 같은 주식 종류의 신주 수량을 하나 이상 곱할 수 있을 때 계산값과 목적 합계를 비교한다.
- 발행금액 관계의 차이가 9원 이하면 경고하지 않고 10원 이상이면 weak 경고를 만든다.
- 신주 수량 전체 또는 증자 전 수량 전체가 원문에서 명시적 0으로 판정되면 weak 경고를 만든다.
  - 의도 : 값을 변경하지 않고 합계·관계·명시적 0을 진단 정보로 남긴다.
6. **workflow warning code**
- 아래 code는 증자 parser record가 아니라 공통 workflow의 `warnings[]`를 만들 때 warning 문자열에서 변환한다.

| 상황 | `warning_code` |
|---|---|
| 유형 판정 실패 | `rights_issue_type_missing` |
| 필드 원천 누락 | `source_not_found:<필드명>` |
| title 누락, 합계 불일치, 복수 종류, 0 검증 | `parse_warning` |

  - 의도 : 사람이 읽는 경고 문장과 프로그램이 분류에 쓰는 짧은 코드를 함께 제공한다.
