# 사채발행 파서 로직 규칙
- 이 문서는 작성 및 검토가 완료되었으므로 사용자의 명시적 허락이 있지 않는 한 **절대로** 수정하지 않는다.
- 이 문서는 `사채발행파싱` 모드에서만 사용하는 특수한 로직에 대해 설명하며, `대체 경로`를 중점적으로 설명한다. 
- 여기서 `대체 경로`란 아래 동작을 **모두** 포함한다.
  1. 특정 파서가 **단일 출처**에서 값을 찾지 못했을 때 다른 table, label, parser, tag 등을 사용하는 모든 로직. 특히 다른 데이터 소스를 사용하는 로직을 엄격히 금지한다.
  2. 특정 파서가 원하는 값을 찾지 못했을 때 상위·하위·인접 요소나 다른 경로를 탐색하는 로직.
  3. 특정 필드가 없거나 비어 있을 때 다른 필드, 메타데이터, 원문 텍스트, 기본값 등으로 **대체하는** 로직.
  4. 파싱 오류, 예외, 빈 결과, 형식 불일치, 유효성 검증 실패 등 비정상 동작에서 별도 분기로 처리하는 로직.
  5. 예외적인 케이스를 처리하기 위해 적용되는 조건문, 보정 로직 또는 임시 처리 로직.
  6. 제목, 본문, 표, 첨부 문서, 인코딩, 줄바꿈, 공백, 특수문자 등 공시원문 변환 과정에서 정상 경로를 대신하는 모든 보조·복구·우회 로직.
  7. 명칭이나 주석상 fallback으로 표시되어 있지 않더라도, 실질적으로 대체 경로 역할을 하는 로직.

### 문서 경계
- 외부 metadata의 위치와 필드별 Only SoT는 [외부 메타데이터 병합 규칙](./external-metadata.md)을 따른다.
- 이 문서는 기타 문서에서 언급된 내용을 반복하지 않고 사채발행 parser가 **어떤 원천을 먼저 선택하고, 실패하면 무엇을 대신 시도하는지**만 정한다.

### 파싱 범위
1. **메인 table**
- 한 table 안에서 `사채의 종류`, `사채의 권면`, `자금조달의 목적`을 모두 찾을 수 있는 첫 번째 table만 사용한다.
- 서로 다른 table의 row를 합쳐서 세 조건을 충족시키지 않는다.
- 조건을 만족하는 table이 없으면 다른 table을 추측해서 사용하지 않고 빈 row 목록으로 각 필드 추출을 계속한다. 이때 메인 table 누락과 각 필드의 원천 누락을 각각 strong warning으로 남긴다.
  - 의도 : 양식이 예상과 다를 때 그럴듯한 다른 표의 값을 사채 조건으로 오인하지 않는다.
2. **투자자 table**
- 첫 row에 `발행 대상자명`과 `발행권면`이 모두 있는 table만 후보로 삼는다.
- 두 header가 서로 다른 column에서 확인되는 후보만 유효하다.
- 후보 확인에는 검색하기 쉽게 정리한 `logical_rows`를 사용하고, 실제 header 위치와 값은 원래 column 위치를 유지한 `positional_rows`에서 읽는다.
- 유효한 후보가 여러 개이면 첫 번째 table만 사용하며, 뒤 table을 대신 사용하거나 여러 table의 투자자를 합치지 않는다.
  - 의도 : 투자자 원천을 하나로 고정하고 설명용 table이나 중복 table이 섞이지 않게 한다.

### 대체 경로와 선택 순서

아래 순서는 코드가 실제로 시도하는 순서이다. 앞 단계에서 값을 찾으면 뒤 단계는 실행하지 않는다.

| 필드 | 먼저 사용하는 경로 | 찾지 못했을 때의 대체 경로 | 모두 실패하면 |
|---|---|---|---|
| `종류` | 주입 `title`의 `신주인수권부사채` | `교환사채` → `전환사채` 순서 | `null`; 본문으로 보완하지 않음 |
| `발행금액` | `사채의 권면` row 중 첫 `원화기준` row | `원화기준` row가 없으면 첫 번째 `사채의 권면` row | `null` |
| `만기일` | `사채만기일`을 포함한 첫 row | `사채만기`를 포함한 첫 row | `null` |
| `기업명(행사대상)` | 정해진 행사대상 label과 같은 row의 바로 오른쪽 cell 또는 같은 cell 안의 값 | 모든 label의 기본 경로가 실패한 뒤, 일부 label에서 `label` → `종류` → `값`의 세 cell 구조 | `null` |
| `행사가액` | `전환가액` | `교환가액` → `행사가액` → `전환가격` → `교환가격` → `행사가격` | `null` |
| `행사시작일`, `행사종료일` | `전환청구기간` | `교환청구기간` → `권리행사기간` → `행사기간` | `null` |

1. **title과 사채 종류**
- `title`은 호출자가 전달한 값을 문자열로 바꾸고 앞뒤 공백만 제거해 사용한다.
- `title`이 비어 있으면 빈 문자열을 저장하고 `주입 제목이 없습니다.` warning을 만든다.
- 한 제목에 여러 종류 문구가 있으면 위 표의 첫 순서대로 하나만 선택한다.
- HTML 본문의 제목이나 `사채의 종류` row는 `title` 또는 `종류`의 대체 원천이 아니다.
  - 의도 : 종류 판정의 출처를 주입 제목 하나로 고정한다.
2. **발행금액**
- 선택한 권면 row의 첫 cell은 label 영역으로 보고 제외한다. 나머지 cell을 오른쪽부터 확인해 처음 숫자로 바꿀 수 있는 값을 사용한다.
- 확인 중 cell 전체가 `-`이면 명시적인 0으로 처리한다.
- 선택한 row에서 값을 찾지 못해도 다른 권면 row나 다른 숫자 field로 이동하지 않는다.
  - 의도 : 해외발행 공시는 원화 환산액을 우선하되, 한 번 선택한 원천 밖의 숫자로 값을 만들지 않는다.
3. **기업명 또는 행사대상 주식**
- 다음 label을 왼쪽부터 적힌 순서대로 확인한다.

  `전환대상` → `교환대상` → `인수권행사대상` → `전환에 따라` → `교환에 따라` → `인수권행사에 따라` → `전환으로 발행할` → `교환으로 발행할` → `인수권행사로 발행할`

- 각 label의 기본 경로는 다음 두 가지이다.
  - label cell 바로 오른쪽 값을 읽는다.
  - 같은 cell 안에서 label 뒤의 `종류:` 또는 `유가증권:` 값을 읽는다.
- `대상`이 들어간 label은 cell 전체가 label과 같거나 같은 cell에 `종류`·`유가증권`이 있어야 한다. `대상`이 없는 label은 같은 cell에 `종류`가 있어야 한다.
- 같은 cell 안의 값을 읽을 때 label과 `종류`·`유가증권` 사이는 40자 이내여야 하며 `:` 또는 `：`가 필요하다.
- 값 뒤에서 `(1)`, `1)`, `1. `, `가.`, `①`처럼 인식 가능한 다음 번호 항목이 시작되면 그 앞까지만 사용한다. 정리한 값이 120자를 넘으면 실패로 본다.
- 모든 label의 기본 경로가 실패하면, 이름에 `대상`이 없는 label에 한해 다음 cell이 정확히 `종류`일 때 그 다음 cell을 사용한다.
- 추출한 값에서 법인 형태나 주식 종류 표현을 제거하지 않는다.
  - 의도 : 알려진 과거 양식만 제한적으로 지원하고 긴 설명문이나 비슷한 label을 행사대상으로 오인하지 않는다.
4. **행사가액**
- 후보 label cell에 `결정방법`, `조정`, `한도`가 있으면 설명 row로 보고 건너뛴다.
- label 오른쪽 cell들을 오른쪽부터 확인한다. 숫자·공백·쉼표·소수점과 선택적인 원 단위만 있는 cell을 사용한다.
- 설명문 속 숫자, 비율, 예시는 가격으로 대신 사용하지 않는다.
  - 의도 : 정상 가격 cell이 없을 때 설명문 숫자로 잘못 복구하지 않는다.
5. **납입일과 행사기간**
- `납입일`은 공통 번호 label 정규화가 허용하는 `숫자.` 또는 `숫자-숫자.` 접두사만 제거한 뒤 정확히 `납입일`인 첫 row의 마지막 값을 사용한다.
- 행사기간은 후보 기간 label과 `시작일` 또는 `종료일`을 함께 포함한 첫 row의 마지막 값을 사용한다.
- 시작일과 종료일은 서로의 값이나 다른 일정 field로 보완하지 않는다.
  - 의도 : 번호와 사채 종류에 따른 label 차이만 허용하고 일정값의 출처는 섞지 않는다.

### 그 밖의 특수 처리
1. **회차와 사채발행방법**
- `회차`는 `사채의 종류`를 포함한 첫 row에서 정확히 `회차`인 cell 바로 오른쪽 값만 읽는다.
- `사채발행방법`은 해당 문구를 포함한 첫 row의 마지막 값만 읽는다.
- 같은 row의 다른 위치나 비슷한 이름의 field를 대체 원천으로 사용하지 않는다.
2. **발행목적**
- `자금조달의 목적` label 바로 다음 cell을 목적명으로 사용하고, 그 오른쪽 cell들을 오른쪽부터 확인해 첫 숫자를 금액으로 사용한다.
- 목적명에서는 원 단위와 제한된 구분 기호만 제거한다. 다른 이름으로 표준화하지 않는다.
- 금액이 0 또는 `-`이면 원천은 존재한 것으로 보되 결과 목록에서는 제외한다.
- 목적명은 있지만 금액이 없으면 그 row를 결과에 넣지 않는다. 모든 목적 row에서 금액을 찾지 못하면 필드 전체를 원천 누락으로 처리한다.
3. **투자자**
- 대상자명과 금액은 header가 정한 각 column에서만 읽는다.
- 대상자명이 빈 값, `-`, `합계`, `총계`, `계`이면 해당 row를 제외한다.
- 금액 cell의 `-`는 0으로 보존하지만, 빈 값이나 숫자로 바꿀 수 없는 글은 해당 row에서 사용할 금액이 없는 것으로 본다.
- 첫 유효 투자자 table에서 보존할 row가 하나도 없으면 `null`로 끝낸다. 뒤 후보 table은 대체 원천으로 사용하지 않는다.
  - 의도 : 다른 column의 숫자나 뒤 table로 빈 결과를 감추지 않는다.

### 상태와 검증
- 사채 parser는 `회차`, `종류`, `기업명(행사대상)`, `발행금액`, `발행목적`, `행사가액`, `납입일`, `만기일`, `사채발행방법`, `행사시작일`, `행사종료일`, `투자자`에 상태를 기록한다.
- `발행금액`은 0 또는 `-`를 읽으면 `explicit_zero`이다.
- `발행목적`은 보존할 양수 항목이 있으면 `parsed`, 금액 원천이 모두 0이면 `explicit_zero`, 금액 원천을 하나도 찾지 못하면 `source_not_found`이다.
- 문자열 field의 원문 `-`는 값이 존재한 것이므로 `parsed`이다.
- 발행목적 합계 또는 투자자 금액 합계가 발행금액과 다르면 값을 보정하지 않고 weak warning만 만든다. 허용 오차는 없다.
- 사채 parser는 medium warning을 직접 만들지 않는다.

### 결과 구조와 warning code
1. **사채발행 고유 필드**
- 모든 사채 종류는 `회차`, `종류`, `기업명(행사대상)`, `발행금액`, `발행목적`, `행사가액`, `납입일`, `만기일`, `사채발행방법`, `행사시작일`, `행사종료일`, `투자자`를 같은 최상위 구조로 반환한다.
- `종류`는 `BW`, `EB`, `CB` 중 하나이고, 목록형인 `발행목적`과 `투자자`는 각각 `[[이름, 금액], ...]` 형식이다.
- 원천을 찾지 못한 필드는 `null`이다. `발행목적`에서 금액 원천이 명시적 0뿐이면 빈 목록이다.
- 식별자, 원문 table, 외부 metadata, 저장 단계 필드는 문서 경계에 연결한 공통 문서가 정한다.
2. **workflow warning code**
- 아래 code는 parser record 자체가 아니라 공통 workflow가 `warnings[]`를 만들 때 사용한다.

| 상황 | `warning_code` |
|---|---|
| 메인 table 누락 | `bond_main_table_missing` |
| 필드 원천 누락 | `source_not_found:<필드명>` |
| 발행목적 합계 불일치 | `bond_funding_purpose_sum_mismatch` |
| 투자자 합계 불일치 | `bond_investor_sum_mismatch` |
| 주입 title 누락 등 나머지 warning | `parse_warning` |

### 명시적으로 사용하지 않는 대체 경로
- 메인 table이 없을 때 여러 table의 row를 합치지 않는다.
- 주입 title이 없거나 종류를 판정하지 못해도 본문 title이나 종류 row를 사용하지 않는다.
- 선택한 field row에서 값을 찾지 못해도 인접 row나 다른 field의 값을 사용하지 않는다.
- 투자자 table의 column이 잘못되었거나 결과가 비어도 다른 column의 숫자를 사용하거나 뒤 table과 합치지 않는다.
- 합계가 맞지 않아도 추출값을 발행금액에 맞춰 수정하지 않는다.
