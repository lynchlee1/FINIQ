# FINIQ 공통 흐름 익히기

이 안내는 FINIQ를 처음 쓰는 사람이 작업공간을 고르고 비동기 작업을 확인하는 순서를 설명한다. 화면에 보이는 결과와 파일에 저장한 결과를 구분하는 방법도 다룬다. 기능별 사양과 작업 안내는 중앙 [README.md](../../README.md)에서 찾는다.

## 1. 작업공간 고르기

화면에서 `작업공간 디렉토리`를 고른다. 별도 저장 경로를 켜지 않으면 공시분석은 이 폴더 아래에서 단계별 입력과 결과를 찾는다.

공시분석 결과는 01~07단계와 09단계 폴더로 나뉜다. 08단계는 07단계 결과를 읽어 보여 주므로 08단계 폴더가 없어도 정상이다. 정확한 폴더 이름은 [공시분석 공통 사양](../../disclosures/common/reference.md)에서 확인한다.

Ontology 주가 자료도 작업공간 아래 표준 경로에서 찾는다. 정확한 위치는 [Ontology 공통 사양](../../ontology/common/reference.md)에서 확인한다.

## 2. 비동기 작업 확인하기

중앙 문서 지도에서 사용할 기능 사양을 열어 입력을 확인한 뒤 작업 하나를 실행한다. 실행 중 다른 화면으로 옮겼다가 돌아와도 화면은 저장한 작업 ID로 같은 작업을 찾아 진행 상태를 이어서 보여 준다.

상태 조회가 `404`를 반환하면 화면은 저장한 작업 ID를 지운다. 결과 본문, 실패 이유, 완료 결과를 읽지 못하면 성공으로 처리하지 않는다. 서버가 실패 이유를 보내지 않으면 화면에 `Job failed`를 표시한다.

공시분석과 Ontology의 상태값은 각각 [공시분석 공통 사양](../../disclosures/common/reference.md)과 [Ontology 공통 사양](../../ontology/common/reference.md)에서 확인한다.

## 3. 화면 결과와 저장 결과 구분하기

진행 내역과 오류 예시는 화면 크기에 맞춰 일부만 보일 수 있다. 긴 파일 경로는 마지막 네 부분만 남기고 앞을 `.../`로 줄인다. 화면 표시를 줄여도 저장 결과와 전체 검사 대상은 바뀌지 않는다.

숫자 `0`은 빈 값이 아니다. 설정을 저장하지 못해도 현재 입력값은 화면에서 지우지 않는다. 화면에 값이 남아 있다는 사실만으로 저장에 성공했다고 판단하면 안 된다. 두 화면의 표시 기준은 각각 [공시분석 공통 사양](../../disclosures/common/reference.md)과 [Ontology 공통 사양](../../ontology/common/reference.md)에서 확인한다.

# 01단계 결과 다시 받기

기존 KIND 조건검색 결과가 무결성 검사를 통과하지 못했고 기존 결과를 지운 뒤 전체 기간을 다시 받아야 할 때 이 절차를 따른다.

1. 공시 자동화 화면 오른쪽 `알림`에서 어느 기간의 결과가 어떤 검사에서 어긋났는지 확인한다. 저장한 페이지 수와 현재 KIND 페이지 수가 다르면 두 값도 함께 보여 준다.
2. 기존 결과를 지우고 해당 기간을 처음부터 다시 받아도 되는지 판단한다.
3. 다시 받으려면 `전체 다시 받기`를 누른다. 기존 결과를 유지하려면 누르지 않는다.
4. 작업이 끝나면 01단계 상태가 `완료`로 바뀌었는지 확인한다. 실행 중 검색 조건이나 충돌 내역이 바뀌면 화면은 다시 확인을 요청한다.

`전체 다시 받기`를 누르지 않으면 기존 결과를 지우거나 다시 받지 않는다. 서버가 확인값을 검사하는 방법과 중단 조건은 [KIND 조건검색 결과 저장](reference.md)에서 확인한다.

# 기존 HTML을 확인하고 기준 해시 만들기

기존 외부 HTML이나 본문 HTML에 바이트 수와 SHA-256 기준값이 없어 작업이 멈췄을 때 이 절차를 따른다.

1. 멈춘 단계가 외부 HTML 저장인지 본문 HTML 저장인지 확인한다.
2. 현재 HTML이 믿을 수 있는 원본인지 직접 확인한다.
3. 외부 HTML이면 `현재 외부 HTML 신뢰`, 본문 HTML이면 `현재 내부 HTML 신뢰` 체크박스를 고른다.
4. `기준 해시 생성`을 누르고 작업이 끝날 때까지 기다린다.
5. 작업이 끝나 화면에 저장 범위가 다시 표시되면 `기준 없음`이 0건이고 `해시 확인`이 기존 HTML 건수와 같은지 확인한다.
6. 다운로드 `실행`을 눌러 나머지 작업을 잇는다. 현재 파일이 기준 해시와 다르면 해당 파일은 다시 받는다.

파일을 직접 확인하지 않았다면 기준 해시를 만들지 않는다. 파일 크기나 SHA-256이 기준값과 다르면 기존 파일을 재사용하지 않는다. 외부 HTML은 [외부 HTML 저장](../04-external-html-download/reference.md), 본문 HTML은 [본문 HTML 저장](../05-internal-html-download/reference.md)에서 세부 검사 기준을 확인한다.

# 처음 보는 목차 검토하기

06단계가 저장 규칙이 없는 목차를 찾아 `needs_review`로 멈췄을 때 이 절차를 따른다.

1. 공시 자동화 화면에 있는 `목차 조합 모아보기`에서 처음 보는 목차 조합을 확인한다.
2. 저장할 목차를 체크박스로 고른다. 조합 안에 있는 목차를 모두 고르거나 빼려면 `전체 선택`과 `전체 해제`를 사용한다.
3. 모든 조합에서 저장할 목차를 골랐는지 확인한다. 저장할 목차가 없는 조합도 `전체 해제`로 판단을 남겨야 한다.
4. `후속 실행`을 누른다. 화면은 선택 결과를 저장하고 멈춘 다음 단계부터 작업을 잇는다.

판단하지 않은 조합이 하나라도 있으면 후속 작업을 시작하지 않는다. `전체 해제`를 고른 조합은 HTML로 저장하지 않는다. 자동화는 이전 선택을 새 목차에 임의로 적용하지 않는다. 목차 선택 기준은 [목차 HTML 저장](reference.md), 자동화 재개 규칙은 [공시분석 공통 사양](../common/reference.md)에서 확인한다.

# parser 문제 조사하고 추출 규칙 고치기

## 1. 저장 결과 확인

사용자가 변환 오류를 제보하면 `<data_root>/07-converted/<mode>/parsed-<mode>.json`부터 확인한다.

- `records`: 다음 화면이 읽는 변환 결과
- `warnings`: parsing은 끝났지만 예상한 공시 양식과 다를 수 있는 파일과 이유
- `errors`: 변환에 실패한 파일과 Python 예외 유형·문장

실행 순서, 중간 저장과 취소 안내는 progress callback과 작업 상태로 전달하며 최종 JSON에는 저장하지 않는다. 변환에 성공한 record가 필터에서 빠져도 해당 warning은 최상위 `warnings`에 남긴다.

## 2. 실제 KIND 파일 확인

`bond_issuance`와 `rights_issuance`의 규칙은 `resources/KIND/bond_issuance`, `resources/KIND/rights_issuance`에 있는 실제 KIND 파일을 직접 확인해 결정한다.

## 3. 추출 규칙 변경

유형별 추출 규칙은 각 parser 진입점과 가까운 module에 둔다. 공통 HTML·표 처리는 `common` package를 사용한다.

test fixture와 합성 HTML은 실제 파일로 규칙을 확정한 뒤 회귀를 검증할 때만 사용한다.

저장 결과의 정확한 구조와 mode별 계약은 [공시원문 변환 사양](reference.md)에서 확인한다.
